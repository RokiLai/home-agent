## 2. 目标与适用边界

### 2.1 目标

为一个个人管理员提供固定公网入口，使其自有设备能够跨家庭宽带、移动网络和 NAT 主动连接 HomeAgent，并通过同一控制台完成设备查看、指令下发、状态上报和升级管理。

目标运行模型为：

- 一个管理员账户；
- 一个 HomeAgent Server 实例；
- 一组由该管理员完全信任的自有设备；
- Agent 主动建立 HTTP/SSE 连接，不要求公网服务端能够主动进入设备所在局域网；
- 允许计划维护期间短时不可用，不承诺多实例高可用或无损故障切换。

### 2.2 非目标

本文不解决：

- 多租户、设备所有权隔离、RBAC 或组织管理；
- 多地域、多实例、自动故障转移和共享会话；
- 将家庭设备的 SSH 端口直接暴露到公网；
- 保证公网服务端能够直接发送局域网广播包；
- 依赖 HTTP 反向代理之外的 CDN、WAF 或身份代理的特定产品配置；
- 对现有认证、安全头、可信代理、限流或存储实现进行代码加固。

### 2.3 容量定位

本文面向个人规模的单实例运行。连接数、设备数、事件频率、状态文件增长速度和磁盘写入上限在现有设计中没有量化 Benchmark，因此不声明具体容量。上线前必须以计划接入的全部设备连续运行 24 小时：不得出现 Server 或 Agent 非预期退出，不得丢失已受理命令的终态，每个测试事件应在 5 秒内到达 Agent，连接/断开测试后活动连接数和文件描述符必须回到基线。该结果只覆盖本次实测设备数，不得外推；超出实测范围时必须重新执行性能验收。

## 3. 当前实现依据与已知边界

当前服务端和 Agent 已具备以下适合公网中心节点的基础能力：

- 服务端使用 Go `net/http` 提供 Web、REST 与 SSE 接口；
- Agent 使用设备专属凭据主动访问自身资源；
- 管理员使用服务端 Session；设备接入使用短期 Claim Token；
- 指令通过 SSE 下发，执行结果通过 HTTP ACK 或状态上报回传；
- Agent 具备断线后重新建立控制连接的运行路径；
- 服务端使用本地文件保存设备、认证、命令、健康和告警等状态。

部署时必须接受以下边界：

1. **单点边界**：Server 或所在主机不可用时，控制台、SSE 下发和状态回传同时中断。
2. **本地存储边界**：数据目录只属于一个实例，不支持多个 Server 共享写入。
3. **内存连接边界**：活跃 SSE 连接绑定当前进程；服务重启后由 Agent 重连。
4. **网络方向边界**：Agent 主动连接服务端可跨 NAT；服务端主动 SSH 到家庭设备通常不可跨 NAT。
5. **广播边界**：公网主机无法直接向远端家庭局域网发送有效的 WOL 二层广播。
6. **地址边界**：Agent 上报的地址可能是局域网地址、临时 IPv6 或不可从服务端到达的地址，不能仅凭“已上报”推断“公网可直连”。

## 4. 部署决策

### 4.1 推荐拓扑

```text
管理员浏览器 / HomeAgent Agent
              │
              │ HTTPS :443
              ▼
       公网域名与反向代理 (Caddy 2.x)
       - TLS 终止 (自动 ACME)
       - SSE 流式转发 (flush_interval -1)
       - 请求 ID 注入与脱敏日志
              │
              │ HTTP 127.0.0.1:8080
              ▼
       homeagent-server
              │
              ▼
       独占持久化数据与资产目录
```

本文推荐反向代理与 HomeAgent 位于同一主机，使用 loopback 转发。反向代理与 HomeAgent 分离部署仅作为需要额外设计审查的允许变体，不与推荐方案同等对待。

强制部署契约：

- 公网只开放反向代理入口，通常为 TCP 443；
- `homeagent-server` 只监听 `127.0.0.1:8080`，不得同时通过公网地址或安全组暴露 8080；
- 推荐方案中反向代理与 HomeAgent 位于同一主机并使用 loopback；若选择分离部署，必须改用隔离私网、限制来源，并在实施文档中补充该网络的认证与可用性契约；
- 所有浏览器、安装脚本和 Agent 配置统一使用同一个规范化 HTTPS Server URL；
- 反向代理必须支持 SSE 立即刷新、长时间响应和客户端断开传播；当前实现默认每 30 秒发送一次 SSE ping，Agent 重连退避上限为 30 秒并增加小于 25% 的随机抖动；
- 数据目录必须位于持久磁盘，并纳入一致性备份。

### 4.2 为什么选择 SSE

HomeAgent 的主要通信方向是服务端持续下发控制事件，Agent 通过独立 HTTP 请求回传 ACK 和状态。SSE 与该方向匹配，能够复用 HTTP 认证和反向代理基础设施。公网长连接不是本方案的限制；实际门禁是代理是否缓冲响应、空闲超时是否大于心跳间隔、断线后是否能够重连并重新收敛状态。按当前默认值，代理 SSE 空闲读取超时不得低于 2 分钟；若代码或部署参数改变 ping 间隔，必须同步调整并重跑验收。

### 4.3 不采用的拓扑

| 方案 | 本文不采用的原因 |
| --- | --- |
| 直接暴露 `:8080` | 绕过 TLS 终止、代理连接治理和统一公网入口，也使转发头信任边界无法成立。 |
| 多个 Server 共享一个数据目录 | 当前文件存储和内存 Broker 没有跨实例协调契约。 |
| CDN 默认代理所有 API | CDN 对 SSE 超时、缓冲、缓存和请求头的行为必须逐项实测，不能作为默认前提。 |
| 服务端主动连接所有家庭设备 | NAT、动态地址和局域网防火墙使该路径通常不成立。 |

### 4.4 实施前置任务

以下前置任务属于本文公开部署链路的一部分，但本次纯文档变更不实现它们。任一未完成时不得开始公网部署：

1. **安装资产完整性**：另建代码任务，为 `install.sh` 和 `install.ps1` 增加发布清单/哈希下载、SHA256 校验及校验不匹配时安全失败；fixture 必须源于真实发布服务观察，并覆盖清单缺失、资产 404、重定向异常和哈希不符反例。
2. **目标环境部署清单**：实施任务必须确定真实域名、主机、Caddy 版本、证书挑战方式、服务用户、绝对数据/脚本/下载目录、防火墙规则、证据目录和备份介质。
3. **真实代理链预检**：在任何 Agent 迁移前，以目标 Caddy 进程和真实域名验证 DNS、完整 TLS/重定向链、转发头覆盖、SSE 刷新、断开传播和上游失败行为。

## 5. 域名、端口与进程配置

### 5.1 DNS 与端口

建议为服务端分配独立域名，例如 `homeagent.example.com`。DNS 记录必须解析到反向代理的公网地址。

主机入站端口基线：

| 端口 | 来源 | 用途 | 要求 |
| --- | --- | --- | --- |
| TCP 443 | 公网 | HTTPS Web、API、SSE | 必须开放。 |
| TCP 80 | 公网 | ACME HTTP-01 证书签发与 HTTPS 强制重定向 | 开放给 Caddy 自动管理证书与 301 跳转。 |
| TCP 8080 | 无公网来源 | HomeAgent 内部 HTTP | 仅 loopback（127.0.0.1）监听，严禁对公网暴露。 |
| TCP 22 | 管理员固定入口或私网 | VPS 运维 | 不属于 HomeAgent 设备 SSH 管理链路。 |

### 5.2 HomeAgent 启动参数与通信域名配置

部署实例应显式提供管理员用户名、初始管理员密码、持久化数据目录、脚本目录、下载资产目录与公网通信域名，不依赖首次启动把随机密码输出到日志：

```sh
HOMEAGENT_LISTEN="127.0.0.1:8080" \
HOMEAGENT_PUBLIC_URL="https://homeagent.rokilai.online" \
HOMEAGENT_DATA_DIR="/var/lib/homeagent/data" \
HOMEAGENT_SCRIPTS_DIR="/var/lib/homeagent/scripts" \
HOMEAGENT_DOWNLOADS_DIR="/var/lib/homeagent/downloads" \
HOMEAGENT_ADMIN_USERNAME="admin" \
HOMEAGENT_ADMIN_PASSWORD="<从受控凭据源注入的高强度密码>" \
homeagent-server serve
```

通信域名与资产分发约束：

- **默认通信域名与自建自定义覆盖**：系统默认标准通信入口为 `https://homeagent.rokilai.online`；自建用户可通过配置文件 `server.public_url` 或环境变量 `HOMEAGENT_PUBLIC_URL` 覆盖为自己的公网域名或内网 IP。服务端将通过 API 向 Web 控制台下发该地址，控制台根据该配置动态生成设备接入命令；
- 密码不得写入仓库、镜像、公开脚本或 shell 历史；
- 生产启动环境不得继续使用示例值 `CHANGE_ME`；
- 数据、脚本和下载目录属主必须为运行 HomeAgent 的专用系统用户（如 `homeagent:homeagent`）；
- 数据目录属主权限建议为 `0700`，脚本目录与下载目录权限为 `0755`，内部文件为 `0644` 或 `0755`；
- 数据目录及其中认证、设备和 SSH 密钥文件不得被 Web Server 作为静态目录发布；
- 脚本目录必须包含 `install.sh` 与 `install.ps1`，下载目录可作为离线/私网环境的下载兜底（提供 `/downloads/` 入口）；
- 服务管理器必须显式声明上述绝对路径与确定工作目录，不得依赖默认相对目录 `scripts` 或交互式 shell 的当前工作目录；
- `HOMEAGENT_JOIN_TOKEN` 仅用于确有需要的旧设备迁移，新部署不应默认启用。

### 5.3 进程守护

公网部署必须由操作系统服务管理器（如 systemd）托管 `homeagent-server`，并在单元配置中确定工作目录、运行身份与环境变量。

systemd 服务配置基线示例（`/etc/systemd/system/homeagent.service`）：

```ini
[Unit]
Description=HomeAgent Central Server
After=network.target network-online.target
Wants=network-online.target

[Service]
Type=simple
User=homeagent
Group=homeagent
WorkingDirectory=/var/lib/homeagent
EnvironmentFile=/etc/homeagent/homeagent.env
ExecStart=/usr/local/bin/homeagent-server serve
Restart=on-failure
RestartSec=5s
TimeoutStopSec=15s
LimitNOFILE=65535

# 安全沙箱与权限加固
ProtectSystem=strict
ReadWritePaths=/var/lib/homeagent/data
ReadOnlyPaths=/var/lib/homeagent/scripts /var/lib/homeagent/downloads
PrivateTmp=true
ProtectHome=true
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

### 5.4 服务端极简安装契约（`install-server.sh`）

为免除自建用户安装 Go 开发环境与手动编译的负担，系统提供一键服务端安装与更新脚本 `scripts/install-server.sh`：

1. **自动识别与下载**：检测当前系统的 OS 与 Arch，直接从 GitHub Release 下载预编译的 `homeagent-server-${os}-${arch}` 及同名 `.sha256` 校验文件；
2. **SHA256 完整性比对**：下载后优先使用 `sha256sum`/`shasum` 比对，校验不匹配立即中止并清理临时文件；
3. **系统目录就位**：原子安装至 `/usr/local/bin/homeagent-server`，并创建受限数据目录 `/var/lib/homeagent/data`；
4. **服务配置生成**：在 Linux 环境下自动生成 `/etc/systemd/system/homeagent.service` 与 `/etc/homeagent/homeagent.env` 模板，支持 `systemctl enable --now homeagent` 立即启动。

必须满足：

- 开机启动；
- 异常退出后按受控退避重启（如 `RestartSec=5s`）；
- 停止时给予服务端优雅关闭时间（如 `TimeoutStopSec=15s`）；
- 日志有容量或时间轮转（由 systemd journald 或外部 logrotate 托管）；
- 启动环境与交互式 shell 分离，环境变量由只读的 `EnvironmentFile`（权限 `0600`）注入；
- 升级前能够停止服务、备份数据并回滚二进制。

## 6. 反向代理契约

### 6.1 必须满足的行为

反向代理必须：

1. 在公网入口终止 TLS；若开放 TCP 80，则该端口只能用于 ACME 证书验证或 301 重定向到 HTTPS；
2. 将请求转发到唯一的 HomeAgent 内部地址（`127.0.0.1:8080`）；
3. 覆盖客户端提供的转发头，根据代理实际观察重新设置来源协议和地址；
4. 注入或保留全局唯一请求 ID（`X-Request-ID`），贯穿代理日志与故障追踪；
5. 对 SSE 响应（`/api/v1/devices/{id}/events`）禁用缓冲与压缩，设置流式刷新，及时向客户端推送事件；
6. 为普通 API 设置合理的请求体大小上限（默认 10MB）和空闲超时，同时为 SSE 保持长响应通道；
7. 将上游不可用明确返回为网关错误（502/504），不缓存登录、Claim、设备 API 或 SSE 响应；
8. 输出结构化访问日志，记录请求 ID、客户端真实 IP、请求方法、URI、状态码、上游耗时与上游状态，但必须过滤脱敏 `Cookie`、`Authorization`、Claim Token、Device Token 与密码。

### 6.2 规范反向代理基线：Caddy 2.x

本方案选定 **Caddy 2.x** 作为唯一规范反向代理基线。个人单实例场景下，Caddy 原生内置全自动 ACME 证书管理、HTTP/2 / HTTP/3 支持以及优良的流式转发特性，运维复杂度低于维护独立的 Web 服务器加 Certbot 续期脚本。

Caddyfile 规范配置基线：

```caddyfile
homeagent.example.com {
    # 1. 结构化 JSON 访问日志与脱敏
    log {
        output file /var/log/caddy/homeagent_access.log {
            roll_size 50mb
            roll_keep 7
            roll_keep_for 720h
        }
        format json
    }

    # 2. 基础请求限制
    request_body {
        max_size 10MB
    }

    # 3. 注入请求追踪 ID
    request_header X-Request-ID {http.request.uuid}

    # 4. SSE 控制流反向代理：禁用缓冲与压缩、立即刷新、长超时
    @sse path_regexp sse ^/api/v1/devices/[^/]+/events$
    handle @sse {
        reverse_proxy 127.0.0.1:8080 {
            flush_interval -1
            header_up -X-Forwarded-For
            header_up X-Forwarded-For {remote_host}
            header_up X-Forwarded-Proto {scheme}
            header_up X-Forwarded-Host {host}
            header_up X-Request-ID {http.request.uuid}
        }
    }

    # 5. 常规 REST API、静态 UI 与分发入口反向代理
    handle {
        reverse_proxy 127.0.0.1:8080 {
            header_up -X-Forwarded-For
            header_up X-Forwarded-For {remote_host}
            header_up X-Forwarded-Proto {scheme}
            header_up X-Forwarded-Host {host}
            header_up X-Request-ID {http.request.uuid}
        }
    }
}
```

上线前必须在目标主机执行 `caddy validate --config /etc/caddy/Caddyfile`，并通过真实请求验证：
- 访问日志输出完整的 JSON 字段（包含 `duration`, `status`, `request_id`）；
- 伪造的客户端 `X-Forwarded-*` 请求头被代理实际观察值覆盖；
- SSE 事件在下发后 5 秒内到达 Agent，不产生额外缓冲延迟；
- 客户端主动断开后，Caddy 及时向上游 `homeagent-server` 发送关闭信号并释放连接。

### 6.3 附录：Nginx 配置参考（非规范）

若因特殊环境要求无法使用 Caddy，可参考以下 Nginx 配置。该配置不作为本方案主推荐基线，采用时必须单独完成证书自动化和日志轮转设计：

```nginx
# 仅供非规范参考，需自行配置 certbot 证书及日志脱敏
server {
    listen 443 ssl http2;
    server_name homeagent.example.com;

    # ssl_certificate /path/to/fullchain.pem;
    # ssl_certificate_key /path/to/privkey.pem;

    client_max_body_size 10m;

    # SSE 控制流路由
    location ~ ^/api/v1/devices/[^/]+/events$ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Request-ID $request_id;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 2m;
        chunked_transfer_encoding on;
    }

    # 常规请求
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Request-ID $request_id;
        proxy_read_timeout 60s;
    }
}
```

## 7. 公网运行链路

### 7.1 管理员访问

```text
浏览器访问 HTTPS 域名
  → 登录接口验证用户名和密码
  → 浏览器保存 HttpOnly Session Cookie
  → 管理 API 使用 Session
  → 退出时服务端撤销 Session 并清除 Cookie
```

管理员应从公网域名完成首次登录并立即验证密码修改、退出和旧 Session 失效路径。不得使用内部 HTTP 地址的成功结果代替公网入口验收。

### 7.2 新设备接入

```text
管理员登录控制台
  → 创建短期、单次 Claim Token
  → 控制台生成带 public_url 与 Token 的安装命令
  → 目标设备从 GitHub 下载安装脚本与目标架构二进制及 .sha256 校验文件
  → 校验哈希匹配（不匹配则立即中止安装并清理临时文件）
  → 执行 claim 指令向 HOMEAGENT_SERVER 提交 Claim Token
  → Agent 获得并持久化专属 Device Token
  → Claim Token 消耗或过期
  → Agent 使用 Device Token 建立自身 SSE 控制连接
```

安装资产分发与完整性校验契约：

1. **GitHub 资产分发与覆盖策略**：
   - 安装脚本默认从 GitHub Release 规范路径下载对应平台的 Agent 二进制与 `.sha256` 校验文件：
     `https://github.com/${repo}/releases/download/${version}/homeagent-agent-${os}-${arch}`
   - **私网/离线扩展点**：支持通过 `HOMEAGENT_DOWNLOAD_BASE_URL` 覆盖下载源（例如企业私网内指定为服务端自带的 `http://192.168.1.100:8888/downloads`）。
2. **默认通信域名与自建自定义覆盖**：
   - 若执行安装脚本时未显式设置 `HOMEAGENT_SERVER` 环境变量，脚本默认回退至 `https://homeagent.rokilai.online`；
   - 自建用户在控制台配置或环境变量设置 `HOMEAGENT_PUBLIC_URL` 后，控制台生成的命令将自动嵌入该通信域名。
3. **设备安装与接入双模式契约**：
   - **模式 1：零参数极简安装（文档与手动运维呈现）**：
     - 用户直接运行纯安装命令，无需在安装时提供任何 Token 或参数：
       - POSIX: `curl -fsSL https://raw.githubusercontent.com/RokiLai/home-agent/main/scripts/install.sh | sh`
       - Windows: `irm https://raw.githubusercontent.com/RokiLai/home-agent/main/scripts/install.ps1 | iex`
     - 安装脚本下载并校验二进制后就位，提示用户后续执行：
       - `homeagent-agent claim --claim-token "<claim-token>"`
       - `homeagent-agent service install`
   - **模式 2：一步到位自动接入（Web 控制台动态生成）**：
     - 若当前通信域名为系统默认的 `https://homeagent.rokilai.online`，控制台省略 `HOMEAGENT_SERVER` 前缀以呈现最短单行命令：
       - **macOS / Linux / OpenWrt**：
         ```sh
         curl -fsSL https://raw.githubusercontent.com/RokiLai/home-agent/main/scripts/install.sh | HOMEAGENT_CLAIM_TOKEN="${token}" sh
         ```
       - **Windows (PowerShell)**：
         ```powershell
         $env:HOMEAGENT_CLAIM_TOKEN="${token}"; irm https://raw.githubusercontent.com/RokiLai/home-agent/main/scripts/install.ps1 | iex
         ```
     - 若管理员自定义了 `public_url`，控制台自动补充 `HOMEAGENT_SERVER="${effectiveServerURL}"`。
4. **下载与校验顺序**：安装脚本在下载二进制后、执行任何可执行操作前，必须通过 HTTPS 获取同源 `.sha256` 文件并执行摘要比对：
   - POSIX 环境：优先使用 `sha256sum -c`，兜底使用 `shasum -a 256 -c`；
   - Windows 环境：使用 `Get-FileHash -Algorithm SHA256` 对比 `.sha256` 文件内容。
5. **安全失败**：若 `.sha256` 404、校验和不匹配或哈希工具不可用，脚本必须立即删除下载的临时二进制文件，向标准错误输出明确失败信息，并以非零状态码退出，严禁执行未通过完整性校验的文件。
6. **单次认领**：认领成功后，Device Token 存入本地配置（权限 0600），Claim Token 立即在服务端标记已消耗，后续通信使用专属 Device Token。

### 7.3 SSE 连接与恢复

公网验收必须观察完整链路：

```text
Agent 发起 SSE 请求
  → DNS 解析
  → TLS 握手
  → 反向代理转发请求
  → HomeAgent 设备身份校验
  → SSE 建连并收到事件或 ping
  → Agent 执行事件
  → ACK/状态请求经同一公网入口返回
```

必须分别测试：代理重载、Server 重启、客户端网络切换、短时断网和 DNS 地址变化。按当前 Agent 默认退避，公网入口恢复可用后应在 45 秒内重新建立 SSE；超时即验收失败。验收关注点不是“连接曾经成功”，而是断线后 Agent 是否自动重连、设备最终状态是否与恢复后最新上报一致，并且同一命令 ID 不得生成第二次执行记录或额外副作用。

## 8. NAT 下的功能边界

### 8.1 SSH 同步

SSE 下发由 Agent 主动连接，因此通常能够穿过家庭 NAT。服务端的 SSH 兜底同步属于相反方向：公网 Server 主动连接设备上报地址。除非设备具有服务端可路由的 IPv6、VPN 地址或端口映射，否则该路径应视为不可用。

个人公网部署的默认行为应是：

- 以 SSE/Agent 本地执行作为主控制路径；
- 不为 SSH 兜底而把家庭设备 SSH 端口直接暴露公网；
- 如果确需服务端 SSH，使用明确受控的 VPN 地址，并单独验证路由、主机密钥和访问策略；
- 控制台中的 SSH 失败不得自动推断 Agent/SSE 离线。

### 8.2 Wake-on-LAN

WOL 魔术包通常需要在目标设备所在二层网络或可转发该广播的网关内发送。公网 Server 直接发送不能证明家庭设备可被唤醒。

在没有局域网代理能力前：

- 只把 WOL 视为服务端与目标设备位于同一可广播网络时可用；
- 不把公网部署后的 WOL 按钮存在作为功能可用证据；
- 如需远程 WOL，应另行设计由家庭内常在线 Agent 或路由器代发的契约与测试。

### 8.3 IPv6 与 DDNS

具有全局 IPv6 地址不等于从公网 Server 可达。地址选择还受临时地址、前缀变化、主机防火墙和运营商入站策略影响。DDNS 更新成功也只证明 DNS 提交成功，不证明端口可达或目标服务正确。

本文不预设 DDNS 记录指向公网 Server 还是家庭设备；实际部署必须逐条记录声明其目标和用途。涉及 IPv6/DDNS 时，必须分别验证：

- Agent 上报地址及其接口来源；
- 目标服务确实监听所选地址，且主机与边界防火墙允许预期来源；
- DNS 权威查询结果；
- 从独立公网网络发起的实际可达性；
- 前缀变化后的更新、旧记录清理和失败恢复。

## 9. 数据、备份与恢复

### 9.1 备份范围

至少备份整个 `HOMEAGENT_DATA_DIR`，而不是只备份 `devices.json`。该目录可能包含：

- 管理员密码哈希与 Session（`auth.json`）；
- Enrollment/Claim 状态（`enrollment.json`）；
- 设备记录及 Device Token Hash（`devices.json`）；
- 服务端 SSH 管理密钥（`keys/`）；
- 命令持久化状态（`commands.json`）；
- 健康与告警状态（`health/`, `alerting/`）；
- ACL 配置（`acl.yaml`）。

### 9.2 一致性要求

由于状态由多个本地文件组成，直接在服务运行时逐文件复制不具备一致快照保证。默认恢复流程应为：

1. 阻止新的公网请求或进入维护窗口；
2. 优雅停止 `homeagent-server`；
3. 对完整数据目录创建带时间戳的原子快照或文件系统快照；
4. 记录来源版本、UTC 时间、数据规模和文件清单，对备份生成校验和，并校验文件可读性、权限与属主；
5. 启动服务并执行健康与登录冒烟测试。

如目标文件系统提供已验证的一致性快照能力，可在后续部署文档中记录替代流程。未经恢复演练的备份不得视为有效恢复能力。

### 9.3 恢复验收与适用边界

恢复必须在隔离环境或维护窗口验证：

- 管理员能够登录；
- 设备记录与 ACL 未丢失；
- 服务端 SSH 公钥身份未意外变化；
- 恢复点之前存在且未过期的 Session、Claim Token 和 Device Token 按持久化记录继续有效；恢复点之后创建或撤销的凭据按时间点恢复模型丢失或回退，并在隔离环境中验证该结果；
- Agent 能够重新连接并上报状态；
- 恢复时仍为非终态的命令在 Server 启动后转为 `interrupted`，不得被当作成功或自动重复执行。

**备份恢复适用范围与凭据事故安全门禁**：

1. **适用场景（灾难数据恢复）**：本文定义的快照备份与时间点恢复，**仅适用于主机损坏、硬件故障、误删数据等非凭据安全事故**。在该场景下，备份恢复能完整找回设备清单与历史配置。
2. **不适用场景与凭据事故安全门禁**：时间点恢复本质上会将数据回退到历史快照，这会导致快照之后已被管理员撤销、废弃或已泄露的凭据（Session、Claim Token、Device Token、旧管理员密码）在恢复后重新变为“有效”，带来凭据复活安全风险。鉴于当前单实例部署尚未提供离线全量凭据作废与强制吊销 CLI，**本部署方案明确将凭据泄露/注销事故排除在时间点快照恢复之外**。
3. **凭据事故标准处置路径**：若发生管理员密码泄露、Session 劫持或 Device Token 大规模泄露事故，严禁直接从旧备份还原开放公网；必须作为全新实例重新部署，初始化高强度管理员密码，并通过控制台生成新的短期 Claim Token，由管理员对全部自有设备执行全量重新认领（Re-claim）。

## 10. 日志、监控与告警

最低运行监控包括：

- 反向代理 TLS 证书到期时间；
- 公网 HTTPS 健康请求的状态码与延迟；
- HomeAgent 进程存活、重启次数和退出原因；
- 磁盘空间、inode 和数据目录增长；
- 登录失败与限流事件；
- SSE 当前连接、频繁重连和上游 5xx；
- 命令超时、设备离线、DDNS 和告警通道失败；
- 最近一次备份及最近一次成功恢复演练时间。

`GET /health` 只能证明 HTTP 进程能够响应，不证明认证、持久化、SSE、Agent ACK 或外部集成正常。因此至少还需要一个真实设备的端到端合成检查或人工冒烟流程。

日志中不得出现：

- 管理员密码；
- `Cookie` 或 `Authorization` 完整值；
- Claim Token、Device Token、GitHub/Cloudflare Token 或 Webhook Secret；
- SSH 私钥内容。

## 11. 升级与回滚

### 11.1 升级前

- 记录当前正式版本和目标候选版本；
- 阅读版本变更与数据兼容说明；
- 执行完整数据目录一致性备份；
- 保存当前二进制和服务配置的可恢复副本；
- 验证磁盘空间和反向代理健康。

### 11.2 升级路径

涉及 Server 或 Agent 安装、升级与自动更新时，必须通过真实用户入口验证“上一正式版本 → 候选版本”。不得仅以二进制可启动、Release 资产存在或内部函数测试通过作为发布验收。

公网部署至少覆盖：

1. 上一正式版 Server 与 Agent 正常连接；
2. Server 升级后管理员经公网域名登录；
3. 上一正式版 Agent 经真实公网入口执行支持的升级路径；
4. 升级后 SSE 重连、指令、ACK 和状态展示完整闭环；
5. 失败时恢复旧二进制与备份数据，确认旧版本能够重新运行。

回滚成功必须同时证明旧版本的服务配置、二进制和数据目录均已恢复，并重新执行管理员登录、Agent SSE、无破坏性指令、ACK 和最终状态展示。实际升级任务必须记录明确版本号、资产摘要、执行命令、故障注入点、回滚触发条件与允许时限；这些环境参数未确定前不得批准该次升级。

Server 升级前还必须验证候选 Agent 与上一正式版 Server 的兼容矩阵。只有候选 Agent 能在旧 Server 上完成 Claim 或既有凭据启动、SSE、指令和 ACK 闭环时，才允许先升级 Agent；否则必须先设计真实可执行的 Agent 回滚入口，并在升级计划中覆盖“Server 已回滚、部分 Agent 已升级、其余 Agent 未升级”的混合版本状态。缺少上述兼容证据或 Agent 回滚路径时，禁止开始 Agent 升级。

## 12. 真实公网验收矩阵

以下检查必须从独立公网网络执行，不能全部在 Server 本机或同一 loopback 链路完成。证据统一保存到该次部署验收目录，以 `UTC时间-检查编号-环境-摘要` 命名；代理请求 ID、命令 ID 和设备 ID 应贯穿关联日志。包含敏感值的原始证据必须先脱敏再归档。

| 编号 | 成功标准 | 验证手段 | 必须保存的证据 | 当前状态 |
| --- | --- | --- | --- | --- |
| PA-01 | DNS 指向目标公网入口 | 从至少两个独立递归解析器查询 A/AAAA | 查询时间、完整答案和 TTL | 未执行 |
| PA-02 | 公网入口只提供预期端口 | 从独立公网主机执行端口探测 | 目标地址、端口及结果 | 未执行 |
| PA-03 | HTTPS 证书链有效；若开放 HTTP，则 HTTP 强制进入 HTTPS | 记录 TLS 协议、证书主机名和有效期；开放 80 时另记录完整重定向 | 原始响应头和证书摘要 | 未执行 |
| PA-04 | 8080 不能绕过代理访问 | 从公网直接访问公网 IP:8080 | 连接失败或明确拒绝证据 | 未执行 |
| PA-05 | 管理员登录、修改密码、退出完整有效 | 通过公网域名执行真实浏览器流程 | Console 无未捕获异常；Network、Cookie 属性、关键页面可见、入口可交互和旧 Session 失效结果 | 未执行 |
| PA-06 | Claim Token 只能成功认领规定次数 | 并发提交有效 Claim，并提交过期/错误 Claim 反例 | 每次请求状态与最终设备记录 | 未执行 |
| PA-07 | Agent 能通过公网域名建立 SSE | 记录 DNS、TLS、HTTP 状态和首个事件/ping | 代理日志、Server 日志和 Agent 日志关联 | 未执行 |
| PA-08 | SSE 不被代理缓冲 | 连接后 45 秒内收到默认 ping；下发测试事件后 5 秒内到达 Agent | 同一事件的服务端与 Agent 时间戳 | 未执行 |
| PA-09 | 网络中断后自动恢复 | 断开 Agent 网络 2 分钟后恢复；入口恢复后 45 秒内重连 | 断线、退避、重连和状态收敛时间线；同一命令 ID 无第二次执行 | 未执行 |
| PA-10 | Server 重启后连接恢复 | 在无在途高风险操作时重启 Server，入口恢复后 45 秒内重连 | 重启前后连接与任务状态；设备最新上报字段一致 | 未执行 |
| PA-11 | 指令形成下发—执行—ACK 闭环 | 向测试设备执行无破坏性指令 | 命令 ID、事件、ACK 和最终 UI 状态 | 未执行 |
| PA-12 | 凭据不出现在日志 | 对代理、Server、Agent 日志执行敏感值检索 | 检索规则与零命中结果 | 未执行 |
| PA-13 | 备份可在非凭据事故下恢复 | 在隔离环境恢复完整数据目录，模拟主机损毁恢复 | 恢复前后文件校验和清单、管理员登录、设备列表与功能冒烟结果；确认未完结命令转为 interrupted | 未执行 |
| PA-14 | 代理重载后 SSE 自动恢复 | 重载真实代理；若连接中断，入口恢复后 45 秒内重连 | 中断时长、重连和最终状态 | 未执行 |
| PA-15 | 外部假设失效时安全失败 | 分别模拟 DNS 错误、证书过期/不受信、代理上游不可达 | Agent/浏览器拒绝或明确失败证据，无降级到明文 | 未执行 |
| PA-16 | 客户端断开能够释放上游 SSE | 连续执行 20 轮连接/主动断开；每轮关联代理上游关闭与 Server 请求结束 | 每轮 10 秒内出现对应设备断开日志；上游活动 TCP 连接数回到基线，进程文件描述符与内存不得随轮次单调增长 | 未执行 |
| PA-17 | 安装资产通过 GitHub Release（或自定义下载源）完整下载并通过哈希校验；public_url 配置生效 | 使用正式安装入口从 GitHub Release 下载脚本、二进制与 .sha256 文件，执行完整安装与 Claim；另注入哈希不匹配反例；验证自定义 public_url 在 API 与控制台生效 | 完整 URL、重定向链、状态码、SHA256 校验匹配日志、Claim 成功记录，以及哈希不匹配时安装脚本安全中止并清理的终端证据 | 未执行 |
| PA-18 | 上一正式版本可升级并完整回滚 | 记录明确版本号，从真实用户入口升级；注入失败后恢复旧二进制、配置和数据 | 命令、资产摘要、升级与回滚时间线，以及登录、SSE、指令、ACK、UI 复验 | 未执行 |

对远程关机、升级等具有破坏性或不可逆影响的指令，应使用专用测试设备并单独获得执行授权；不得为了完成文档验收直接操作日常生产设备。

## 13. 外部假设审计记录模板
