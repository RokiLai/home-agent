## 背景与目标

在家庭、私有云或云服务器部署场景下，用户希望将 HomeAgent 服务端直接暴露在公网（或配合反向代理/域名访问）。原有的鉴权方式采用全局静态 `HOMEAGENT_JOIN_TOKEN`，在公网环境下存在以下不足：

1. **用户记忆负担重**：高强度的随机 Token 难以记忆，在不同终端或浏览器访问 Web 控制台时需要频繁翻找复制。
2. **缺乏标准 Web 会话管理**：未携带凭证访问时直接加载前端面板并产生大量 401 API 错误，缺乏标准登录、注销与 HttpOnly 会话安全机制。
3. **凭据权限未解耦**：旧静态全局 Token 破坏了控制台管理、临时设备接入与设备日常通信之间的权限隔离，若在客户端终端历史或安装日志中残留，存在全局越权安全风险。

### 核心设计目标

- **管理员端**：支持**用户名 + 密码**登录 Web 控制台，基于 **Server-side Session + HttpOnly Cookie** 实现会话管理，支持 7 天记住登录状态与一键安全登出；Web 前端不再存储与传输 Admin Bearer Token。
- **设备接入端**：在 Web 控制台一键生成**短期有效（默认 15 分钟 / 单次即焚）的 Claim Token**；客户端安装脚本无需配置静态密码，运行单行命令即可自动完成设备绑定与专属凭证分发。
- **三层凭证体系与最小权限**：彻底解耦管理员会话（Admin Session）、临时接入凭据（Claim Token）与设备专用凭据（Device Token），实现最小权限原则、资源级防越权（IDOR）与公网防爆破保护。
- **凭据哈希存储与安全持久化**：服务端统一仅保存 Token 的 SHA-256 哈希（密码使用 bcrypt 哈希），客户端安全配置本地文件权限（0600 / Windows ACL），全链路日志脱敏。

### 架构边界与非目标（明确不引入）

为保持 HomeAgent 单实例轻量化部署与极简运维特性，本次改造**明确不引入**以下复杂组件与架构：
- 不引入 OAuth / OIDC / 第三方联合登录；
- 不引入 JWT（无状态签名）或复杂的公私钥 JWT 体系；
- 不引入 Redis / Memcached / 分布式缓存；
- 不引入 mTLS / 客户端 PKI 证书体系；
- 不引入 API Gateway / 独立的认证微服务；
- 不引入 新的外部数据库（继续复用现有 SQLite/YAML 本地存储）；
- 不引入 分布式锁机制（单实例内通过 Go `sync.Mutex` 或存储层原子语义保证一致性）；
- 不引入 复杂多租户 RBAC 与多管理员体系。

## 2. 系统总体架构与时序图

### 2.1 三层凭证体系矩阵

```text
                     HomeAgent Server
                            │
            ┌───────────────┼───────────────┐
            │               │               │
      Admin Session     Claim Token     Device Token
            │               │               │
     HttpOnly Cookie     15min / 1次        长期
            │               │               │
       管理系统资源       仅 devices/claim   仅自身资源
                            │
                            │
                            ▼
                      Device Token
```

| 凭据类型 | 生命周期 | 适用主体 | 传递方式 | 权限范围 | 服务端存储 | 客户端存储 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Admin Session** | 7 天（记住登录）或 浏览器临时会话 | Web 控制台 / 管理员 | `HttpOnly Cookie` (`SameSite=Strict`, `Path=/`, `Secure`) | 全局管理、设备增删改、密钥分发、远程唤醒与关机、生成与作废 Claim Token | `SHA-256(token)` | 浏览器 Cookie (HttpOnly，JS 不可读) |
| **Claim Token** | 短期（默认 15 分钟，支持 `max_uses=1` 即焚） | 客户端安装脚本 / `install.sh` | `Authorization: Bearer <claim_token>` | **仅允许**调用设备认领接口 (`POST /api/v1/devices/claim`)，严禁访问任何 Admin/Device API | `SHA-256(token)` | 仅临时保存在安装命令行环境变量中，认领完成后即弃 |
| **Device Token** | 长期（与服务端生成的 `device_id` 强绑定） | `homeagent-agent` 守护进程 | `Authorization: Bearer <device_token>` | **仅允许**访问自身资源（上报自身状态、建立自身 SSE 长连接、自身 ACK 回执），严禁跨设备与访问 Admin API | `SHA-256(token)` + 关联 `device_id` | 本地配置文件（Linux/macOS `0600`，Windows ACL 限制） |

### 2.2 服务端凭证存储架构

```text
HomeAgent Server Storage (DB / YAML)
│
├── Admin Password
│      └── bcrypt Hash (Cost = 12, 仅启动初始化/后台修改)
│
├── Admin Sessions
│      └── { token_hash: SHA-256, user_id, created_at, expires_at }
│
├── Claim Tokens
│      └── { token_hash: SHA-256, expires_at, remaining_uses, description }
│
└── Device Records
       └── { device_id: ULID/UUID, device_token_hash: SHA-256, metadata: {...} }
```

> [!IMPORTANT]
> - 服务端数据库、状态文件与 YAML **严禁存储任何明文 Token**。
> - 所有 Token 在生成时仅向调用方返回一次明文，服务端仅持久化其 SHA-256 哈希。
> - 校验时对请求携带的明文 Token 计算 SHA-256 后比对哈希值。

### 2.3 完整认证与认领时序

```mermaid
sequenceDiagram
    autonumber
    actor Admin as 管理员
    participant Web as Web 控制台 UI (Browser)
    participant Server as HomeAgent Server
    participant Storage as 数据持久层 (YAML/DB)
    participant Client as 待接入设备 (Agent / install.sh)

    Note over Admin,Storage: 阶段一：管理员登录与 Session Cookie 建立
    Admin->>Web: 浏览器访问 Web 控制台，输入用户名与密码
    Web->>Server: POST /api/v1/auth/login { username, password, remember_me: true }
    Server->>Server: bcrypt 校验密码哈希
    Server->>Server: 生成 64 字符高强度随机 Session Token
    Server->>Storage: 保存 Session Token Hash、过期时间与用户元数据
    Server-->>Web: 200 OK + Set-Cookie: homeagent_session=...; HttpOnly; SameSite=Strict; Path=/; Secure
    Web->>Admin: 渲染仪表盘（前端无 Token 存储，后续请求自动附带 Cookie）

    Note over Admin,Web: 阶段二：生成短期设备认领凭据
    Admin->>Web: 进入「快速接入向导」页面
    Web->>Server: POST /api/v1/enrollment-tokens { ttl_seconds: 900, max_uses: 1 } (Cookie 鉴权)
    Server->>Server: 生成高强度随机 Claim Token (如 claim_7b9d31...)
    Server->>Storage: 保存 Claim Token Hash、过期时间与 max_uses=1
    Server-->>Web: 201 Created (返回一次性明文 Claim Token)
    Web->>Admin: 动态渲染带倒计时的单行安装命令

    Note over Admin,Client: 阶段三：客户端执行单行安装脚本
    Admin->>Client: 终端粘贴运行: curl -fsSL https://server/install.sh | HOMEAGENT_SERVER=... HOMEAGENT_CLAIM_TOKEN=... sh
    Client->>Client: 探测本地架构，下载对应 homeagent-agent 二进制
    Client->>Client: 本地生成 ed25519 SSH 密钥对，收集主机硬件元数据 (hostname, mac, ip, os, arch)
    Client->>Server: POST /api/v1/devices/claim (Header: Authorization: Bearer claim_xxx, Body: { device: {...} })
    
    Note over Server,Storage: 阶段四：服务端原子校验与专属 Device Token 派发
    Server->>Storage: 原子操作 ConsumeClaimToken (查 Hash -> 校验未过期 -> 校验 remaining_uses > 0 -> 扣减次数)
    Server->>Server: 生成全局唯一 device_id (UUID/ULID) 与 Device Token
    Server->>Storage: 保存设备元数据与 SHA-256(device_token_hash)
    Server-->>Client: 200 OK { success: true, device_id: "01K2M8...", device_token: "dev_9c8b...", admin_public_key: "..." }

    Note over Client,Server: 阶段五：设备本地凭证持久化与 SSE 闭环
    Client->>Client: 将 device_id 与 device_token 安全写入本地 (Linux/macOS 0600 权限)
    Client->>Client: 注册并启动系统服务 (launchd / systemd / Windows Service)
    Client->>Server: GET /api/v1/devices/{device_id}/events (Header: Authorization: Bearer dev_9c8b...)
    Server->>Server: 校验 Device Token Hash 且强制匹配 token.device_id == request.device_id
    Server-->>Client: 建立 SSE 长连接并即时下发 key_sync 配置快照
```

## 3. 详细 API 契约设计

### 3.1 管理员认证接口

#### 1. 管理员登录
- **请求路径**：`POST /api/v1/auth/login`
- **安全特性**：公开访问，受基于 IP 的防爆破滑动窗口限流保护
- **请求体**：
  ```json
  {
    "username": "admin",
    "password": "my-secure-password",
    "remember_me": true
  }
  ```
- **响应头**：
  ```http
  Set-Cookie: homeagent_session=agt_sess_9a8b7c6d5e4f3a2b1c...; HttpOnly; SameSite=Strict; Path=/; Max-Age=604800; Secure
  ```
  *(注：若 `remember_me=false`，则不设置 `Max-Age`，作为浏览器 Session Cookie，或服务端配置较短生命周期)*
- **响应体 (200 OK)**：
  ```json
  {
    "user": {
      "username": "admin",
      "role": "admin"
    }
  }
  ```
  *(注：响应体 JSON 中不再返回 Token 字符串，完全依赖 HttpOnly Cookie 维持状态)*

#### 2. 校验当前登录状态
- **请求路径**：`GET /api/v1/auth/me`
- **鉴权方式**：自动校验请求中的 `homeagent_session` Cookie
- **响应体 (200 OK)**：
  ```json
  {
    "authenticated": true,
    "username": "admin",
    "role": "admin"
  }
  ```
- **未登录响应 (401 Unauthorized)**：
  ```json
  {
    "error": "unauthorized",
    "message": "Valid session required"
  }
  ```

#### 3. 退出登录
- **请求路径**：`POST /api/v1/auth/logout`
- **鉴权方式**：校验 `homeagent_session` Cookie
- **服务端处理**：必须在服务端存储中立即 **Revoke / 删除** 该 Session Token Hash
- **响应头**：
  ```http
  Set-Cookie: homeagent_session=; HttpOnly; SameSite=Strict; Path=/; Max-Age=0; Expires=Thu, 01 Jan 1970 00:00:00 GMT
  ```
- **响应体 (200 OK)**：
  ```json
  {
    "success": true
  }
  ```

### 3.2 短期认领凭据（Enrollment / Claim Token）管理接口

#### 1. 创建短期认领凭据
- **请求路径**：`POST /api/v1/enrollment-tokens`
- **鉴权方式**：Admin Session Cookie
- **请求体**：
  ```json
  {
    "ttl_seconds": 900,
    "max_uses": 1,
    "description": "MacBook Pro Onboarding"
  }
  ```
- **响应体 (201 Created)**：
  ```json
  {
    "token": "claim_7b9d31f98e2a4f0c99a07d6e5c4b3a21",
    "expires_at": "2026-08-21T11:05:00Z",
    "max_uses": 1,
    "remaining_uses": 1,
    "description": "MacBook Pro Onboarding"
  }
  ```
  *(注：明文 `token` 仅在创建时返回这唯一一次，服务端仅持久化其 SHA-256 哈希)*

#### 2. 列出当前活跃的认领凭据
- **请求路径**：`GET /api/v1/enrollment-tokens`
- **鉴权方式**：Admin Session Cookie
- **响应体 (200 OK)**：
  ```json
  {
    "tokens": [
      {
        "id": "claim_7b9d31f9...",
        "created_at": "2026-08-21T10:50:00Z",
  ```

#### 3. 手动作废认领凭据
- **请求路径**：`DELETE /api/v1/enrollment-tokens/{id}`
- **鉴权方式**：Admin Session Cookie
- **响应体 (204 No Content)**

### 3.3 设备认领接口

#### 客户端使用 Claim Token 接入
- **请求路径**：`POST /api/v1/devices/claim`
- **鉴权方式**：必须且仅通过 HTTP Header 传递：`Authorization: Bearer <claim_token>`
- **请求体**（严格仅包含设备元数据与公钥，禁止在 Body 中传递 Token）：
  ```json
  {
    "device": {
      "hostname": "laptop-example",
      "os": "darwin",
      "arch": "arm64",
      "ssh_user": "exampleuser",
      "ssh_port": 22,
      "public_key": "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIExamplePublicKey...",
      "mac": "3c:22:fb:1a:2b:3c",
      "addresses": ["192.168.1.50"]
    }
  }
  ```
- **服务端处理逻辑**：
  1. 提取 Header 中的 `claim_token` 并计算 SHA-256；
  2. 调用 `ConsumeClaimToken` 原子完成查询、有效期校验与剩余次数扣减；
  3. 服务端生成全局唯一的 `device_id`（UUID 或 ULID）；
  4. 生成 64 字节高强度的 `device_token` 并保存其 SHA-256 哈希，绑定至 `device_id`；
  5. 绑定设备元数据与管理员 SSH 公钥。
- **响应体 (200 OK)**：
  ```json
  {
    "success": true,
    "device_id": "01K2M8X8J7A6B5C4D3E2F1G0H9",
    "device_token": "dev_9c8b7a6d5e4f3a2b1c0d9e8f7a6b5c4d",
    "admin_public_key": "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIAdminServerPublicKey..."
  }
  ```

---

### 3.4 设备专用 API 接口

所有设备专有通信端点统一通过专用 `Device Token` 鉴权，并强制进行资源级归属比对：

- **典型端点**：
  - `GET /api/v1/devices/{device_id}/events`（建立 SSE 事件长连接）
  - `POST /api/v1/devices/{device_id}/heartbeat`（心跳状态上报）
  - `POST /api/v1/devices/{device_id}/acks`（指令执行回执）
- **鉴权 Header**：`Authorization: Bearer <device_token>`
- **权限校验规则**：
  ```go
  // 中间件鉴权要求：
  1. Device Token 合法且未撤销；
  2. 提取 token 关联的 token.device_id；
  3. 必须满足: token.device_id == url.Path.device_id (严禁跨设备访问，否则返回 403 Forbidden)。
  ```

## 4. 客户端与安装脚本设计

### 4.1 POSIX 安装脚本交互逻辑 (`scripts/install.sh`)

用户在 Web 控制台复制单行命令后在终端执行：

```sh
curl -fsSL https://<server-ip>:8080/install.sh -o /tmp/install.sh
HOMEAGENT_SERVER="https://<server-ip>:8080" \
HOMEAGENT_CLAIM_TOKEN="claim_7b9d31f98e2a4f0c99a07d6e5c4b3a21" \
sh /tmp/install.sh
```

**脚本内部执行流**：
1. **下载二进制**：探测本地 OS 与 CPU 架构，下载对应版本的 `homeagent-agent`；
2. **生成本地密钥对**：本地生成专属 `ed25519` SSH 密钥对；
3. **执行认领与凭据换取**：
   ```sh
   "$install_dir/homeagent-agent" claim \
     --server "$HOMEAGENT_SERVER" \
     --claim-token "$HOMEAGENT_CLAIM_TOKEN"
   ```
   *(底层通过 HTTP Header `Authorization: Bearer $HOMEAGENT_CLAIM_TOKEN` 发起认领请求)*；
4. **安全持久化 Device Token**：
   - 认领成功后，将服务端返回的 `device_id` 与 `device_token` 写入本地设备状态文件；
   - **文件路径与权限配置**：
     - **Linux**（系统级 daemon）：
       ```text
       路径: /var/lib/homeagent/device.json
       Owner: root:root
       权限模式: 0600 (仅 root 可读写)
       ```
     - **macOS**（系统级 daemon）：
       ```text
       路径: /Library/Application Support/HomeAgent/device.json
       Owner: root:wheel
       权限模式: 0600
       ```
5. **服务自启注册**：注册并启动系统服务（`systemd` / `launchd` / `init.d`），守护进程启动时直接从本地 `device.json` 读取凭据连接服务端，无需常驻管理员密码或 Claim Token。

### 4.2 Windows PowerShell 接入 (`scripts/install.ps1`)

```powershell
$env:HOMEAGENT_SERVER="https://<server-ip>:8080"
$env:HOMEAGENT_CLAIM_TOKEN="claim_7b9d31f98e2a4f0c99a07d6e5c4b3a21"
irm https://<server-ip>:8080/install.ps1 | iex
```

- **凭证存储路径**：`$env:ProgramData\HomeAgent\device.json`
- **ACL 安全控制**：利用 Windows ACL 移除 Users 继承权限，仅授予 `SYSTEM`、`Administrators` 以及 `HomeAgent Service` 服务账户读写权限。

### 4.3 凭据日志脱敏要求

在客户端与服务端的任何环节，必须确保 Token 安全：
- 安装脚本执行过程严禁在 `set -x` 或标准输出中回显完整 Token；
- 客户端日志、系统运行日志（`syslog` / `journald`）禁止输出完整 `Device Token` 或 `Claim Token`；
- 服务端 HTTP Access Log、Panic 恢复栈及 Trace 中必须对 `Authorization` Header 及 Cookie 进行脱敏过滤（如输出 `Bearer claim_7b9d...[REDACTED]`）。

## 5. Web 控制台（UI）交互改造

### 5.1 登录页与全局 401 状态机
- **未登录与失效拦截**：前端挂载全局 HTTP 响应拦截器，当收到任何 API 的 `401 Unauthorized` 响应或初始访问无有效会话时，自动跳转并呈现全屏**登录面板**。
- **登录交互**：
  - 输入管理员用户名与密码；
  - 提供「记住登录状态（7天）」复选框（勾选后服务端 Session 有效期 7 天，未勾选使用会话级 Cookie）；
  - 登录成功后直接刷新或无缝切回先前试图访问的页面；
  - **前端安全**：浏览器通过 HttpOnly Cookie 自动携带凭据，前端 JS 代码严禁在 `localStorage` 或 `sessionStorage` 中保存 Admin Token。
- **顶部状态栏**：右上角显示管理员用户名、会话状态与「退出登录」按钮。点击退出登录时调用 `POST /api/v1/auth/logout` 销毁服务端 Session 并清空 Cookie。

### 5.2 「快速接入向导（Onboarding）」升级
- **动态生成 Claim 凭据**：管理员进入接入页面时，前端自动调用 `POST /api/v1/enrollment-tokens` 生成一个 15 分钟有效的单次 Claim Token；
- **倒计时提示**：界面动态渲染 `凭据有效倒计时: 14分32秒`，到期后自动禁用一键复制并提供「重新生成凭据」按钮；
- **自适应一键复制**：单行命令中的 Token 自动填充为当前生成的 Claim Token，支持一键复制 POSIX 命令或 PowerShell 命令。

## 6. 公网安全与防护加固设计

### 6.1 管理员密码哈希与首次初始化（Bootstrap）
- **密码哈希算法**：管理员密码通过 `golang.org/x/crypto/bcrypt`（Cost = 12）计算哈希后存储在服务端持久层；
- **环境变量作为 Bootstrap 凭证**：
  - `HOMEAGENT_ADMIN_USERNAME`（默认 `admin`）与 `HOMEAGENT_ADMIN_PASSWORD` 仅作为**首次启动初始化凭据**；
  - **覆盖规则**：若持久化存储中已存在管理员记录，服务端后续重启时**绝对不得**使用环境变量自动覆盖已有密码；
  - 若未配置环境变量且数据库为空，首次访问 Web 控制台时强制弹出「初始化管理员密码」向导。

### 6.2 服务端 Token 哈希存储规范
- 服务端对三类 Token 统一仅保存 SHA-256 哈希：
  ```text
  Admin Session Token -> SHA-256 Hash
  Claim Token         -> SHA-256 Hash
  Device Token        -> SHA-256 Hash
  ```
- 即使持久化存储介质意外泄露，攻击者也无法直接还原有效凭证。

### 6.3 Claim Token 消耗原子化（Atomic Claim）
为防止高并发场景下两个请求同时使用 `max_uses=1` 的 Claim Token 产生“双花”竞争：
- 服务端提供不可分割的原子操作语义：
  ```go
  // ConsumeClaimToken 原子完成:
  // 1. 查找 Token Hash
  // 2. 校验 expires_at 未过期
  // 3. 校验 remaining_uses > 0
  // 4. 扣减 remaining_uses (remaining_uses--)
  func (m *EnrollmentManager) ConsumeClaimToken(rawToken string) (*ClaimInfo, error)
  ```
- **并发控制**：在单实例架构中采用 Go `sync.Mutex` 或底层 SQLite 事务保证原子扣减，无需引入外部分布式锁与 Redis，确保并发请求下最多仅有一个认领成功。

### 6.4 设备 ID 与设备硬件元数据解耦
- **服务端生成唯一 ID**：设备的唯一标识 `device_id` 必须由服务端统一生成（推荐使用 128-bit UUID v4 或 ULID），严禁直接使用客户端上报的 `hostname`、`MAC` 或 `IP` 作为设备主键；
- **元数据降级**：`hostname`、`os`、`arch`、`mac`、`addresses`、`ssh_user`、`ssh_port` 仅作为展示与通信用的设备元数据（Metadata）；
- **动态适应**：设备修改主机名、IP 漂移、网卡变更均不会改变已分配的 `device_id`，两台同名主机亦可正常并存注册。

### 6.5 资源级权限约束与 IDOR 防护
- 中间件 `auth.RequireDevice()` 在校验 Token 有效性的同时，必须严格对比 URL 路由中的目标资源 ID：
  ```text
  Device A Token -> 请求 /api/v1/devices/A/events -> 校验通过
  Device A Token -> 请求 /api/v1/devices/B/events -> 403 Forbidden
  Device A Token -> 请求 /api/v1/auth/login        -> 403 Forbidden
  ```
- 杜绝设备间水平越权（IDOR）与权限逃逸。

### 6.6 凭证即时撤销语义（Revocation）
- **Admin Session**：管理员调用 Logout 或 Session 过期时，服务端立即删除 Session Hash，旧 Cookie 即刻失效；
- **Claim Token**：到期（`expires_at`）、次数耗尽（`remaining_uses == 0`）或管理员在 Web 控制台点击删除时，立即失效；
- **Device Token**：管理员在控制台「删除设备」或「撤销设备授权」时，服务端立即注销对应 `Device Token Hash`，同时主动中断当前设备已建立的 SSE 连接，后续请求一律返回 `401 Unauthorized`。

### 6.7 防爆破与速率限制（Rate Limiting）
- 针对 `/api/v1/auth/login` 与 `/api/v1/devices/claim` 接口内置基于客户端 IP 的滑动窗口限流；
- 单 IP 连续登录失败 5 次，自动触发 15 分钟临时锁定并在日志中记录安全告警。

## 8. 向后兼容性与平滑迁移策略

### 8.1 `HOMEAGENT_JOIN_TOKEN` 降权与迁移机制

针对存量环境已配置的 `HOMEAGENT_JOIN_TOKEN`，系统采取**严格降权与平滑迁移**策略，坚决维护权限隔离：

1. **废弃并剥离管理权限**：
   - `HOMEAGENT_JOIN_TOKEN` 标记为 **Deprecated**；
   - **完全剥离其全局管理员权限**，严禁使用 `HOMEAGENT_JOIN_TOKEN` 访问任何 Web 控制台管理 API 或 `/api/v1/auth/*` 接口。
2. **仅作为存量设备迁移凭据**：
   - 存量旧设备在升级过渡阶段，允许使用 `HOMEAGENT_JOIN_TOKEN` 调用设备认领/凭据迁移端点；
   - 服务端校验通过后，为该旧设备换发独立的 `Device Token`；
   - 设备端将新 `Device Token` 持久化至本地，后续所有通信完全切换为专用 `Device Token`。
3. **新部署与未来版本演进**：
   - 新部署环境默认不再生成和推荐使用 `HOMEAGENT_JOIN_TOKEN`；
   - 在后续大版本迭代中将彻底移除 `HOMEAGENT_JOIN_TOKEN` 兼容逻辑。

## 9. 验收测试场景与测试矩阵 (Phase 5)

为确保新认证架构在公网环境下的安全性与稳定性，Phase 5 必须覆盖以下测试场景：

> 下列自动化场景已在认证、API、Daemon 和 UI 测试中落地。清单保留原始验收粒度；真实公网反向代理与浏览器链路仍待《个人公网服务端部署方案》验收，不因本地自动化通过而视为完成。

### 9.1 Claim Token 场景
- [ ] **单次有效测试**：`max_uses=1` 的 Token 首次认领成功，再次使用返回 `401/403`；
- [ ] **并发双花测试**：20 个并发请求同时使用同一个 `max_uses=1` 的 Claim Token 发起认领，**严格仅允许 1 个请求成功**，其余 19 个均失败；
- [ ] **TTL 过期测试**：超过有效期（如 15 分钟）的 Claim Token 无法完成认领；
- [ ] **手动作废测试**：管理员在后台 DELETE 凭证后，该 Claim Token 立即失效；
- [ ] **权限隔离测试**：携带 Claim Token 请求 Admin API 或 Device API 返回 `401/403 Forbidden`。

### 9.2 Admin Session 场景
- [ ] **密码验证测试**：正确用户名密码登录成功并获得 HttpOnly Cookie；错误密码返回认证失败；
- [ ] **Cookie 访问测试**：携带有效 Session Cookie 可正常调用管理 API；
- [ ] **登出销毁测试**：调用 `/api/v1/auth/logout` 后，服务端 Session Hash 立即删除，旧 Cookie 重放请求返回 `401 Unauthorized`；
- [ ] **过期失效测试**：Session 到期后自动拒绝访问并触发前端 401 登录跳转。

### 9.3 Device Token 与防 IDOR 场景
- [ ] **自身资源访问**：Device A 携带自身的 Device Token 能够正常建立 `/devices/A/events` SSE 连接；
- [ ] **跨设备越权拦截 (IDOR)**：Device A 携带自身 Token 请求 `/devices/B/events`，服务端**严格返回 403 Forbidden**；
- [ ] **权限越级拦截**：Device Token 请求管理员 API 或认领凭据生成接口返回 `403 Forbidden`；
- [ ] **设备注销即时生效**：管理员在后台删除设备 A 后，服务端即时切断设备 A 的活跃 SSE 连接，设备 A 后续请求均返回 `401 Unauthorized`。

### 9.4 设备身份与元数据解耦场景
- [ ] **主机名无关性**：客户端修改 `hostname` 并上报，服务端 `device_id` 保持不变，设备凭据依然有效；
- [ ] **IP 漂移无关性**：客户端网络 IP 发生变化，心跳上报更新元数据，`device_id` 保持不变；
- [ ] **同名设备注册**：两台具有相同 `hostname`（如两台均名为 `ubuntu-server`）的主机分别完成认领，服务端分配两个完全不同的独立 `device_id`，互不干扰。

### 9.5 凭据泄露与脱敏审计
- [ ] **日志脱敏验证**：全面检索服务端应用日志、HTTP 访问日志、Trace、客户端安装日志，确认无任何完整明文 Token（Session Token、Claim Token、Device Token）输出；
- [ ] **前端存储审计**：登录 Web 控制台并完成各项操作，检查浏览器 `localStorage` 与 `sessionStorage`，确认无任何 Admin Token 残留。

### 9.6 兼容性与迁移场景
- [ ] **旧 Token 降权验证**：使用 `HOMEAGENT_JOIN_TOKEN` 请求 Admin API 返回 `401/403 Forbidden`；
- [ ] **旧设备平滑迁移**：存量设备使用 `HOMEAGENT_JOIN_TOKEN` 成功换取独立 `Device Token` 并无缝切换通信。
