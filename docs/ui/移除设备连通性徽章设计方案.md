## 2. 背景与问题

设备卡片头部当前并列展示三个状态：

1. 综合健康状态：`HEALTHY`、`DEGRADED`、`OFFLINE` 或 `UNKNOWN`；
2. 控制面连接状态：`在线` 或 `离线`；
3. SSH 密钥同步状态：`SYNCED`、`PENDING` 或 `ERROR`。

三个状态具有不同的数据来源和业务语义，但在设备正常时通常同时呈现为正向徽标。连接态标签与综合健康状态在视觉上处于同一层级，造成重复强调，增加卡片头部噪声，并挤占设备名称和异常状态的可用空间。

综合健康状态已负责表达设备的整体可用性，其中 `OFFLINE` 专用于设备活跃度丢失；控制面连接状态仍是瞬时 SSE 连接事实，不能替代综合健康状态。因此本任务精简连接态的可见呈现，不合并或删除底层状态模型。

## 3. 目标与非目标

### 3.1 目标

- 从每张设备卡片头部完全移除可见的“在线/离线”连接态标签（`.online-badge`、连接状态圆点及“在线/离线”文本）。
- 从设备列表顶部完全移除“离线”筛选按钮（`data-filter="offline"`）。
- 保留综合健康状态作为设备卡片的主要状态入口。
- 保留 SSH 密钥同步状态及其现有语义。
- 在不改变业务行为的前提下减少状态重复和卡片头部占用，释放设备名称和异常状态的展示空间。
- 桌面端与移动端采用一致的信息层级，并在真实浏览器下无重叠、无遮挡、无水平溢出。

### 3.2 非目标

- 不删除或修改 API DTO 的 `connected` 字段。
- 不修改 `healthy`、`degraded`、`offline`、`unknown` 健康状态枚举及其评估规则。
- 不修改唤醒、关机、升级或其他设备操作对连接态的判断。
- 不修改仪表盘设备摘要中的连接指示点。
- 不修改 GitHub 凭据页面的已连接/未连接状态。
- 不新增 `unknown` 状态筛选按钮（界面保持现有 `all`、`healthy`、`degraded`、`synced`、`pending` 组合）。
- 不改变任何服务端 API、公开路由、持久化结构或协议。

## 4. 现有契约与数据来源

| 状态 | 数据来源 | 当前用途 | 本任务处理 |
|---|---|---|---|
| 综合健康状态 | `device.health.status` | 卡片健康徽标、健康详情、健康筛选 | 保留 |
| 控制面连接状态 | `device.connected`；缺失时回退到 `updated_at` 时效判断 | 卡片连接标签、离线筛选、设备操作判断、摘要指示点 | 移除卡片连接标签及列表离线筛选入口，保留其他用途 |
| SSH 密钥同步状态 | `device.sync_status` | 卡片同步徽标、同步筛选与同步结果 | 保留 |

`isDeviceOnline(d)` 仍是视图层统一连接态适配函数。实现不得将 `connected` 直接透传为综合健康状态，也不得以移除标签和筛选入口为由删除该函数。

## 5. 设计决策

### 5.1 卡片头部状态层级与布局

设备卡片头部的状态区域仅保留：

1. 综合健康状态按钮（`.btn-view-health` / `.health-badge`）；
2. SSH 密钥同步状态徽标（`.header-badges .status-badge`，`title="SSH 密钥同步状态"`）。

不再渲染 `.online-badge` 元素、连接状态圆点以及“在线/离线”文字。健康状态为 `OFFLINE` 时继续显示健康徽标，因为它表示综合评估结果，而不是被移除的瞬时连接标签。

卡片头部移除连接态标签后，释放的水平空间优先保障设备名称（`.device-hostname`）展示，在桌面端、移动端及 200% 文本缩放下各元素间距自适应，无重叠、无文本裁剪被遮挡，卡片整体及页面无水平溢出。

### 5.2 底层连接态继续生效

移除标签后，下列行为保持不变：

- 唤醒按钮继续根据连接态调整样式、提示和行为；
- 关机入口继续根据连接态决定是否可用或如何提示；
- 仪表盘设备摘要的连接指示点继续反映瞬时连接事实；
- `connected` 缺失时继续使用 `updated_at` 回退判断。

### 5.3 筛选状态收敛与残留值规范化

当前 DOM（`internal/ui/static/index.html`）中的实际筛选按钮为：`all`（全部）、`healthy`（健康）、`degraded`（异常）、`offline`（离线）、`synced`（已同步）、`pending`（待同步），DOM 中并不存在 `online` 和 `unknown` 按钮。

本任务针对筛选区域进行如下收敛：

1. **DOM 入口清理**：从 `internal/ui/static/index.html` 移除 `data-filter="offline"` 按钮，仅保留 `all`、`healthy`、`degraded`、`synced`、`pending` 5 个有效筛选入口，不新增 `unknown` 按钮。
2. **过滤代码分支清理**：在 `internal/ui/static/js/devices/render.js` 中删除不可达的 `online`、`offline` 分支以及无 DOM 触发入口的 `unknown` 分支，保持支持的过滤分支与 DOM 筛选按钮完全一致。
3. **残留与非法状态规范化契约**：
   - 当 `state.currentFilter` 为已废弃的 `online`、`offline` 或不在有效集合（`['all', 'healthy', 'degraded', 'synced', 'pending']`）内的任意非法值时（例如热更新残留、测试注入或非法状态修改）：
     - **状态规范化**：显式将 `state.currentFilter` 改写为 `'all'`；
     - **UI 按钮同步**：移除所有筛选按钮的 `.active` 样式类，并将 `.active` 同步赋予 `data-filter="all"` 按钮；
     - **渲染行为**：按全量设备列表进行渲染，严禁显示空列表、抛出异常或维持不可见/不可取消的隐藏过滤条件。

移除筛选不影响设备卡片继续展示综合健康状态 `OFFLINE`，也不影响健康详情入口。用户仍可从卡片状态识别并查看综合离线原因，但不能再通过列表顶部单独筛出离线设备。

### 5.4 样式清理边界

仅当确认 `.online-badge`、`.online-badge.is-online` 和 `.online-badge.is-offline` 不再被其他界面引用时，删除这些专用于卡片标签的样式及相应移动端覆盖。名称相近但服务于操作按钮的 `.btn-wake-device.is-online`、`.btn-wake-device.is-offline` 和菜单状态类不属于清理范围。

## 6. 状态与失败路径

| 场景 | 预期呈现 | 必须保持的行为 |
|---|---|---|
| 健康且已连接 | `HEALTHY` 与同步状态；无“在线”标签 | 在线相关操作逻辑不变 |
| 健康但 SSE 瞬时断开 | 健康状态与同步状态；无“离线”标签 | 不出现瞬时连接态筛选入口 |
| 综合健康离线 | 显示健康状态 `OFFLINE`；无额外“离线”标签 | 健康详情仍可用，不提供离线筛选 |
| 健康降级但仍连接 | 显示 `DEGRADED` 与同步状态 | 健康原因可查看 |
| 健康状态缺失 | 不新增连接态替代健康徽标 | 连接态仍供操作逻辑使用 |
| `connected` 字段缺失 | 不显示连接标签 | 继续按 `updated_at` 执行兼容回退 |
| 当前筛选残留为 `online`、`offline` 或非法值 | 状态规范化为 `all`，激活“全部”按钮并显示全量设备 | 显式改写 `state.currentFilter = 'all'`，同步 UI active 状态，不维持用户无法取消的隐藏筛选 |

本任务不新增异步状态或持久化状态，因此不引入新的恢复、并发或重启语义。

## 7. 兼容性与依赖

- 公开 API：无变化。
- 前端状态模型：`currentFilter` 的有效取值收敛为 `all`、`healthy`、`degraded`、`synced`、`pending`；遇到其他残留值时强制规范化为 `all` 并同步 UI。
- DOM：移除卡片内非公开的 `.online-badge` 节点及列表顶部的离线筛选按钮（`data-filter="offline"`）；不得修改现有业务按钮、设备卡片根节点及健康详情入口标识（`.btn-view-health`、`#deviceHealthModal` 等）。
- CSS：删除确认无引用的专用连接标签样式，不进行无关格式化。
- 外部依赖：无新增依赖。
- 客户端：不修改 Agent 客户端，因此不升级客户端版本号。

## 9. 测试策略与验收证据

### 9.1 契约测试（单元与组件级）

测试必须由本文契约推导，至少覆盖：

1. 已连接设备卡片不包含 `.online-badge`，也不显示“在线”连接标签；
2. 未连接设备卡片不包含 `.online-badge`，也不显示“离线”连接标签；
3. 设备列表筛选区不包含 `data-filter="online"` 或 `data-filter="offline"`，仅保留 `all`、`healthy`、`degraded`、`synced`、`pending`；
4. 综合健康状态为 `offline` 时仍显示健康状态 `OFFLINE`，且健康详情入口仍可用；
5. 残留的 `currentFilter === "online"`、`"offline"` 或非法值在渲染时被规范化改写为 `state.currentFilter = 'all'`，DOM 同步激活 `data-filter="all"` 按钮，并展示全量设备列表，无隐藏过滤或异常；
6. `connected` 缺失时，在线判断仍按 `updated_at` 回退；
7. 唤醒与关机等依赖连接态的行为保持既有测试通过；
8. 渲染路径无未捕获异常。

其中第 1、2、3 项为“无多余副作用”的负例断言，防止标签或筛选入口通过其他分支重新出现；第 4 项防止误删综合健康离线状态；第 5 项防止移除入口后残留不可取消的脏筛选状态。
