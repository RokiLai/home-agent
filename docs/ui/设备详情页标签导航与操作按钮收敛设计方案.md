# 设备详情页标签导航与操作按钮收敛设计方案

## 1. 状态与范围

| 维度 | 当前状态 | 说明 |
|---|---|---|
| 设计状态 | 已通过审查 | 方案审查完成，用户已确认审查结论并授权实施 |
| 实施状态 | 实施完成 | 代码改造与测试同步完成，概览底部冗余按钮已完全移除 |
| 验收状态 | 验收通过 | 单元测试、契约测试、-race 全量回归与 Diff 覆盖率全部达标通过 |

- 任务标识：`consolidate-device-detail-tabs`
- 目标界面：控制台“设备详情页”（`#pageDeviceDetail`）
- 关联方案：《控制台信息架构与核心任务流设计方案》、《系统设置标签页打开方式与结构统一方案》
- 变更清单：`changes/consolidate-device-detail-tabs.yaml`

本方案只针对“设备详情页”内的**标签导航栏与操作按钮重复冗余问题**进行收敛。目标是：
1. 移除“运行概览”（overview）卡片底部的 `.detail-actions` 冗余按钮栏（`← 返回设备列表`、`查看健康诊断`、`SSH 与访问`、`网络详情`、`操作记录`、`设备设置`）。
2. 保留并确立顶部二级标签导航栏（`.detail-tab-nav`）为设备详情页唯一的分区导航机制。
3. 隔离 `app.js` 中全局 `.filter-pill` 对顶部标签的误触，保障 6 个分区的路由切换与浏览器前进/后退/刷新链路闭环。
4. 不变更设备管理数据模型、后端 API、设备基本设置与危险动作（关机、移除、公钥同步）的底层业务逻辑。

| `internal/ui/static/js/devices/render.js`（第 766-773 行） | 在 `renderDeviceDetailView` 的 overview 分支底部，渲染了包含 6 个按钮的容器：`<div class="detail-actions mt-3">`，内含 `← 返回设备列表` 及 5 个分区跳转链接。 | **严重冗余**：与顶部 Tab 及面包屑完全重叠；且其它 5 个子分区（health、ssh、network、commands、settings）均无此底部栏，仅概览独有，导致交互与视觉体验割裂。 |

## 3. 功能契约与交互设计

### 3.1 界面布局与容器层级

收敛后的设备详情页（`#pageDeviceDetail`）统一采用清晰的二级 Tab 容器结构：

```text
#pageDeviceDetail (.content-panel)
  ├── .panel-header
  │     ├── .detail-breadcrumb: [← 返回设备管理] (#/devices)
  │     ├── #deviceDetailTitle (设备别名/主机名)
  │     └── #deviceDetailBadge (健康状态标签)
  ├── .detail-tab-nav (常驻二级标签栏)
  │     ├── [运行概览] (data-section="overview")
  │     ├── [健康诊断] (data-section="health")
  │     ├── [SSH 与访问] (data-section="ssh")
  │     ├── [网络详情] (data-section="network")
  │     ├── [操作记录] (data-section="commands")
  │     └── [设备设置] (data-section="settings")
  └── #deviceDetailContainer (动态内容容器)
        └── .detail-section-overview
              └── .card: 设备概览信息网格 (移除原底部 .detail-actions)
```

1. **唯一返回入口**：点击面包屑 `&larr; 返回设备管理` 导航至 `#/devices`。
2. **唯一分区切换入口**：点击顶部 `.detail-tab-nav` 内的标签，触发对应分区导航。
3. **彻底移除冗余栏**：`.detail-section-overview` 容器内仅保留“设备概览”信息卡片，末尾不再渲染 `.detail-actions`。

### 3.2 路由与标签状态契约

| 分区标识 (`section`) | URL Hash 路径 | 激活标签文案 | 对应内容面板样式类 | 核心展示内容 |
|---|---|---|---|---|
| `overview`（默认） | `#/devices/<id>/overview` 或 `#/devices/<id>` | 运行概览 | `.detail-section-overview` | 主机名、设备 ID、物理 MAC、操作系统、IP 地址、SSH 用户、Agent 版本、健康状态 |
| `health` | `#/devices/<id>/health` | 健康诊断 | `.detail-section-health` | 健康原因、DDNS 域名绑定、CPU/内存指标与采样时间 |
| `ssh` | `#/devices/<id>/ssh` | SSH 与访问 | `.detail-section-ssh` | SSH 端口、公钥同步状态、快捷命令、立即同步公钥按钮、共享用户列表 |
| `network` | `#/devices/<id>/network` | 网络详情 | `.detail-section-network` | IPv4 地址列表、IPv6 地址列表、物理 MAC、DDNS 域名 |
| `commands` | `#/devices/<id>/commands` | 操作记录 | `.detail-section-commands` | 该受管设备的指令下发与执行历史列表 |
| `settings` | `#/devices/<id>/settings` | 设备设置 | `.detail-section-settings` | 备注名、所有权、远程关机及移除设备危险操作区域 |

- **路由归一化**：当 Hash 为 `#/devices/<id>`（省略 section）或为未知 section 时，`parseRoute` 统一归一化为 `section = 'overview'`。
- **Tab 激活态更新**：在 `renderDeviceDetailView` 中遍历 `.detail-tab`，当且仅当 `tab.dataset.section === section` 时添加 `active` 类，其余移除 `active` 类。

## 4. 状态流转与失败路径

| 场景 / 触发动作 | 系统行为与状态更新 | 异常与防护机制 |
|---|---|---|
| 用户在详情页点击顶部 Tab | 1. 触发 `navigateDeviceDetailSection(sec)`；<br>2. 更新 `window.location.hash`；<br>3. `hashchange` 捕获并调用 `renderDeviceDetailView`；<br>4. 对应 Tab 添加 `.active`，`#deviceDetailContainer` 渲染对应分区。 | 若设备 ID 不存在或 section 无效，直接拦截并返回 `false`，不产生脏 Hash。 |
| 用户点击浏览器“后退”或“前进”按钮 | 1. 触发 `hashchange`；<br>2. 重新解析路由参数并调用 `renderDeviceDetailView`；<br>3. 恢复历史分区展示并同步 Tab 选中态。 | 与原生历史记录无缝契合，无多余副作用。 |
| 用户直接输入或刷新 URL（带合法 ID 及分区） | 1. `setupRouter` 启动并解析 Hash；<br>2. 等待 `fetchDevices()` 返回设备事实数据；<br>3. 正确渲染指定分区。 | 设备尚未加载完成前，不显示空白或崩溃，等待数据返回后自动触发渲染。 |
| 用户直接输入不存在的设备 ID | 渲染 `#deviceDetailContainer` 为独立空状态提示“未找到该设备或暂无访问权限”，显示返回设备列表按钮。 | 标题设置为“设备不存在”，Badge 清空，防止界面白屏或脚本未捕获异常。 |

## 7. 审查记录与结论
