## 问题与现有证据

截图中，前两项“立即同步密钥”“客户端自升级”和“远程关闭设备”以彩色描边按钮呈现，图标与文字整体居中；“共享与授权管理”“转移设备所有权”“查看详情”“移除此设备”则按普通菜单项靠左排列。不同操作的图标与文字起点不一致，菜单整体显得松散。菜单靠近屏幕上沿，长菜单在较矮视口或文字放大时可能超出可见区域；是否已经发生实际裁切仍需浏览器验证。

静态代码显示：

1. `internal/ui/static/js/devices/render.js` 在 `.device-dropdown-menu` 内渲染七个操作项与两条分隔线。同步、升级、关机项同时带有 `.dropdown-item` 和独立操作按钮类。
2. `internal/ui/static/style.css` 的 `.dropdown-item` 使用 `display: flex`、`gap: 8px` 和左对齐文字；其后的 `.btn-sync-device`、`.btn-upgrade-device`、`.btn-shutdown-device` 使用 `justify-content: center`、独立背景与边框。相同元素上的后续规则会覆盖菜单项的部分布局属性。这能够解释截图中的居中和视觉风格不一致。
3. `.device-dropdown-menu` 以 `bottom: calc(100% + 8px)` 向上展开，未设置视口相关的最大高度或内部滚动。移动端规则只调整了最小宽度、最大宽度和菜单项触控高度。

上述样式冲突有代码直接证据；菜单是否被视口裁切，以及裁切发生的具体条件，仍是待验证问题，不能仅凭截图认定根因。

## 调整方案

### 视觉与对齐

- 将菜单内部所有操作项统一为左对齐布局，让图标占相同宽度，文字从同一列开始；图标与文字保持垂直居中。
- 仅在 `.device-dropdown-menu` 内覆盖同步、升级、关机按钮的通用布局规则，不改变这些类在菜单外的使用方式。
- 保留同步、升级、关机的语义色，但统一圆角、内边距、边框层级与项间距。危险操作仍以文字颜色和轻量背景区分，避免三个大块按钮破坏菜单的列表节奏。
- 保留现有操作顺序、分组、禁用状态、文案与事件行为；“远程关闭设备”和“移除此设备”仍有明确的视觉区分。

### 视口与可访问性

- 菜单宽度不得超过视口可用宽度；窄屏下维持不低于 44 CSS 像素的可点击高度。
- 为菜单设置相对于视口的最大高度，内容过多时在菜单内部纵向滚动，确保顶部和底部操作都可访问。
- 保持键盘焦点可见，禁用项不能被误认为可执行；菜单滚动不得造成页面级横向溢出。
- 若真实浏览器验证发现固定向上展开在特定位置仍无法完整显示，应再确定是否需要依据按钮位置切换展开方向。该行为变更需单独验证定位、滚动与焦点路径。

## 预计实施范围

本次实施按变更清单限定在下列文件；不修改菜单事件处理与公开接口。

| 文件 | 预计工作 |
|---|---|
| `internal/ui/static/style.css` | 收敛菜单项样式、对齐和视口约束。 |
| `internal/ui/testdata/browser-layout.test.mjs` | 使用真实 API 契约数据渲染设备卡，在浏览器中验证计算样式、菜单边界、窄屏触控与滚动。 |
| `internal/version/version.go` 与 `internal/version/version_test.go` | 服务端静态 UI 资源变更对应服务端版本从 `v0.6.51` 升至 `v0.6.52`；客户端版本不变。 |

不新增外部依赖，不变更公开接口或菜单操作语义。菜单仍在设备卡 `.device-actions > .dropdown-wrapper > .device-dropdown-menu` 内，七个 `.dropdown-item` 按现有顺序排列；每项的 `svg` 图标与 `span` 文本构成两列。所有项的图标左边缘与文字左边缘分别相差不超过 1 CSS 像素。窄屏操作项高度不低于 44 CSS 像素；菜单边界距视口至少 8 CSS 像素，内部滚动可到达最后一项，页面无横向溢出。

## 验证与验收

1. 在真实浏览器中打开设备列表，展开设备卡片菜单，分别检查桌面、窄屏和较矮视口；记录各项图标及文字的计算位置、菜单边界和滚动范围。
2. 验证同步、升级、共享、转移、关机、详情和移除入口均可点击；禁用、进行中及悬停/焦点状态保持正确。
3. 对窄屏菜单检查触控目标、无页面横向溢出、菜单首尾项均可见或可滚动到达。
4. 实施后执行变更范围检查、架构依赖检查、相关 UI 测试、全量回归和 Diff Coverage 检查。任一检查失败时，不标记实施完成。

## 实施与验证记录

- 修复前新增的真实浏览器测试在 `1280×800` 下明确失败：同步、升级、关机等菜单项的计算 `justify-content` 不是 `flex-start`，与截图中的对齐问题一致。
- 初次加上菜单高度限制后，`360×640` 下声明为 44px 的菜单项实际点击高度约 42.68px；按浏览器测量将菜单项最小 CSS 高度调整为 46px，并禁止 flex 压缩。
- 定向 `TestBrowserLayoutAndAccessibility` 已通过：验证 `1280×800`、`360×640`、`360×480` 加 200% 文字缩放时，七个操作项的图标和文字列分别对齐，菜单位于视口内，末项可滚动触达，焦点轮廓可见，离线设备关机入口仍禁用，且页面无横向溢出。
- 完整质量门禁 `go run ./cmd/homeagent-quality-gate --base HEAD --change changes/fix-device-actions-menu-design.yaml --diff-coverage 60` 已通过：变更范围、架构、前端语法、模块测试、全量 `-race` 回归与 Diff Coverage 均为通过。
