# 设备详情页轮询重绘与输入保护设计方案

## 1. 状态与范围

| 维度 | 当前状态 | 说明 |
|---|---|---|
| 设计状态 | 已通过审查 | 方案审查完成，用户已确认审查结论并授权实施 |
| 实施状态 | 实施完成 | 代码与测试改造已完成 |
| 验收状态 | 验收通过 | 单元测试、门禁与静态检查已验证通过 |

- 任务标识：`fix-device-detail-polling-input-interruption`
- 目标界面：控制台“设备详情页”（`#pageDeviceDetail`）及其健康诊断等子分区视图
- 关联方案：《控制台信息架构与核心任务流设计方案》、《设备详情页标签导航与操作按钮收敛设计方案》
- 变更清单：`changes/fix-device-detail-polling-input-interruption.yaml`

本方案只针对控制台**4 秒定时轮询无条件全量重写详情页 DOM，导致正在输入的表单（如 DDNS 域名输入框）内容与焦点丢失的问题**进行彻底修复。目标是：
1. 建立用户交互与活跃焦点保护机制：当用户在详情页输入框内打字或存在未提交内容时，轮询刷新绝不销毁破坏输入控件。
2. 建立详情数据变更差量比对（Diff Guard）：若 4 秒轮询获取的设备数据与上次渲染无实质变化，直接跳过全量重绘，杜绝无意义的 DOM 重排与屏幕闪烁。
3. 优化受管域名面板加载机制：消除模板拼接中的隐式 `setTimeout` 重复请求，避免列表周期性变更为“读取中…”。
4. 保证手动 Tab 切换、显式操作触发（如保存、同步、预检）及实质数据变动时的 UI 及时响应与闭环。

## 2. 现状证据与问题根因分析

### 2.1 完整执行链证据

| 步骤 | 代码位置 | 执行事实 | 产生后果 |
|---|---|---|---|
| 1. 定时触发 | `internal/ui/static/js/app.js:250` | `setInterval(..., 4000)` 每 4 秒无条件调用 `fetchDevices()`。 | 全局轮询启动。 |
| 2. 状态更新 | `internal/ui/static/js/devices/actions.js:96-98` | 异步请求 `/api/v1/devices` 完成，解析最新数据覆盖 `state.devices`。 | 内存状态更新。 |
| 3. 无条件重绘 | `internal/ui/static/js/devices/actions.js:113-115` | `if (state.currentPage === 'deviceDetail' && state.currentDetailDeviceId)` 分支**无条件**直接调用 `renderDeviceDetailView(...)`。 | 无论数据是否变动、无论用户是否在交互，每 4 秒必然触发详情页渲染。 |
| 4. DOM 全量替换 | `internal/ui/static/js/devices/render.js:576` | `container.innerHTML = ...` 直接将整个分区模板字符串赋给容器。 | 原 DOM 树被连根拔起销毁，所有绑定在其上的交互状态归零。 |
| 5. 焦点与输入丢失 | `internal/ui/static/js/devices/render.js:593` | `<input id="deviceDomainBindingInput">` 随容器被销毁重建。 | 用户键入的一半字符直接清空，输入光标丢失，输入框失去焦点。 |
| 6. 异步副作用 | `internal/ui/static/js/devices/render.js:597` | 模板内的内联 `<span style="display:none">${setTimeout(() => window.loadDeviceDomainBindings?.(device.id), 0)}</span>` 被重新解析。 | 每 4 秒重复发起域名列表 HTTP 查询，列表不断闪现“读取中…”。 |

### 2.2 根因结论

根因在于“**轮询调度层缺少变更守卫（Diff Guard）**”与“**渲染实现层采取了粗暴的全量 `innerHTML` 覆写且缺乏表单上下文保护**”。

## 3. 功能契约与技术设计

### 3.1 活跃输入与焦点保护契约（Active Input Protection）

在详情页渲染执行前，建立统一的输入状态检测与保护：

1. **检测活跃输入**：
   - 判定标准：当前活动元素 `document.activeElement` 属于输入控件（`INPUT` 或 `TEXTAREA`）且位于 `#deviceDetailContainer` 内部；或者容器内的受管输入框（如 `#deviceDomainBindingInput`）中已有用户输入的非空文本（`value.trim() !== ''`）。
2. **保护机制**：
   - **轮询触发场景（自动轮询）**：若检测到活跃输入，且数据仅为常规轮询拉取（非用户主动点击 Tab 或主动提交），则**完全跳过对包含输入框的分区 DOM 的重构**，仅更新页面头部标题与健康徽章（如 `#deviceDetailBadge`），确保正在输入的内容 100% 零干扰、零中断。
   - **必要更新场景（数据实质变动）**：若确实需要重绘，先捕获输入框的上下文快照：
     ```javascript
     const snapshot = {
       id: inputEl.id,
       value: inputEl.value,
       isFocused: document.activeElement === inputEl,
       selectionStart: inputEl.selectionStart,
       selectionEnd: inputEl.selectionEnd
     };
     ```
     在 DOM 更新完成后立即通过微任务无缝恢复其 `value`，并调用 `inputEl.focus()` 与 `setSelectionRange(start, end)` 恢复光标位置。

### 3.2 数据变更差量比对（Data Fingerprint Guard）

在 `internal/ui/static/js/devices/actions.js` 中引入针对当前详情设备的快照指纹机制：

1. **设备指纹字段集**：
   提取与界面呈现密切相关的核心属性：
   - `id`、`hostname`、`alias`、`os`、`arch`、`mac`、`agent_version`
   - `health.status`、`health.reasons`、`health.metrics`
   - `addresses`、`ssh_user`、`ssh_port`、`sync_status`、`applied_hash`、`ddns_domain`
2. **判定契约**：
   - 记录上一次成功渲染该设备分区时的指纹字符串 `lastRenderFingerprint`；
   - 4 秒轮询获取到新数据后计算 `currentFingerprint`；
   - 若 `currentFingerprint === lastRenderFingerprint` 且分区（`section`）未切换，则直接跳过 `renderDeviceDetailView` 调用。

### 3.3 域名绑定面板加载去重

1. 从模板 HTML 字符串中彻底移除内联的 `${setTimeout(() => window.loadDeviceDomainBindings?.(...), 0)}` 隐式调用；
2. 仅在首次渲染该分区（或明确通过预检、添加、接管操作）时，显式调用一次 `loadDeviceDomainBindings(deviceId)`；
3. 加载完成后保留当前面板状态，除非用户刷新或显式触发操作，否则不重置为“读取中…”。

## 4. 状态流转与失败路径

| 场景 / 触发条件 | 系统行为 | 异常与边界防护 |
|---|---|---|
| 用户正在 `#deviceDomainBindingInput` 打字（焦点在输入框中） | 4 秒轮询返回数据：检测到焦点位于输入框中，Diff Guard 与 Input Guard 生效，跳过全量 DOM 重绘。 | 用户输入过程完全流畅，字符不丢失，光标不跳动，焦点保持。 |
| 用户输入完毕但未点击提交（输入框有文本，焦点离开） | 4 秒轮询返回数据：检测到输入框内有非空文本，轮询刷新保护输入内容不被清空。 | 即使焦点短暂离开（如用户移动鼠标准备点击按钮），输入内容依然安然无恙。 |
| 用户点击顶部 Tab 切换（如从 health 切换至 overview） | 用户显式主动导航，不受轮询输入保护抑制，立即执行目标分区渲染并切换 active 状态。 | Tab 正常切换，路由正常流转。 |
| 用户点击“预检并添加”保存域名成功 | 保存完成后显式调用 `input.value = ''` 并刷新绑定列表。 | 成功后输入框正常清空，列表恢复最新状态。 |
| 轮询期间设备健康状态或核心指标发生实质变动 | 计算指纹发生改变，但输入框有未提交内容时，优先保护输入框数据，平滑更新健康 Badge 与运行指标，不重置输入框。 | 数据正确呈现最新值，输入不中断。 |

## 7. 审查记录与结论

- 审查事项 1：是否应单纯延长轮询时间？
  - **结论**：不应延长。4 秒轮询对于设备离线告警、命令执行收敛等是合理的实时监控节奏；必须从根本上解决“全量 DOM 覆写破坏表单”的实现缺陷，而不是靠放宽轮询掩盖问题。
- 审查事项 2：焦点保护与数据比对是否互斥？
  - **结论**：不互斥。二者为互补的双层防线：数据未变时不触发渲染（节省性能）；数据变动时保护输入不被冲掉（保障体验）。
