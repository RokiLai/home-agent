## 2. 背景与问题

控制台目前在设备健康详情弹窗（`#deviceHealthModal`）内提供了设备健康状态变动历史展示区（`#healthModalEventsTimeline`）。

当前前端实现直接渲染了后端原始英文枚举及技术规则代号：
1. **事件类型标签**：直接渲染全大写英文字符串（如 `OPENED`、`RESOLVED`、`CHANGED`），与控制台整体中文交互界面存在割裂感。
2. **变动原因标识**：直接渲染后端定义的蛇形技术代号（snake_case，如 `heartbeat_stale`、`memory_pressure`、`disk_space_low`、`ssh_key_drift` 等）。普通运维人员不易快速直观理解其背后所指示的具体健康隐患。
3. **视觉层次与辅助信息**：缺乏对技术标识（Code）与友好自然语言说明的区分，没有留存易读的辅助提示。

因此，需对该健康变动历史展示层进行中文文案适配，在保持后端协议向后兼容的前提下提升信息可读性与直观性。

## 3. 目标与非目标

### 3.1 目标

- 在前端展示层建立健康事件类型（`type`）与原因规则代号（`reason_code`）的规范中文文案映射字典。
- 将事件状态徽标转换为直观清晰的中文标签（如 `触发告警` / `异常产生`、`已恢复`、`状态变更`），并保持与既有徽标色彩体系（红/绿/黄）一致。
- 将原因规则代号转换为直观的中文业务语义（如 `心跳陈旧`、`设备离线`、`内存压力偏高`、`磁盘空间不足` 等）。
- 保留原始规则代号作为辅助元素（例如小字体辅助标签或悬停 `title` 属性），兼顾初级用户的直观易读与高级用户的精准技术排查。
- 完善边界与异常降级策略，确保当后端返回未定义的新枚举或自定义原因代码时能够安全兜底并清晰呈现，不发生前端白屏或渲染崩溃。
- 规范容器层级与对齐契约，确保在桌面端和移动端响应式布局下均无文本折叠破坏或溢出。

### 3.2 非目标

- 不修改后端 `GET /api/v1/devices/{id}/health/events` 接口契约及任何 API 数据结构。
- 不修改服务端持久化模型中的 `HealthEvent` 结构体字段与类型定义。
- 不修改系统健康规则评估器（`evaluator.go`）中的业务规则判定逻辑与现有代码。
- 不改变当前历史记录的拉取分页参数（`limit=10`）与查询周期。

## 5. 详细设计

### 5.1 事件类型（`type`）中文映射契约

| 事件类型 (`ev.type`) | 中文标签 | 徽标样式类 (`class`) | 语义说明 |
|---|---|---|---|
| `opened` | `异常产生` | `status-badge status-error` | 健康规则首次或再次进入 firing 异常状态 |
| `resolved` | `已恢复` | `status-badge status-synced` | 健康规则由 firing 恢复为正常状态 |
| `changed` | `状态变更` | `status-badge status-warning` | 异常规则的严重等级（Severity）发生升降变化 |
| 未知类型（兜底） | `${ev.type.toUpperCase()}` | `status-badge` | 保持原始大写文本作为兜底 |

### 5.2 原因规则代号（`reason_code`）中文映射契约

| 规则代号 (`reason_code`) | 中文标题 | 监控维度 | 辅助含义说明 |
|---|---|---|---|
| `device_offline` | 设备离线 | 活跃度 | 超过离线阈值未收到设备心跳上报 |
| `heartbeat_stale` | 心跳陈旧 | 活跃度 | 活跃上报延迟，正在确认连通性 |
| `device_never_seen` | 从未上报 | 活跃度 | 设备登记后尚未建立首次认证心跳 |
| `agent_version_outdated` | 客户端版本过旧 | 版本状态 | 客户端版本低于推荐或最低支持版本 |
| `agent_version_invalid` | 客户端版本非法 | 版本状态 | 上报的客户端版本号不符合语义化规范 |
| `ssh_sync_failed` | SSH 密钥同步失败 | 配置收敛 | 设备执行公钥配置或同步命令异常 |
| `ssh_key_drift` | SSH 密钥配置漂移 | 配置收敛 | 设备本地生效配置与控制面期望不一致 |
| `ddns_sync_failed` | DDNS 解析同步失败 | 网络与 DDNS | 向云解析服务商推送记录失败 |
| `ddns_no_valid_address` | 未检测到有效 IPv6 | 网络与 DDNS | 设备接口未分配或未发现公网 IPv6 地址 |
| `ddns_address_drift` | DDNS 解析记录漂移 | 网络与 DDNS | 域名解析指向与设备当前公网地址不符 |
| `ddns_prefix_stale` | IPv6 网络前缀陈旧 | 网络与 DDNS | 路由器分配的网络前缀已过租期 |
| `upgrade_failed` | 自升级执行失败 | 任务管理 | 客户端自升级脚本执行异常退出 |
| `upgrade_not_converged` | 自升级未收敛 | 任务管理 | 升级指令完成但上报版本未在预期时间内更新 |
| `disk_space_low` | 磁盘空间不足 | 运行资源 | 根目录或挂载盘可用空间低于安全阈值 |
| `memory_pressure` | 内存压力偏高 | 运行资源 | 可用内存比例低于告警警戒水位 |
| *其他未枚举代号* | 原始代号字符串 | 兜底 | 遇新拓展规则代码直接显示原始代号 |

### 5.3 容器与布局层级及对齐契约

在 `#healthModalEventsTimeline` 中，每个事件条目的 DOM 结构规范如下：

```html
<div class="health-event-item" style="display:flex;align-items:center;justify-content:space-between;padding:6px 8px;background:rgba(255,255,255,0.02);border-radius:4px;gap:8px;">
  <div style="display:flex;align-items:center;gap:6px;min-width:0;flex:1;">
    <span class="status-badge ${badgeClass}" style="font-size:0.65rem;flex-shrink:0;">${escapeHTML(typeLabel)}</span>
    <span style="font-weight:600;font-size:0.8rem;color:var(--text-primary);overflow:hidden;text-overflow:ellipsis;white-space:nowrap;" title="${escapeHTML(code)}">${escapeHTML(reasonLabel)}</span>
    <span class="font-mono text-muted" style="font-size:0.68rem;flex-shrink:0;opacity:0.75;">(${escapeHTML(code)})</span>
  </div>
  <span class="text-muted" style="font-size:0.72rem;flex-shrink:0;white-space:nowrap;">${formattedTime}</span>
</div>
```

**布局与对齐约束**：
1. 条目采用 `flex` 容器，横向两端对齐（`space-between`），右侧固定放置时间，左侧自适应伸缩并设置 `min-width:0`。
2. 徽标（Badge）设置 `flex-shrink:0`，防止在窄屏被压缩。
3. 中文标题具备超长省略属性（`text-overflow:ellipsis`），并附带 `title` 悬停提示。
4. 原始代码以弱化的小括号等宽字体紧随其后，保证技术定位凭据不丢失。

## 6. 状态与失败路径

1. **加载状态**：展示 `正在加载历史变动记录...`，保留原有加载指示。
2. **空记录状态**：当 `events` 为空时，展示统一提示 `暂无状态变动历史记录。`。
3. **接口异常路径**：
   - HTTP 状态码非 2xx：展示 `无法拉取历史记录`；
   - 网络超时或抛出异常：展示 `加载历史异常: ${错误信息}`。
4. **脏数据/未知代码路径**：
   - 当 `type` 为未知或非规范值时，格式化为原样大写，徽标保持默认样式；
   - 当 `reason_code` 未在字典中命中时，中文标题安全回退至原始 `reason_code` 字符串，且不会产生双重括号显示。

## 7. 兼容性与外部依赖

## 8. 验收条件与测试策略

### 8.1 验收条件

1. 打开任意具有健康历史事件的设备详情，健康变动历史中的徽标显示为 `异常产生`、`已恢复` 或 `状态变更`，不再呈现 `OPENED` / `RESOLVED` / `CHANGED`。
2. 常见的健康原因规则（如 `heartbeat_stale`、`device_offline`、`disk_space_low`、`memory_pressure`）呈现为清晰中文，且附带原始代号。
3. 空历史、接口异常、未知代号均能优雅降级展示，无未捕获的 JavaScript 运行时异常。
4. 移动端及桌面端布局在各种分辨率下无水平横向溢出、文字重叠或遮挡。

   - 执行已有的浏览器端及移动端适配测试套件（`npm test` / `node --test`），确认 DOM 树与样式渲染正常。
