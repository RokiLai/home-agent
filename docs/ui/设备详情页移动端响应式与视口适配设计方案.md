# 设备详情页移动端响应式与视口适配设计方案

## 1. 状态与范围

| 维度 | 当前状态 | 说明 |
|---|---|---|
| 设计状态 | 已通过审查 | 方案审查完成，用户已确认审查结论并授权实施 |
| 实施状态 | 实施完成 | 代码与测试改造已完成 |
| 验收状态 | 验收通过 | 单元测试、门禁与静态检查已验证通过 |

- 任务标识：`mobile-device-detail-responsive`
- 目标界面：控制台“设备详情页”（`#pageDeviceDetail`）及其子标签视图与顶层布局容器
- 关联方案：《控制台信息架构与核心任务流设计方案》、《设备详情页标签导航与操作按钮收敛设计方案》、《设备详情页轮询重绘与输入保护设计方案》
- 变更清单：`changes/mobile-device-detail-responsive.yaml`

本方案旨在解决控制台**在窄屏移动设备（如手机横竖屏、宽度 `<= 640px`）访问设备详情页时出现的布局挤占、内容溢出破损及触控体验不佳的问题**。具体改进目标包括：
1. **解决二级标签栏（Tab Bar）溢出**：消除硬编码内联样式，为 `.detail-tab-nav` 引入平滑横向滚动与不换行保护，防止最后标签（如“设备设置”）被挤出卡片边界。
2. **释放首屏视觉重心**：在移动端视口下访问设备详情页时，自动收起/隐藏全局统计指标卡片（`.stats-grid`），让用户首屏即可直观看到当前设备详情、健康徽章与核心指标，避免翻屏查找。
3. **优化危险区域与操作按钮触控排版**：针对设备设置分区的“远程关机”与“移除此设备”，在移动端从小屏并排自适应调整为上下堆叠并拉伸为通栏大按钮，触控高度符合 `>= 44px` 规范。
4. **提升小屏文字排版呼吸感**：完善设备标题、所属用户长 ID 及状态徽章的截断与换行控制，避免横向撑爆容器。

## 2. 现状证据与问题根因分析

### 2.1 完整执行链与布局证据

| 步骤 / 区域 | 代码位置 | 布局与样式现状 | 移动端缺陷后果 |
|---|---|---|---|
| 1. 全局指标卡片 | `internal/ui/static/index.html:155` 与 `style.css:2378` | `<section class="stats-grid">` 位于主内容区顶层，在 `<= 400px` 下设为 `grid-template-columns: 1fr;`。 | 4 个大卡片单列纵向堆叠，高度超过 320px，在手机上把详情页挤到一屏开外。 |
| 2. 详情标签导航 | `internal/ui/static/index.html:386` | 硬编码内联样式 `style="display: flex; gap: 8px; ..."`，未指定 `overflow-x`，未指定 `flex-shrink: 0`。 | 6 个标签按钮总宽度超过 420px，超出手机视口宽度；最右侧的“设备设置”按钮直接突兀地溢出在卡片之外。 |
| 3. 危险操作按钮 | `internal/ui/static/js/devices/render.js:752` | 硬编码内联样式 `style="display:flex; justify-content:space-between; align-items:center;"`。 | 左侧描述文字与右侧按钮在小屏下挤在一行，文字强行换行且按钮贴边，按钮有效点击区域偏小。 |
| 4. 路由状态标记 | `internal/ui/static/js/router.js:150` | `switchPage` 仅切换 `.page-view.active`，未在父级容器（如 `.admin-main` 或 `body`）同步当前页面名称属性。 | 纯 CSS 无法根据当前页面（如 `deviceDetail`）按需隐藏顶层非页面组件（如 `.stats-grid`）。 |

### 2.2 根因结论

根因在于**移动端媒体查询（Media Query）未覆盖设备详情页的新增组件**，且 HTML 模板中存在硬编码内联样式阻碍了响应式覆盖，加之顶层容器缺乏当前路由页面状态标识，导致移动端布局失真与空间浪费。

## 3. 功能契约与容器布局层级设计

### 3.1 容器与布局层级及对齐契约

```text
.admin-main [data-page="deviceDetail"]
│
├── .top-header (保留移动端汉堡菜单、页面标题、所有者 Badge、刷新与退出)
│
├── .stats-grid (契约：在 max-width: 640px 且当前处于 deviceDetail 时 display: none)
│
└── #pageDeviceDetail.page-view.active
    └── .content-panel
        ├── .panel-header
        │   ├── .panel-title-group
        │   │   ├── .detail-breadcrumb (← 返回设备管理)
        │   │   └── #deviceDetailTitle (设备名与主机名，长文本自适应折行或省略)
        │   └── #deviceDetailBadge (健康徽章)
        │
        ├── .detail-tab-nav (契约：横向平滑滚动容器，flex-wrap: nowrap, overflow-x: auto)
        │   ├── .filter-pill.detail-tab (运行概览，flex-shrink: 0)
        │   ├── .filter-pill.detail-tab (健康诊断，flex-shrink: 0)
        │   ├── .filter-pill.detail-tab (SSH 与访问，flex-shrink: 0)
        │   ├── .filter-pill.detail-tab (网络详情，flex-shrink: 0)
        │   ├── .filter-pill.detail-tab (操作记录，flex-shrink: 0)
        │   └── .filter-pill.detail-tab (设备设置，flex-shrink: 0)
        │
        └── #deviceDetailContainer
            └── 各分区面板及 .danger-zone-row (契约：移动端 flex-direction: column)
```

### 3.2 具体改造契约

1. **路由与父级属性绑定（`router.js`）**：
   - 在 `switchPage(pageName)` 中，为 `.admin-main` 元素同步设置 `data-page="${pageName}"` 属性；
   - 便于 CSS 精准控制不同页面在移动端的顶层组件显隐，不侵入其他业务逻辑。

2. **全局指标卡片按需隐藏（`style.css`）**：
   - 规则：在 `@media (max-width: 640px)` 媒体查询下：
     ```css
     .admin-main[data-page="deviceDetail"] .stats-grid {
       display: none;
     }
     ```
   - 桌面宽屏下不受影响，完整保留 4 列统计数据；手机端访问设备详情时，首屏立即聚焦设备信息。

3. **二级标签导航栏平滑横向滚动（`index.html` & `style.css`）**：
   - 将 `index.html` 中的内联样式剥离，统一由 CSS 类 `.detail-tab-nav` 声明：
     ```css
     .detail-tab-nav {
       display: flex;
       gap: 8px;
       margin: 12px 0 16px 0;
       border-bottom: 1px solid var(--border-color);
       padding-bottom: 10px;
       overflow-x: auto;
       white-space: nowrap;
       -webkit-overflow-scrolling: touch;
       scrollbar-width: none; /* Firefox */
     }
     .detail-tab-nav::-webkit-scrollbar {
       display: none; /* WebKit */
     }
     .detail-tab {
       flex-shrink: 0;
     }
     ```
   - 彻底解决最后一个按钮被挤出卡片的问题，允许用户在手机上自然滑动切换标签。

4. **危险操作面板触控响应式重构（`render.js` & `style.css`）**：
   - 提取内联样式为 `.danger-zone-row` 语义类；
   - 在 `@media (max-width: 640px)` 下：
     ```css
     .danger-zone-row {
       display: flex;
       justify-content: space-between;
       align-items: center;
       gap: 12px;
     }
     @media (max-width: 640px) {
       .danger-zone-row {
         flex-direction: column;
         align-items: stretch;
         gap: 10px;
       }
       .danger-zone-row .btn {
         width: 100%;
         min-height: 44px;
       }
     }
     ```
   - 手机端下，按钮变更为通栏大按钮，文字描述在上、操作按钮在下，操作更明确、触控更安全。

5. **长文本与面包屑排版防御（`style.css`）**：
   - 确保 `deviceDetailTitle` 在小屏下支持自适应换行，避免超长主机名破坏布局边界；
   - 设备设置中用户所有权 ID 等单行等宽文本增加 `overflow-wrap: anywhere;` 保护。

## 4. 状态流转与失败路径

| 场景 / 触发条件 | 预期行为 | 边界与容错处理 |
|---|---|---|
| 用户在手机（竖屏，宽 375px）进入设备管理并点击某设备进入详情 | 路由切换至 `#/devices/<id>/overview`，`data-page` 置为 `deviceDetail`；全局卡片被隐藏，首屏直达详情。 | 若用户旋转手机至横屏（宽 > 640px），全局卡片自适应恢复显示。 |
| 用户切换至“设备设置”标签 | 横向滚动列表中“设备设置”处于高亮激活状态，页面完整容纳无横向溢出。 | 选中的激活 Tab 样式高亮清晰可见。 |
| 用户在设备设置页查看电源与危险区域 | “远程关机”与“移除此设备”按钮通栏堆叠展示，各按钮高度不低于 44px。 | 按钮之间有 10px 间距，杜绝误触。 |
| 用户点击面包屑“← 返回设备管理” | 路由切换回 `#/devices`，`data-page` 变为 `devices`，全局统计卡片恢复可见。 | 无缝切回，状态完全还原。 |

## 7. 审查记录与结论

- 审查事项 1：是否直接在所有页面隐藏全局 stats-grid？
  - **结论**：不应全局隐藏。首页仪表盘与设备列表需要全局卡片展示宏观概览；仅在移动端访问二级详情页（`deviceDetail`）时按需隐藏，确保信息聚焦且不破坏其他页面体验。
- 审查事项 2：二级 Tab 栏是否采用折行（wrap）还是横向滚动（scroll）？
  - **结论**：采用移动端标准横向滚动（`overflow-x: auto; white-space: nowrap`）。若在手机上 6 个标签折行排列，会占据 3 行高度，继续压缩首屏内容空间；横向平滑滚动既紧凑又符合现代移动端交互习惯。
- **审查结论**：用户已确认方案，明确授权进入实施阶段。
