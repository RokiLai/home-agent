## 2. 背景与问题

控制台在完成多用户 RBAC 权限改造后，密码管理相关交互存在割裂与冗余：

1. **通用设置中遗留孤立卡片**：
   - 「系统设置 → 通用设置」最下方仍保留单管理员时期的「管理员密码修改」独立面板（`#settingsSecPassword`）。
   - 该面板强占了通用设置的大块版面，且固定命名为“管理员”，与多用户体系（包含多管理员、只读访客等角色）语义脱节。
2. **用户权限表格存在能力断层**：
   - 在「用户权限」（`#/settings/users`）表格中，所有者（Owner）可以为其他用户“重置密码”；
   - 但对于当前登录账号自身所在行，操作栏仅显示为灰色静态文本 `当前登录账号`，未提供修改自身密码的入口，导致用户产生“在用户管理页无法管理自身账号密码”的困惑。
3. **只读访客（Viewer）缺少改密入口**：
   - 根据 RBAC 规则，非 Owner 用户无权访问「用户权限」标签页；若直接从通用设置移除密码面板而未提供全局入口，普通用户将完全失去修改个人密码的途径。

---

## 3. 目标与非目标

### 3.1 目标

- **收敛通用设置面板**：移除通用设置底部的 `#settingsSecPassword` 静态卡片，使通用设置面板聚焦于网络解析、设备认领与凭据同步。
- **用户权限列表支持改密**：在用户权限表格的当前登录用户行增加「修改密码」操作按钮，点击弹出修改个人密码模态框。
- **全局个人控件支持改密**：在页面顶部导航栏的 `#userProfileWidget`（用户控件）中增加「修改密码」入口，保证所有角色（包括只读访客）在任意页面均可安全修改个人密码。
- **DOM 契约与测试完全兼容**：将修改密码表单重构成模态弹窗 `changePasswordModal`，严格保留现有表单及控件 ID，确保现有自动化测试与响应式测试零破坏。
- **双重密码逻辑严格区隔**：明确区分“个人改密（需原密码）”与“所有者重置他人密码（无需原密码）”两条独立业务流与接口。

### 3.2 非目标

- 不变动后端认证与密码校验接口（保持调用 `POST /api/v1/auth/password` 与 `POST /api/v1/users/{id}/password-reset`）。
- 不变更密码复杂度安全要求（维持最小 6 位字符）。
- 不修改 RBAC 角色模型与数据持久化逻辑。

## 4. 架构设计与交互契约

### 4.1 密码操作双轨契约

系统中两类密码操作在主体、凭据和底层接口上严格分离：

| 维度 | 修改个人密码 (Self Change) | 管理员重置他人密码 (Admin Reset) |
|---|---|---|
| **适用人群** | 所有已登录用户（Owner、Admin、Viewer） | 仅系统所有者 (Owner) |
| **操作对象** | 当前会话登录账号自身 | 用户列表中的其他用户 |
| **凭据要求** | 当前旧密码 + 新密码 + 确认新密码 | 仅新密码（直接强制重写） |
| **API 路径** | `POST /api/v1/auth/password` | `POST /api/v1/users/{id}/password-reset` |
| **交互载体** | 全局模态弹窗 `#changePasswordModal` | 独立模态弹窗 `#resetUserPasswordModal` |
| **成功反馈** | 提示“密码修改成功”，清空表单并自动关闭弹窗 | 提示“密码重置成功”，清空表单并自动关闭弹窗 |

## 5. 状态流转与失败路径

### 5.1 弹窗状态与表单重置

1. **打开弹窗 (`openChangePasswordModal`)**：
   - 清空 `#changePasswordAlert` 提示与错误样式；
   - 重置 `#changePasswordForm` 内部输入字段；
   - 移除 `#changePasswordModal` 的 `hidden` 类名；
   - 自动将焦点置于 `#oldPasswordInput`。
2. **关闭弹窗 (`closeChangePasswordModal`)**：
   - 为 `#changePasswordModal` 添加 `hidden` 类名；
   - 重置表单，恢复提交按钮 `#savePasswordBtn` 可用状态。

### 5.2 校验与失败路径

| 场景 | 触发时机 | 处理行为 | 页面反馈 |
|---|---|---|---|
| **旧密码或新密码未填写** | 点击提交 | 前端表单原生 `required` 拦截或 JS 校验拦截 | 弹窗内提示“请输入当前旧密码和新密码” |
| **新密码长度不足 6 位** | 点击提交 | 前端原生 `minlength="6"` 及 JS 校验拦截 | 弹窗内提示“新密码长度不能少于 6 位” |
| **两次新密码不一致** | 点击提交 | 前端 JS 对比 `newPass !== confirmPass` | 弹窗内提示“两次输入的新密码不一致，请检查” |
| **旧密码校验错误** | 接口返回 400 | 后端认证失败返回错误 JSON | 弹窗内展示后端提示“旧密码错误”或通用失败提示，按钮恢复可点击 |
| **网络异常 / 服务不可用** | 接口请求失败 | `try/catch` 捕获异常 | 弹窗内提示“网络异常，请重试”，按钮恢复可点击 |
| **成功修改** | 接口返回 200 | 成功回调处理 | 提示全局 Toast“密码修改成功”，清空表单并自动关闭弹窗 |
