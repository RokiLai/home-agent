# HomeAgent 服务端 Web 页面移动端适配方案

## 1. 文档状态与生命周期

| 维度 | 当前状态 | 说明 |
|---|---|---|
| **设计状态** | 已确认 | 设计审查通过并获用户授权实施 |
| **实施状态** | 实施中 | 正式进入多阶段开发与真实浏览器自动化验收 |
| **验收状态** | 待验收 | 实施完成后基于真实 Headless 浏览器与门禁脚本逐项验证 |

- 任务标识：`server-web-mobile-adaptation`（关联批量控制迁移任务 `relocate-batch-controls-to-devices`）
- 适用对象：HomeAgent Server 内嵌 Web 控制台
- 目标范围：登录遮罩、仪表盘、设备管理、快速接入、GitHub 凭据同步、操作历史、系统设置及全局弹窗
- 非目标：原生移动应用、服务端 API 改造、引入第三方生产构建依赖、桌面端信息架构重构

本文只定义移动端适配契约、布局边界与验收方法。设计审查通过并获得用户明确授权前不得开始实现。

## 2. 背景与现状

当前控制台采用 Go `embed` 托管原生 HTML、CSS 和 ES Modules，不依赖前端框架与第三方运行时构建链。控制台采用 SPA 单页架构，公开路由契约为 6 个受保护页面，未认证会话通过全局登录遮罩（Overlay）拦截，不设独立登录路由。

在历史探索和既有迭代中，代码库已沉淀了一批基础响应式规则与基线测试（存量基线）：
- `style.css` 已包含 `1100px`、`900px`、`640px` 和 `400px` 基础媒体查询；
- `index.html` 声明了基础 `viewport` 与抽屉 DOM 结构；
- `internal/ui/testdata/mobile-responsive.test.mjs` 已建立了初步的静态 CSS 语法与 DOM ID 存在性断言。

但现有基线仍存在以下未闭环问题（本次任务的增量范围）：
1. 顶部全局操作在窄屏同时呈现，按钮文案、用户信息和登出入口容易争抢空间，缺乏极限断点和 200% 文本缩放下的确定性折行降级契约。
2. 全网批量控制（全网同步、全网升级）仍在仪表盘首页，需迁移至设备管理页面并适配响应式网格。
3. 设备矩阵外层面板在窄屏下存在内边距嵌套（Card-in-Card），需实施统一的 16px 基准线与父容器扁平化。
4. 操作历史五列表格虽支持滚动，但需完善单 DOM 行卡片化及 `data-label` 无障碍树可感知契约。
5. 弹窗与表单的动态高度（`100dvh`/`100vh`）、独立滚动区及字号保护（$\ge 16\text{px}$）需系统性规范。
6. 测试套件此前缺少真实浏览器布局引擎下的像素级溢出、分状态激活触控几何尺寸与命中闭环、200% 文本缩放（覆盖登录遮罩与 6 大受保护路由）及无障碍树自动化验收证据。

## 3. 目标与成功标准

### 3.1 功能目标

- 360 CSS px 宽度起，所有核心页面与登录遮罩可完成主要任务，页面级（`body/html`）无横向滚动。
- 保持桌面端现有功能、6 大受保护路由、DOM 标识、API 请求和状态语义不变。
- 触控目标、导航、表单、弹窗、批量操作和危险操作在手机上清晰可用。
- 采用 `100dvh`（带 `100vh` 回退）、输入框字号保护（$\ge 16\text{px}$）与独立滚动容器等兼容措施，降低软键盘与动态视口带来的可用性影响。
- 支持安全区设备，统一 16px 页面基准线，避免底部按钮被系统手势区域覆盖。

### 3.2 量化验收标准

| 指标 | 验收要求 | 验证手段 |
|---|---|---|
| 最小支持视口 | 360 × 640 CSS px | 真实 Headless 浏览器（Chrome + CDP）自动化注入视口，断言 `document.documentElement.scrollWidth <= window.innerWidth`（无页面横向滚动） |
| 页面横向溢出 | 核心页面主体与遮罩无横向溢出；明确声明的代码块/Tab 等局部横向滚动容器除外 | 真实 Headless 浏览器遍历核心页面与遮罩计算真实 `scrollWidth` 与 `clientWidth` |
| 触控目标与命中 | 所有交互元素在所属激活状态下实际几何尺寸 $\ge 44 \times 44\text{px}$，且点击命中自身或子节点（`target === hit \|\| target.contains(hit)`），状态矩阵校验后“未验证目标清单”为空 | 真实 Headless 浏览器按状态激活矩阵逐态采集可见启用元素，调用 `getBoundingClientRect()` 测量尺寸并通过 `document.elementFromPoint(x, y)` 验证点击命中，末尾执行差集断言 |
| 200% 文本缩放适应 | 操作系统 200% 文本缩放模式下核心任务可完成，顶部栏正确折行，页面无破坏性溢出 | 真实 Headless 浏览器在 360px 视口下通过 CDP `Emulation.setEmulatedOSTextScale({ scale: 2 })` 注入 200% 文本缩放，执行未认证登录遮罩与 6 大路由全流程交互与溢出检查 |
| 正文字号与输入保护 | 表单输入框字号 $\ge 16\text{px}$（防 iOS 自动缩放）；主要正文 $\ge 14\text{px}$；辅助信息 $\ge 12\text{px}$ | 真实 Headless 浏览器通过 `window.getComputedStyle()` 校验计算样式 |
| 弹窗可见性与焦点 | 标题、关闭入口及主操作可见且顺序稳定；内容区独立滚动，支持 Focus Trap 与 `Escape` 关闭 | 真实 Headless 浏览器派发真实键盘事件，断言 Focus Trap 循环捕获、`Escape` 响应及焦点安全返回原触发按钮 |
| 运行时异常阻断 | 测试全流程无未捕获异常与控制台错误 | 监听 CDP `Runtime.consoleAPICalled`（`type === 'error'`）与 `Runtime.exceptionThrown`，任何异常直接阻断测试 |
| 表格卡片化可访问性 | 操作历史保留完整表格语义结构，无障碍树中每个单元格具备明确的字段名称关联 | 真实 Headless 浏览器通过 CDP `Accessibility.getFullAXTree` 抓取真实无障碍树，断言卡片化后字段可识别（阻断性断言） |

**验证边界与残余风险**：
- **必须自动化证明项**：各断点（360px、390px、412px、844px 横屏、768px、1280px）下的无横向溢出、状态激活矩阵下的 44px 触控几何尺寸与命中闭环（差集为 0）、顶部栏 200% 文本缩放折行降级与全流程主操作可交互性、抽屉/弹窗 Focus Trap 与焦点恢复、表格无障碍树字段关联及受控本地真实 API 契约数据渲染链路，必须通过真实 Headless 浏览器与 Node 测试套件（`go test -v ./internal/ui`）实现 100% 自动化验证。
- **真机残余风险**：移动设备原生软键盘弹出时的系统视口动态形变、异形屏物理刘海切角与底层系统手势，受自动化沙盒环境限制，属于已接受的真机残余风险，交付时显式记录并通过人工抽样验证。

## 4. 设计原则

1. **保持业务契约**：移动端只改变呈现和交互编排，不改变 API、路由体系、权限、状态枚举和批量结果聚合逻辑。
2. **内容优先**：先保证状态、失败原因和主要操作可见，再压缩辅助描述和装饰元素。
3. **局部重排而非整体缩放**：网格降列、表格转卡片、操作区换行，不使用页面缩放掩盖布局问题。
4. **渐进增强**：基础功能在不支持新 CSS 特性的浏览器中仍可用；安全区和动态视口使用带回退值的声明。
5. **危险操作不提速**：关机、解绑、批量升级等操作继续保留确认和独立结果反馈，不因移动端空间有限而合并确认步骤。
6. **单一 DOM 契约**：复用同一份语义 DOM，通过 CSS 重排；操作历史保持标准 `<table>` 结构，通过 `data-label` 暴露字段名，不维护第二套 DOM。
7. **容器扁平化与 16px 基准线**：移动端避免“卡片套卡片（Card-in-Card）”造成的多层内边距累加；所有顶层与下级卡片必须共享统一的 16px 页面基准线，父级容器在窄屏下自动扁平化。

## 5. 响应式分层

沿用现有断点体系，避免产生并行断点：

| 范围 | 布局定位 | 核心策略 |
|---|---|---|
| `> 1100px` | 宽桌面 | 四列统计、主次双栏、固定侧栏 |
| `901–1100px` | 窄桌面/横屏平板 | 统计两列，保留侧栏，压缩次要间距 |
| `641–900px` | 平板/大屏手机横屏 | 侧栏变抽屉，主次栏合并，操作区允许换行 |
| `401–640px` | 手机 | 单栏内容、紧凑卡片、全屏弹窗、表格卡片化呈现 |
| `<= 400px` | 小屏手机 | 统计单列，次要文案收敛，操作按钮纵向排列 |

断点判断以 CSS 宽度为准，不通过 User-Agent 区分设备。横竖屏切换后由 CSS 自动重排，不维护 JavaScript 设备状态。

## 6. 全局布局与导航

### 6.1 侧栏抽屉

- `<= 900px` 时侧栏保持离屏抽屉模式，打开后显示遮罩。
- 打开抽屉时锁定页面背景滚动；关闭后恢复原滚动位置。
- 打开后焦点进入侧栏，`Escape`、关闭按钮、点击遮罩或选择导航项均可关闭。
- 抽屉开关使用 `aria-expanded`，侧栏使用可感知名称；关闭后焦点返回开关。
- 刘海屏使用 `env(safe-area-inset-*)`，侧栏头部和底部状态不得进入不可触控区域。

### 6.2 顶部栏与批量操作

- **顶部栏空间优先级与确定性收缩契约**：
  - **左侧导航与标题组**：
    - 菜单开关按钮（`#sidebarToggleBtn`）具备固定 $\ge 44 \times 44\text{px}$ 触控保护尺寸；
    - 页面标题容器采用 `flex: 1 1 auto; min-width: 0;`；
    - 标题文本（`#currentPageTitle`）在小屏下采用 `text-overflow: ellipsis; overflow: hidden; white-space: nowrap;` 单行截断展示，并通过元素自带的 `title` 和 `aria-label` 完整保留无障碍可感知全名；
    - 辅助描述（`#currentPageDesc`）在 $\le 640\text{px}$ 自动收敛隐藏。
  - **右侧操作组（`#headerActions`）**：
    - 采用 `flex: 0 0 auto; display: flex; align-items: center; gap: 8px;`；
    - 刷新按钮（`#refreshBtn`）在小屏下保持为 44px 具名纯图标按钮（`aria-label="刷新数据"`）；
    - 用户名徽标（`#adminUsernameDisplay`）在 $\le 400\text{px}$ 自动隐藏；
    - 登出按钮（`#btnLogout`）在 $\le 400\text{px}$ 自动收敛为 44px 具名纯图标按钮（隐藏冗余文字文本，保留图标和 `aria-label="退出当前管理会话"`）。
  - **极限断点与 200% 文本缩放降级契约**：
    - 默认在常规字号下保持单行紧凑排列；
    - 当处于 $360\text{px}$ 极窄视口叠加 $200\%$ 文本缩放（`setEmulatedOSTextScale`）、或水平空间被大字号撑满无法单行容纳时，顶部栏允许 Flex 自动折行（`flex-wrap: wrap`）重排为紧凑双行布局（第一行：菜单开关 + 页面标题；第二行：右对齐的刷新与登出操作栏），严禁因强制单行导致页面级横向溢出或触控区挤压。
- **全网设备批量控制**：
  - 全网同步与全网升级作为设备批量运维操作，归位至设备管理页面（`#pageDevices`）的头部控制面板/操作区中：桌面端横向展示，移动端（`<= 640px`）自适应为双列等分网格（`1fr 1fr`），小屏（`<= 400px`）单列，避免在仪表盘概览首页误触，并与设备矩阵的管理操作形成天然协同。
- **顶部栏滚动与吸顶契约**：
  - 顶部栏保持非吸顶，避免引入未经验证的动态工具栏遮挡问题。

### 6.3 全局反馈

- Toast 位于安全区内，手机端左右至少保留 16px，长文本可换行。
- 加载、成功、部分成功和失败继续使用既有状态来源；批量操作不得因请求已受理而显示整体成功。
- 网络失败、会话过期和 SSE 断线提示不得遮挡主要操作，并应可由读屏软件感知。

### 6.4 容器层级与 16px 边距对齐契约

- **统一页面边距 Token**：移动端（`<= 640px`）统一定义基准变量 `--page-padding-inline: 16px;`。
- **安全区计算公式**：
  - 左侧边距：`padding-left: calc(var(--page-padding-inline) + env(safe-area-inset-left, 0px));`
  - 右侧边距：`padding-right: calc(var(--page-padding-inline) + env(safe-area-inset-right, 0px));`
- **移动端容器扁平化（Anti-Nesting）**：当通用面板容器（如 `.content-panel`）内部直接包含独立子卡片（如 `.device-card`）时，父面板在 `<= 640px` 下必须降级为无背景、无边框、无内边距的透明布局流（`background: transparent; border: none; padding: 0;`），子卡片直接平铺并与页面顶部控制栏、统计卡片和搜索筛选栏的外边缘严格对齐 16px 基准线。

## 7. 页面与遮罩级适配

### 7.1 登录遮罩（Overlay）

- 登录界面采用全局模态遮罩（`#loginOverlay` / `.login-overlay`），不维护独立 `#/login` 路由。
- 未认证用户访问任意受保护路由时显示登录遮罩；认证成功后遮罩隐藏，原目标路由无缝呈现。
- 登录卡片宽度为视口宽度减安全边距，最大宽度保持现有桌面约束。
- 输入框使用至少 16px 字号，避免 iOS 聚焦自动缩放。
- 使用 `100dvh`，并提供 `100vh` 回退；外层容器设置 `overflow-y: auto`，纵向空间不足时由外层平滑滚动，保证提交按钮可触达。

### 7.2 仪表盘（`#/dashboard`）

- `<= 1100px` 统计卡片两列，`<= 400px` 单列，数字和标签允许安全省略但完整值需可访问。
- 主内容与侧栏内容在 `<= 900px` 合并为单列，顺序为：设备状态、快速接入、GitHub 状态、活动日志。
- 安装命令区域允许代码横向局部滚动（`overflow-x: auto`），复制按钮固定在右上角，不随代码滚出视口。
- 活动日志使用紧凑行，长正文换行而非撑宽页面。

### 7.3 设备管理（`#/devices`）

- 全网批量控制面板（包含“全网同步”与“全网升级”）集成于设备管理页面头部；桌面端横向排列，移动端自适应为网格/纵向排列，与设备列表的搜索筛选区保持统一的 16px 对齐基准线。
- 手机端设备列表单列（`grid-template-columns: minmax(0, 1fr)`），卡片宽度不得依赖破坏性的固定最小宽度。
- 设备矩阵外层面板在手机端扁平化为透明容器，使批量操作栏、矩阵搜索/筛选栏与各个 `.device-card` 作为同级卡片展开。
- 主信息优先级为：设备名/别名、在线与健康状态、主要地址、最近心跳、任务状态；完整 Facts 可进入详情。
- 常用安全操作直接显示，低频操作进入卡片菜单；菜单不得超出视口。
- 关机、删除或其他危险操作保持二次确认。确认弹窗必须明确设备名和操作后果。
- 同一设备状态通过 SSE 更新时，卡片不得丢失当前菜单、焦点或用户正在输入的备注名。

### 7.4 快速接入（`#/onboarding`）

- 系统选择标签保持局部横向滚动（`overflow-x: auto`），并提供可见的选中状态。
- 安装命令容器采用“代码区域可滚动、复制按钮固定可达”的结构。
- Token 倒计时和刷新入口换行后仍在同一语义分组；过期状态必须替换可执行命令并阻止复制失效凭据。
- 说明步骤单列排列，命令和 Token 不写入日志或无意暴露到页面其他区域。

### 7.5 GitHub 凭据同步（`#/github`）

- 授权账户信息、同步统计和操作按钮在手机端纵向排列。
- 设备授权矩阵改为单列卡片；设备名、授权状态和开关保持同屏可理解。
- 设备流验证码保持可读但不得以固定超大字号造成溢出；复制和打开 GitHub 两个操作均可触控。
- 本任务只调整 GitHub 授权页面和弹窗的响应式呈现，不修改 Device Flow 请求、轮询、关闭或迟到响应行为；相关行为问题须另立任务完成协议验证后处理。

### 7.6 操作历史（`#/commands`，单 DOM 表格与无障碍树阻断契约）

- 桌面端保留语义表格。
- 手机端固定采用同一 DOM 表格的 CSS 行卡片化呈现（`display: block` 重排）。
- **阻断性无障碍契约**：保留标准 `<table>/<thead>/<tbody>/<tr>/<th>/<td>` 结构，每一个 `<td>` 必须声明 `data-label="字段名"`，且其文本必须与对应 `<th>` 严格一致；通过伪元素呈现字段名，并在真实 Headless 浏览器中通过无障碍树（AXTree）断言字段关联完整性。
- 不得增加第二套移动端记录 DOM、第二次请求或第二份业务状态。
- 局部横向滚动仅作为无 CSS/极端异常场景兜底，不作为主要移动交互。

### 7.7 系统设置（`#/settings`）

- 表单字段、说明和操作按钮单列排列。
- 保存与重置保持独立视觉层级，重置不得成为默认主操作。
- 密码修改表单在受限视口下支持 `overflow-y: auto` 完整滚动，字号保证 $\ge 16\text{px}$；错误定位到对应字段并保留用户已输入的非敏感内容。

### 7.8 健康详情与其他弹窗

- `<= 640px` 时弹窗固定为全屏面板：宽度和高度占满安全区域，高度使用 `100dvh` 约束并提供 `100vh` 回退；`641–900px` 保持居中弹窗。
- 标题栏和底部主操作固定在弹窗内，正文独立滚动（`overflow-y: auto`）；关闭按钮点击区域至少 44 × 44px。
- 健康指标网格在手机端改为单列。行内 `grid-template-columns` 必须迁移为可被媒体查询控制的命名类。
- 打开弹窗锁定背景滚动（`body.modal-open`）并保存触发元素；关闭后安全恢复焦点。
- 多弹窗不得叠加；已有弹窗打开时拒绝新的打开请求，保持当前弹窗与焦点不变，并显示“请先完成或关闭当前操作”的非阻塞提示。

## 8. 核心任务与验收对象

下列集合用于解释本文中的“核心页面与遮罩”“主要任务”“主操作”和“关键字段”，实现与测试不得自行缩减：

| 页面/组件 | 主要任务 | 主操作 | 必须可见或可访问的关键字段 |

| 登录遮罩 | 建立管理员会话 | 登录 | 用户名、密码、记住登录、错误原因 |
| 仪表盘 | 判断全局状态与系统健康度 | 刷新 | 设备总数、同步状态、待处理数、版本、活动日志 |
| 设备管理 | 查找设备、查看状态、执行单设备操作与全网批量控制 | 全网同步、全网升级、搜索、筛选、打开操作菜单 | 设备名/别名、在线、健康、地址、心跳、任务结果 |
| 快速接入 | 生成并复制有效安装命令 | 刷新凭据、复制命令 | 系统类型、有效期、过期状态、安装命令 |
| GitHub 同步 | 查看账户授权并管理设备同步 | 登录/解绑、设备授权开关 | 账户、授权状态、同步数量、设备级状态、轮询状态 |

## 9. 状态与失败路径

移动端适配不引入新的服务端状态枚举。视图层必须显式处理下列状态：

| 场景 | 页面行为 | 禁止行为 |
|---|---|---|
| 初始加载 | 显示稳定占位，不改变页面宽度 | 用空白页面代替状态 |
| 空数据 | 显示空状态和可执行下一步 | 显示为加载中 |
| 请求失败 | 保留已有内容并显示局部失败与重试 | 清空全部页面状态 |
| 会话过期 | 显示全局登录遮罩，登录成功后恢复原受保护路由 | 持续触发 401 Toast 风暴 |
| SSE 断线 | 显示连接状态，按既有策略重连 | 把旧数据标为实时成功 |
| 批量部分成功 | 由每个设备独立结果聚合并展示明细 | 根据任务创建成功显示整体成功 |
| 内容超长 | 换行、省略并提供完整可访问值 | 撑出页面或覆盖操作 |
| 视口切换 | CSS 重排并保留当前路由、输入和焦点语义 | 刷新页面或重建业务状态 |

“保留焦点语义”指：触发抽屉或弹窗的元素仍存在时，关闭后焦点返回该元素；元素因数据刷新消失时，焦点返回当前页面标题。“恢复可恢复的页面路由”指登录成功后回到会话过期前的上述 6 个受保护路由之一；路由不存在或不合法时回到 `#/dashboard`。

页面级失败验证至少覆盖下表；不适用的组合必须在测试中显式标注：

| 页面 | 触发条件 | 保留内容 | 可见反馈与用户动作 | 恢复结果 |
|---|---|---|---|---|
| 仪表盘/设备 | 初始请求失败或 SSE 断线 | 已成功加载的数据 | 局部错误或连接状态；允许刷新/自动重连 | 成功后原位更新，不重置路由 |
| 快速接入 | Token 请求失败或过期 | 非敏感说明 | 显示失败/过期；禁用复制，允许刷新 | 新 Token 成功后恢复命令和倒计时 |
| GitHub | HomeAgent 状态接口失败 | 最近一次明确状态 | 保持现有错误呈现与操作入口，不新增 Device Flow 行为 | 恢复后按现有逻辑渲染；若需修改轮询、关闭或迟到响应行为则停止本任务并另立变更 |
| 操作历史 | 列表请求失败 | 既有记录 | 表格内错误和重试 | 保持排序并原位替换 |
| 系统设置 | 校验或保存失败 | 用户输入 | 字段级/表单级错误；允许修正重试 | 成功后显示确认且不重复提交 |
| 全局 | 401 会话过期 | 当前合法路由标识 | 弹出登录遮罩 | 登录成功恢复原路由 |
| 批量操作 | 部分目标失败 | 每个目标结果 | 显示成功/失败数量和失败明细 | 后续刷新仍以服务端独立状态为准 |

## 10. 可访问性与触控

- 所有只含图标的按钮提供准确的可访问名称（`aria-label`），不能只依赖 `title`。
- 使用 `:focus-visible` 提供清晰焦点；抽屉、菜单和弹窗管理焦点进入、循环与返回。
- 状态不能只依靠颜色表达，必须有文本或图标语义。
- hover 只作为增强，任何功能不得要求悬停才能发现或执行。
- 支持 `prefers-reduced-motion: reduce`，关闭非必要位移和淡入动画。
- 操作历史严格绑定 `data-label`，通过真实浏览器无障碍树验证字段可识别性。
- 顶部栏支持 200% 文本缩放折行降级，标题单行截断时保留完整 `aria-label` 与 `title`。

## 11. 技术实现与进程治理边界

### 11.1 允许的实现方式

- 在 `internal/ui/static/style.css` 中整理现有媒体查询并补充响应式类与 16px 基准线。
- 在 `index.html` 中移除阻碍响应式接管的行内布局样式，补充语义属性、`data-label` 和必要容器。
- 在现有 ES Modules 中增加抽屉、菜单、弹窗焦点与滚动锁定等纯交互行为。
- 在 `internal/ui/testdata/` 编写测试脚本：
  1. `browser-layout.test.mjs`：基于 Node 原生标准库连接 Chrome Headless (CDP) 驱动真实浏览器进行布局、尺寸、命中、200% 缩放与无障碍树验收；
  2. `mobile-responsive.test.mjs`：基于 `node:test` 进行静态源码正则断言与 DOM 状态机测试。
- 允许通过环境变量 `CHROME_BIN` 指定浏览器路径（默认优先探测系统 Chrome），环境缺失且未配置时明确报错阻断，不引入第三方 npm 依赖。

### 11.2 Chrome 136+ 启动隔离与进程生命周期闭环

为了遵守 Chrome 136+ 远程调试安全规范并杜绝后台孤儿进程，测试执行必须严格遵循以下进程生命周期：
1. **隔离数据目录**：每次测试启动通过 `fs.mkdtemp` 创建独立的临时 `--user-data-dir`，严禁访问用户真实 Chrome Profile；
2. **确定性端口解析**：启动参数包含 `--headless=new --remote-debugging-port=0 --no-first-run --no-default-browser-check`，从进程 `stderr` 捕获 `DevTools listening on ws://127.0.0.1:(\d+)/...` 或从临时数据目录读取 `DevToolsActivePort` 解析随机端口；
3. **协议与实验性能力前置探针**：连接 CDP 后首先调用 `Browser.getVersion` 记录环境信息，并发送试探性 `Emulation.setEmulatedOSTextScale({ scale: 2 })` 调用。若协议不支持，测试立即阻断抛错，禁止静默跳过或降级为纯根字号模拟；
4. **安全受控 Server**：Go 测试在真实本地 TCP 端口（`httptest.NewServer`）启动，预置固定 Session 与基于公开 DTO 的 mock 数据，禁止向真实外部设备或 GitHub 发起网络副作用；
5. **清理与退出回收**：注册 `exit`、`SIGINT`、`SIGTERM` 及 `finally` 异常清理钩子，在测试退出时先通过 CDP `Browser.close` 退出浏览器，超时后通过 `process.kill()` 强行终止并等待进程退出事件，最后递归删除临时 `--user-data-dir`；
6. **并发隔离**：每个并发测试实例分配独立的临时数据目录与调试端口，互不干扰。

### 11.3 禁止事项

- 不引入 React、Vue、Tailwind、Bootstrap、Playwright、Puppeteer 或第三方生产构建/测试依赖包。
- 不修改现有 REST/SSE 公开契约，不新增 `#/login` 等非受控路由，不复制 API 请求逻辑。
- 不直接依赖其他模块的 `internal` 或 `infrastructure` 实现。
- 不以隐藏关键字段、删除操作或降低测试断言解决小屏布局问题。
- 不为移动端维护独立业务状态或独立路由体系。

### 11.4 版本影响

该变更只修改 Server 内嵌 Web 控制台，不修改客户端，因此不得升级客户端版本号。本任务也不修改 Server 版本；版本升级留给独立发布任务。

## 12. 测试策略

测试先于实现，断言从本文契约推导。测试套件统一集成于 `go test -v ./internal/ui` 中，结合真实浏览器与 Node.js 原生运行器执行。

### 12.1 真实 Headless 浏览器自动化验收（重点验证 CSS 布局与交互路径）

由 Go 测试通过真实本地 TCP 端口启动 Server，启动 Google Chrome Headless，由 Node 测试脚本通过原生 WebSocket CDP 协议连接并执行以下阻断性验证：

1. **代表性视口矩阵验证**：
   | 视口 (CSS px) | 代表场景 | 核心断言 |
   |---|---|---|
   | 360 × 640 | 最小支持手机 | `document.documentElement.scrollWidth <= window.innerWidth`（无页面横向滚动），主要操作 `getBoundingClientRect() >= 44x44px` |
   | 390 × 844 | 常见 iPhone 纵屏 | 顶部栏紧凑排列，设备卡片单列 16px 等宽对齐 |
   | 412 × 915 | 常见 Android 纵屏 | 弹窗占满全屏，内容独立滚动，底部操作可见 |
   | 844 × 390 | 手机横屏 | 侧栏抽屉与主内容层级正确，无垂直挤压截断 |
   | 768 × 1024 | 平板纵屏 | 弹窗居中展示，统计卡片双列 |
   | 1280 × 800 | 桌面回归 | 侧栏常驻，批量操作面板与设备矩阵横向排布 |

2. **状态激活矩阵触控尺寸与命中闭环验证**：
   - 建立覆盖全交互状态的激活矩阵：
     1. **未认证状态**：登录遮罩（用户名/密码输入框、记住登录、登录按钮）；
     2. **6 个页面已登录状态**：各页面导航项、刷新、登出、快速接入复制与系统 Tab、系统设置保存、设备页全网批量控制与搜索筛选；
     3. **设备操作菜单展开状态**：单设备各操作项、危险操作（关机/删除）入口；
     4. **GitHub 条件状态**：已连接/未连接切换、设备授权开关；
     5. **5 大全局弹窗激活状态**：IP 列表弹窗、设备备注编辑弹窗、GitHub 验证码弹窗、健康详情弹窗、危险操作二次确认弹窗。
   - 在每个激活状态下，采集当前真实可见（`offsetParent !== null`、`checkVisibility() === true`、非 `display:none`、非 `visibility:hidden`）且启用的元素：
     - 断言渲染几何尺寸宽高 $\ge 44 \times 44\text{px}$；
     - 计算元素中心点坐标，通过 `hit = document.elementFromPoint(x, y)` 断言 `target === hit || target.contains(hit)`，验证未被遮挡；
     - 记录已验证元素至已测清单。
   - **差集阻断断言**：在状态矩阵全部遍历完成后，计算 `契约交互目标全集清单 − 已验证目标清单`，断言差集为空，彻底杜绝静默漏测。

3. **200% 文本缩放逐流程交互验证**：
   - 视口固定为 360 × 640 CSS px，通过 CDP 官方指令 `Emulation.setEmulatedOSTextScale({ scale: 2 })` 注入 200% 操作系统文本缩放；
   - 逐流程执行核心交互：
     - **未认证状态**：未认证访问 `#/dashboard`，验证登录遮罩全屏呈现、表单输入、记住登录与登录点击；
     - **仪表盘（`#/dashboard`）**：点击刷新，查看日志区域；
     - **设备管理（`#/devices`）**：点击全网同步/全网升级，展开设备操作菜单；
     - **快速接入（`#/onboarding`）**：切换系统 Tab 并点击复制命令；
     - **GitHub 同步（`#/github`）**：呈现授权状态、切换设备授权开关、打开 Device Flow 验证码弹窗并点击关闭按钮；
     - **操作历史（`#/commands`）**：浏览卡片化记录；
     - **系统设置（`#/settings`）**：滚动至密码表单并点击保存；
   - 断言：除允许局部横向滚动的代码块与 Tab 栏外，页面主体无横向溢出，上述所有主操作可见且 `target === hit || target.contains(hit)` 点击命中通过。

4. **抽屉与弹窗焦点及滚动锁定验证**：
   - 派发真实键盘 `Tab` 与 `Escape` 事件；
   - 验证 Focus Trap 循环捕获、`Escape` 键关闭、`body.modal-open` 滚动锁定及关闭后焦点安全返回原触发按钮。

5. **无障碍树（AXTree）可访问性验证**：

   - 断言操作历史表格在卡片化重排后，各数据单元格在无障碍树中仍具备对应表头的字段名称（Accessible Name / Name from label），视障读屏语义完整。

6. **运行时异常与控制台错误阻断**：
   - 监听 CDP `Runtime.consoleAPICalled` 与 `Runtime.exceptionThrown`；
   - 测试过程中产生任何 `error` 级别日志或未捕获 Promise / 运行时异常，直接阻断判定测试失败。

每一阶段均先补失败测试，再实现最小变更，不跨阶段顺手重构。

## 14. 兼容性与风险

| 风险 | 影响 | 控制措施 |
|---|---|---|
| CSS 规则顺序冲突 | 桌面端或旧页面回归 | 沿用既有断点体系，按组件限定作用域，执行真实浏览器自动化回归与断点规则校验 |
| 行内样式覆盖媒体查询 | 小屏规则失效 | 将布局型行内样式迁移为命名类并加真实浏览器计算样式检查 |
| 容器多层嵌套导致边距收缩 | 小屏下卡片过窄变形 | 实施容器扁平化（Anti-Nesting），统一 16px 页面基准线 |
| 表格卡片化读屏语义断裂 | 视障用户无法理解字段 | 绑定 `data-label`，并通过真实浏览器无障碍树（AXTree）阻断验证 |
| 移动端软键盘系统视口形变 | 弹窗或提交按钮被遮挡 | `100dvh` + `100vh` 回退，输入框 $\ge 16\text{px}$，容器独立滚动；系统级形变作为真机残余风险披露 |
| 抽屉或弹窗滚动锁泄漏 | 页面无法继续滚动 | 集中式打开/关闭清理，覆盖异常关闭和路由切换自动化测试 |
| 触控菜单误操作 | 远程关机、解绑等高风险动作 | 44px 目标、动作分组、二次确认、设备身份明确展示，真实浏览器点击命中验证 |
| 孤儿 Chrome 进程或数据残留 | 资源泄露或端口冲突 | 启动独立临时 `--user-data-dir`，注册退出清理钩子并显式等待进程回收 |

## 15. 设计审查结论

### 15.1 已明确

- 功能边界：只适配 Server 内嵌 Web 控制台，将全网批量控制收敛至设备管理页面，不改服务端公开协议、不新增 `#/login` 等非受控路由和客户端，不引入第三方 npm 生产构建依赖。
- 公开契约：现有 6 个受保护路由（`#/dashboard`、`#/devices`、`#/onboarding`、`#/github`、`#/commands`、`#/settings`）、登录遮罩（Overlay）、DOM 关键标识、REST/SSE、鉴权与状态语义保持兼容。
- 状态与失败路径：加载、空数据、请求失败、会话过期、SSE 断线、部分成功和视口切换均有确定性处理要求。
- 布局与对齐契约：固化 16px 页面基准线 Token 与安全区公式，明确父容器扁平化规则。
- 验收体系：以真实 Headless 浏览器（Chrome + CDP）为核心布局、几何尺寸、点击命中（差集为 0）、200% 文本缩放全流程及无障碍树的阻断验收工具；软键盘与物理刘海列为真机残余风险。
- 进程与安全治理：强制临时 `--user-data-dir`、CDP 前置探针、确定性端口解析、本地受控 Server、清理等待闭环与异常阻断收集。
- 测试方向：先测试后实现，包含关键反例和桌面 DOM/交互回归。

### 15.2 已确定的交互决策

1. 操作历史采用单 DOM 表格卡片化，通过真实浏览器无障碍树阻断断言，不采用双呈现。
2. 批量操作（全网同步/全网升级）归位至设备管理页面头部控制卡片并自适应网格。
3. 顶部栏在 360px 且 200% 文本缩放下自适应 Flex 折行降级，标题省略并保留可访问全名，刷新/登出采用具名图标。
4. 手机弹窗采用全屏面板（`100dvh`/`100vh`），平板保持居中弹窗。
5. 多弹窗冲突时拒绝新请求并显示非阻塞提示。

### 15.3 设计审查结论

- 本轮针对指出的 2 项阻断问题和 1 项建议进行了系统性修订（纠正登录为全局遮罩并固定 6 大受保护路由、建立分状态激活矩阵与触控差集为 0 校验、增加 CDP 实验性能力前置探针与版本阻断），已完成复审。
- 本设计方案已获得用户明确授权，正式进入多阶段实施与全量自动化验收。
