## 2. 背景与问题

当前控制台在“系统设置”的信息架构、侧边栏导航及标签页交互上存在割裂：

1. **侧边栏与设置页内入口职责重叠且形态割裂**：
   - 侧边栏导航区提供了“GitHub 凭据同步”（`#navGithub`）与“用户与权限管理”（`#navUsers`）两个独立条目。
   - 与此同时，“系统设置”顶部的标签导航栏中也提供了 `[用户权限]` 和 `[GitHub 集成]` 标签。
   - 这种设计破坏了 `docs/ui/控制台信息架构与核心任务流设计方案.md` 约定的“侧边栏收敛为四项核心一级导航（首页、设备、操作记录、系统设置），其余功能归入系统设置子分区”的原则。
2. **交互行为与打开方式不一致**：
   - “全部”、“通用与安全”、“版本与更新”、“IPv6 DDNS”、“关于系统” 5 项为页面内局部 Tab 切换。点击后留在 `#pageSettings`，顶部标签栏常驻显示，下方对应的内容面板局部显隐，URL 对应 `#/settings/*`。
   - 设置顶部的“用户权限”与“GitHub 集成”硬编码了 `onclick="location.hash = '#/users'"` 和 `onclick="location.hash = '#/github'"`，点击后触发整页跳转，路由脱离 `settings`，导致外层 `#pageSettings` 被整体隐藏，顶部标签导航栏瞬间消失，无法原路切回其他设置。
3. **“全部”视图缺失关键设置面板与路由默认值冲突**：
   - 由于“用户权限”与“GitHub 集成”的 DOM 容器独立于 `#pageSettings` 之外，点击“全部”标签时无法看到这两个关键面板。
   - `app.js` 当前在路由回调中执行 `switchSettingsSection(route.section || 'general')`，导致访问 `#/settings` 时错误回退至 `'general'`，无法展开“全部”面板。
4. **RBAC 权限边界未与设置页子分区深度整合**：
   - 现有多用户权限仅通过控制侧边栏 `#navUsers` 的隐藏来实现，尚未作用于设置页顶部的 `[用户权限]` 标签和分区容器。

## 3. 目标与非目标

### 3.1 目标

- **彻底收敛侧边栏导航**：
  - 从侧边栏移除“GitHub 凭据同步”（`#navGithub`）与“用户与权限管理”（`#navUsers`）两个入口；
  - 侧边栏一级导航严格保持为四项主导航：首页概览（`navDashboard`）、设备管理（`navDevices`）、操作记录（`navCommands`）、系统设置（`navSettings`）（以及接入向导 `navOnboarding`）。
- **统一仅从设置顶部进入**：
  - 用户权限管理与 GitHub 凭据同步仅允许通过系统设置页顶部的标签栏进入；
  - 所有 7 个设置标签项（全部、通用与安全、版本与更新、IPv6 DDNS、用户权限、GitHub 集成、关于系统）统一采用页面内 Tab 切换交互，点击时顶部标签栏常驻显示。
- **统一路由体系与向后兼容映射**：
  - 设置标签 URL 统一规范为 `#/settings/*`（如 `#/settings/users`、`#/settings/github`）；
  - 访问旧路由 `#/users` 和 `#/github` 时自动无缝映射并重定向至 `#/settings/users` 和 `#/settings/github`，侧边栏高亮“系统设置”。
- **RBAC 权限收敛至设置页 Tab**：
  - 设置页顶部“用户权限”Tab（`#settingsTabUsers`）仅对 `owner` 角色展示；对非 `owner` 用户隐藏此 Tab，并在未授权访问时安全回退至 `#/settings/general`。
- **容器结构收敛与卡片层级规范**：
  - 将用户管理与 GitHub 面板收敛移入 `#pageSettings` 的 `.settings-container` 内部，作为标准 `.settings-section`；
  - 消除双层 `.content-panel` 嵌套，保留关键历史 ID（`pageUsers`、`pageGithub`、`usersTableBody`、`githubCardBody` 等）。
- **路由分发逻辑闭环**：
  - 修复 `app.js` 中 `route.section || 'general'` 为 `route.section || 'all'`；
  - 清理 `settings.js` 中多余的 `hashchange` 监听，统一收口至 `router.js`。

### 3.2 非目标

- 不新增或修改任何后端 HTTP API、DTO 结构或认证逻辑。
- 不更改 GitHub 授权（Device Flow）及解绑流程的底层交互逻辑。
- 不更改用户创建、角色分配、会话管理等 RBAC 现有后端业务行为。
- 不更改密码修改、API 服务地址覆盖与 DDNS 配置的提交接口。

### 4.2 路由分发层证据 (`internal/ui/static/js/router.js` 与 `app.js`)

1. **`router.js`**：
   - `validSettingsSections` 集合已经定义为：`new Set(['all', 'general', 'version', 'network', 'users', 'github', 'about'])`；
   - 但在 `parseRoute` 中，`users` 和 `github` 被作为独立顶层 `page` 返回，直接触发整页切换。
2. **`app.js`**（第 216 行）：
   ```javascript
   } else if (page === 'settings' && route) {
     switchSettingsSection(route.section || 'general');
   }
   ```
   当访问 `#/settings` 时，`route.section` 为 `null`，导致回退至 `'general'` 而非 `'all'`。

### 4.3 RBAC 显隐控制证据 (`internal/ui/static/js/auth.js`)

在 `auth.js` 第 38-45 行：
```javascript

    navUsers.classList.remove('hidden');
```

## 5. 设计决策与技术规格

### 5.1 侧边栏导航收敛规范

1. **移除条目**：从 `index.html` 侧边栏中彻底移除 `#navGithub` 与 `#navUsers` 两个 `<a>` 标签。
2. **侧边栏结构**：保留四项主导航加一项接入向导：
   - 首页概览（`#navDashboard`）
   - 设备管理（`#navDevices`）
   - 操作记录（`#navCommands`）
   - 系统设置（`#navSettings`）
   - 快速接入向导（`#navOnboarding`）
3. 侧边栏不再提供任何通往 `#/github` 或 `#/users` 的直接链接。

### 5.2 设置页顶部标签导航规范

在 `index.html` 的 `.settings-tab-nav` 中，7 个标签统一定义为：
```html
<div class="detail-tab-nav settings-tab-nav" style="display: flex; gap: 8px; margin: 0 0 16px 0; border-bottom: 1px solid var(--border-color); padding-bottom: 10px; overflow-x: auto;">
  <button class="filter-pill settings-tab active" data-section="all" onclick="location.hash = '#/settings'">全部</button>
  <button class="filter-pill settings-tab" data-section="general" onclick="location.hash = '#/settings/general'">通用与安全</button>
  <button class="filter-pill settings-tab" data-section="version" onclick="location.hash = '#/settings/version'">版本与更新</button>
  <button class="filter-pill settings-tab" data-section="network" onclick="location.hash = '#/settings/network'">IPv6 DDNS</button>
  <button class="filter-pill settings-tab hidden" data-section="users" id="settingsTabUsers" onclick="location.hash = '#/settings/users'">用户权限</button>
  <button class="filter-pill settings-tab" data-section="github" id="settingsTabGithub" onclick="location.hash = '#/settings/github'">GitHub 集成</button>
  <button class="filter-pill settings-tab" data-section="about" onclick="location.hash = '#/settings/about'">关于系统</button>
</div>
```
- 全部按钮均指向 `#/settings/*`，杜绝整页跳出；
- 赋予用户权限 Tab 独立 ID `#settingsTabUsers`，默认添加 `hidden` 类，由 RBAC 逻辑统一受控。

### 5.3 容器与布局层级规范（消除卡片样式嵌套）

将内容迁入 `#pageSettings` 的 `.settings-container` 中，严格遵循单层 `.content-panel` 结构：

```
#pageSettings (.page-view)
 └── .settings-container
      ├── .settings-tab-nav (7 个 Tab 按钮)
      ├── #settingsSecGeneral (.content-panel .settings-section)
      ├── #settingsSecVersion (.content-panel .settings-section)
      ├── #settingsSecNetwork (.content-panel .settings-section)
      ├── #settingsSecUsers (.settings-section)                <-- 新增外层分区显隐容器
      │    └── #pageUsers (.content-panel)                    <-- 内部唯一单层卡片（保留历史 ID）
      │         ├── .panel-header (标题与新建用户按钮)
      │         └── .table-responsive (用户表格及操作)
      ├── #settingsSecGithub (.settings-section)               <-- 新增外层分区显隐容器
      │    └── #pageGithub (.github-page-container)           <-- 内部容器（保留历史 ID）
      │         ├── .content-panel (GitHub 认证状态卡片)
      │         └── .content-panel (设备 GitHub 授权矩阵卡片)
      ├── #settingsSecPassword (.content-panel .settings-section)
      └── #settingsSecAbout (.content-panel .settings-section)
```

- 移除原容器上的 `class="page-view"`，防止被 `router.js` 的整页切换逻辑隐藏；
- 完整保留所有内部关键 ID：`pageUsers`、`pageGithub`、`usersTableBody`、`githubCardBody`、`githubLoading`、`githubConnected`、`githubDisconnected`、`btnGithubLogin`、`btnGithubDisconnect`、`githubDeviceMatrix`。

### 5.4 路由解析与向后兼容契约

1. **`router.js` 映射**：
   - `#/settings` -> `{ page: 'settings', deviceId: null, section: 'all' }`；
   - `#/settings/<section>`（有效分区：`all`, `general`, `version`, `network`, `users`, `github`, `about`）-> `{ page: 'settings', deviceId: null, section: '<section>' }`；
   - 旧路由向后兼容：
     - `#/users` 自动解析为 `{ page: 'settings', deviceId: null, section: 'users' }`；
     - `#/github` 自动解析为 `{ page: 'settings', deviceId: null, section: 'github' }`；
   - `switchPage` 接收到 `users` 或 `github` 时统一纠偏至 `pageName = 'settings'`，激活侧边栏“系统设置”高亮。
2. **`app.js` 路由回调闭环**：
   - 修正设置页切换回调：
     ```javascript
     } else if (page === 'settings' && route) {
       switchSettingsSection(route.section || 'all');
     }
     ```
   - 确保访问 `#/settings` 或点击【全部】时展示全部设置分区。
3. **事件清理**：
   - 移除 `settings.js` 中多余的 `window.addEventListener('hashchange', ...)` 监听，避免双重触发。

### 5.5 RBAC 权限协同规范 (`auth.js`)

在 `updateRBACVisibility()` 中：
```javascript
const isOwner = state.currentUser && state.currentUser.role === 'owner';
const settingsTabUsers = document.getElementById('settingsTabUsers');
const settingsSecUsers = document.getElementById('settingsSecUsers');

if (settingsTabUsers) {
  if (isOwner) {
    settingsTabUsers.classList.remove('hidden');
  } else {
    settingsTabUsers.classList.add('hidden');
  }
}
```
- 若非 `owner` 用户强行访问 `#/settings/users` 或旧路由 `#/users`，`switchSettingsSection` 检查权限不满足时自动回退激活 `'general'` 分区，并弹出轻量权限提示。

### 5.6 数据按需加载与轮询联动

1. **按需拉取 (`switchSettingsSection`)**：
   - 激活 `version` 或 `all`：执行 `loadVersionStatus()`；
   - 激活 `network` 或 `all`：执行 `loadServerNetworkSettings()`；
   - 激活 `users` 或 `all`：若为 `owner`，执行 `fetchUsersList()`；
   - 激活 `github` 或 `all`：执行 `fetchGitHubStatus()`。
2. **后台轮询 (`app.js`)**：
   在 4 秒轮询中，仅当 `state.currentPage === 'settings'` 且当前分区处于 `users` 或 `all` 且当前用户为 `owner` 时执行 `fetchUsersList()`。

| 访问历史旧路由 `#/github` | 任意 | `settings` | `github` | 系统设置 | GitHub 集成 | 仅 `settingsSecGithub` | 自动映射，无需手动切页 |
| 访问非法子分区 `#/settings/invalid` | 任意 | `settings` | `general` (回退) | 系统设置 | 通用与安全 | 仅通用与密码面板 | 容错回退兜底 |
