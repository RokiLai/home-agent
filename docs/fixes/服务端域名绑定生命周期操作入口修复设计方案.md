## 2. 问题、责任与范围

用户在 Web“设置 → 网络”中的服务端域名绑定列表看到 `files.rokilai.online` 为 `disabled / waiting_report`，右侧却只有“禁用”按钮，没有删除入口。`internal/ui/static/js/settings.js` 的 `renderDomainBindingRows` 对所有绑定无条件渲染禁用；`internal/api/api.go` 已提供 `POST /api/v1/server/domain-bindings/{binding_id}/enable`、`POST .../disable` 与 `DELETE /api/v1/server/domain-bindings/{binding_id}`。设备详情页已有相同生命周期按钮和请求实现，可作为交互参照。

责任分类为服务端页面实现与测试遗漏：已有设计要求服务端列表展示绑定，并约定禁用、删除不自动删除 DNS，但没有明确服务端行操作状态矩阵。本文补齐契约，修改页面与测试，不调整后端接口、Cloudflare 发布器、Nginx 或 DNS。现有 `AGENTS.md` 已覆盖设计、测试和验收流程，无需修改。

## 3. 公开契约与状态矩阵

页面复用既有服务端接口和响应字段 `bindings`、`revision`、`binding_id`、`fqdn`、`config_state`、`runtime_state`；每条写请求使用当前绑定的 `revision` 作为 `expected_revision`。启用请求还需 `publisher_disabled_confirmed: true`。接口访问继续由现有 `instance.settings.manage` 权限控制。

| `config_state` | 行操作 | 执行结果 |
| --- | --- | --- |
| `observing` | 确认接管、删除 | 接管后重新加载；删除后列表不再展示 |
| `enabled` | 禁用、删除 | 按服务端实际状态重新加载 |
| `disabled` | 重新启用、删除 | 启用前确认旧发布者已停止；删除后列表不再展示 |
| `deleted` | 不展示 | 无操作 |

状态分支只依据 `config_state`，不依据 `runtime_state`；`waiting_report` 与 `failed` 等运行状态仍作为原样文本展示。删除调用既有 `DELETE` 接口，只把绑定变成墓碑并释放 FQDN，不删除 Cloudflare AAAA，也不修改 Nginx 端口映射。禁用已禁用的绑定不应继续显示为可点击动作。

## 4. 界面与失败路径

页面使用现有 `serverDomainBindings` 容器及 `serverDomainBindingList` 列表；每行维持 `detail-row`，左侧 FQDN 与状态，右侧 `detail-actions` 操作组。所有操作用可聚焦的文字按钮，删除使用现有危险按钮样式。现有 `style.css` 的 `.detail-row` 为无换行 flex 布局，且没有 `.detail-actions` 规则；因此须增加仅作用于域名绑定列表的窄屏换行与操作组间距规则，避免长 FQDN 和双按钮产生横向溢出。

启用、禁用、删除均先弹出明确确认；取消时零写请求。启用说明旧发布者须停止管理该域名；禁用和删除均说明不会删除 Cloudflare AAAA，删除还提示同名域名可重新绑定。成功后重新获取服务端列表，依据真实响应更新状态和控制面 revision，不本地推测结果。`401/403/404/409` 与网络或 `5xx` 均提示失败、不误报成功；`404/409` 后重新加载列表以消除过期 revision。网络异常不应形成未捕获的事件异常。
