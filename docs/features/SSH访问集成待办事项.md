# 将 ssh-access 并入 HomeAgent：TODO

## 目标

将 `ssh-access` 已验证的 SSH 公钥安全同步能力吸收到 HomeAgent，作为实时控制平面的离线同步、安全写入和灾难恢复扩展。

合并后由 HomeAgent 统一管理设备身份、公钥、ACL、分发与同步状态，避免形成两个并行的授权来源。

## 核心约束

- [ ] HomeAgent Registry 是设备、公钥和 ACL 的唯一事实来源。
- [ ] `ssh-access/keys/*.pub` 只作为迁移、导入导出或灾难恢复格式，不作为第二个实时配置源。
- [ ] 每台设备的私钥始终只保存在设备本机；禁止上传至 Server、Git 或日志。
- [ ] `authorized_keys` 只能存在一个由 HomeAgent 负责的有效托管区。
- [ ] 保留用户在托管区之外手工维护的条目、注释和 SSH options。
- [ ] 所有写入必须先校验，再备份，并通过同文件系统内的原子替换完成。
- [ ] 协议、公开接口或数据结构如需变更，须先明确兼容策略，不得擅自破坏现有客户端。

## 阶段一：强化统一 SSH 同步引擎

- [ ] 梳理 `internal/sshsync` 的现有公开契约和调用方。
- [ ] 定义统一的 KeySet、同步计划和应用结果模型。
- [ ] 对公钥执行严格格式和算法校验。
- [ ] 显式拒绝 OpenSSH、PEM、PuTTY 等私钥内容或标记。
- [ ] 按“算法 + Base64 Key Body”识别重复公钥，不受注释差异影响。
- [ ] 检查托管区开始和结束标记的数量、顺序及完整性；异常时安全失败。
- [ ] 提供 dry-run，展示当前数量、目标数量、新增项、移除项及是否需要写入。
- [ ] 在目标文件所在目录创建临时文件，校验完成后原子替换。
- [ ] 写入前创建可恢复备份，并定义备份保留与清理策略。
- [ ] 正确设置 SSH 目录和 `authorized_keys` 权限或 Windows ACL。
- [ ] 保证重复应用同一 KeySet 完全幂等，不产生无意义备份或状态变化。
- [ ] 统一 SSE、SSH 兜底和本地命令使用的写入实现，避免多份规则漂移。

## 阶段二：迁移 ssh-access 存量配置

- [ ] 设计 `keys/*.pub` 导入命令，并默认以 dry-run 展示导入计划。
- [ ] 校验每个文件仅包含一个有效公钥，拒绝子目录、非公钥文件和重复 Key。
- [ ] 定义文件名、Key 注释与 HomeAgent Device ID 的映射规则。
- [ ] 对无法可靠映射的设备要求显式指定身份，禁止静默猜测。
- [ ] 识别旧托管标记：
  - `# >>> ssh-access managed begin >>>`
  - `# <<< ssh-access managed end <<<`
- [ ] 在一次原子操作中，将旧托管区迁移为 HomeAgent 托管区。
- [ ] 禁止迁移后同时保留两个有效托管区，避免已吊销公钥继续生效。
- [ ] 旧托管区损坏、重复或嵌套时停止迁移，并提示人工检查。
- [ ] 迁移前生成备份，迁移失败时保持原文件不变。
- [ ] 提供迁移结果报告，包括导入、跳过、冲突、移除和需人工处理的项目。

## 阶段三：离线同步与灾难恢复

- [ ] 定义可导出的离线 KeySet 格式，包含版本、内容哈希、生成时间和目标设备。
- [ ] 评估并设计 KeySet 签名与验证，防止离线文件被篡改或跨设备误用。
- [ ] 提供本地 `validate`、`plan`、`apply` 命令。
- [ ] 支持 Server 暂时不可用时，由设备本地安全应用已验证的 KeySet。
- [ ] 明确离线版本回退、过期和重放策略。
- [ ] 支持导出不含私钥的灾难恢复材料。
- [ ] 编写 Server 丢失、Agent 离线和 Registry 恢复操作手册。

## 安全专项

- [ ] 明确 HomeAgent 管理密钥与设备登录密钥的边界和威胁模型。
- [ ] 为 Server 管理私钥定义最小文件权限、备份、轮换和吊销流程。
- [ ] 审计首次 SSH Host Key 信任流程；不得把未经外部验证的 `ssh-keyscan` 结果描述为身份已验证。
- [ ] 防止路径穿越、符号链接替换、换行注入和命令参数注入。
- [ ] 对并发同步使用设备级锁，并验证写入期间不会丢失用户的非托管修改。
- [ ] 日志不得输出私钥、Join Token、完整认证凭据或其他 Secret。
- [ ] 对异常输入和外部协议假设至少增加一个安全失败的反例测试。

## 跨平台要求

- [ ] macOS：验证 OpenSSH 路径、权限、LaunchAgent 身份和本地网络权限行为。
- [ ] Linux：验证普通用户与服务账户的 Home、目录权限和原子替换。
- [ ] OpenWrt：验证 Dropbear 路径及 BusyBox 环境兼容性。
- [ ] Windows：验证普通用户 `authorized_keys`、管理员密钥文件及严格 ACL。
- [ ] 不支持的平台或环境必须在写入前明确失败，不得部分应用。

## 完成定义

- HomeAgent 是唯一授权控制面，旧 `ssh-access` 不再独立写入目标设备。
- 实时推送、SSH 兜底和离线应用共享同一套校验与原子写入语义。
- 存量托管区可安全迁移，失败时不会锁死 SSH 或残留隐式授权。
- 所有平台的用户非托管配置均保持不变。
- 测试和发布验收全部通过，并具备明确的恢复与回滚路径。
