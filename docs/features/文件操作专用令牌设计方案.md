# 文件操作专用令牌设计方案

## 一、阶段与授权状态

- 设计状态：修订契约经用户确认。
- 实施状态：服务端与管理界面本地实现完成；线上部署与快捷指令接入未执行。
- 验收状态：本地服务端、界面及质量门禁通过；生产与快捷指令接入待验收。
- 当前授权：用户已确认修订契约，允许按变更清单实施服务端及管理界面，不含部署和手机凭据保存。
- 实施范围已由 `changes/file-access-token-design.yaml` 明确允许路径；部署须在测试与本地 dev 提交完成后单独确认。

## 二、背景与代码证据

快捷指令目前要求每次输入网页登录会话令牌。目标是提供可撤销、权限受限的长期文件凭据，并让快捷指令保存后重复使用。

现有契约依据：

- `internal/api/api.go` 的文件路由使用 `requireSession`；保留期修改使用 `PermInstanceSettingsManage`。
- `internal/auth/auth.go` 的 `ExtractSessionToken` 优先读取 `homeagent_session` Cookie，并接受 `Bearer agt_sess_...`。
- `internal/auth/session.go` 的 `GetUser` 返回用户副本，账户状态与 `SessionVersion` 用于会话失效校验。
- `cmd/homeagent-server/main.go` 在数据目录装配 `auth.json` 与 `files` 服务。
- `internal/ui/static/index.html` 已有 `pageFiles`、`files-toolbar` 与 `filesTableBody`；文件逻辑位于 `internal/ui/static/js/files.js`。
- 原《临时文件中转站设计方案》约定所有有效会话共用文件空间。本方案保留该规则，令牌不引入个人文件隔离。

2026-10-10 对 `https://homeagent.rokilai.online/api/v1/files` 执行真实未认证 GET：直接返回 HTTP 401、JSON `error=unauthorized`、`message=Valid session required`，未发生重定向。用户报告现有快捷指令运行成功，但未提供逐分支验收证据，不能据此标记本能力通过。

## 三、功能边界与权限

每位有效登录用户可以创建、列出和撤销自己的专用令牌；不能查看或操作他人的令牌。令牌名称用于识别设备，不授予设备管理能力。默认有效期 365 天，可选 30、90、365 天及永久。永久仅免于时间到期，仍受撤销、账户状态和认证版本失效规则约束。

固定权限集合，不接受客户端自定义 scope：

| 方法与路由 | 专用令牌 |
| --- | --- |
| POST `/api/v1/files` | 允许上传 |
| GET `/api/v1/files` | 允许列表与容量查询 |
| GET `/api/v1/files/{id}/download` | 允许下载，沿用 Range 契约 |
| POST `/api/v1/files/{id}/links` | 允许生成现有限时下载链接 |
| 文件删除、链接列表及撤销、文件设置读写 | 禁止 |
| 设备、命令、用户、设置、令牌管理等其他接口 | 禁止 |

生成链接沿用现有有效期与文件生命周期限制。撤销专用令牌不撤销它已经生成的公共链接；界面和快捷指令配置说明必须明确这一点。公共链接的现有撤销入口仍只接受登录会话。

## 四、公开接口与凭据处理

新增接口只接受现有有效登录会话，专用令牌不能管理自己或创建新令牌：

| 接口 | 输入与输出 |
| --- | --- |
| POST `/api/v1/file-access-tokens` | JSON `name`、可选 `expires_in_days`；201 返回元数据及一次性 `token` |
| GET `/api/v1/file-access-tokens` | 200 返回 `tokens`，仅当前用户，按创建时间倒序、同时间按 id 倒序 |
| DELETE `/api/v1/file-access-tokens/{id}` | 204；当前用户重复撤销返回 204；不存在或他人 id 返回 404 |

元数据字段：`id`、`name`、`created_at`、`expires_at`、`revoked_at`、`status`、`scopes`。`status` 为 `active`、`expired`、`revoked`、`account_invalid`；最后一项表示账户或签发认证版本失效，优先级为撤销、账户失效、过期、有效。`scopes` 固定为 `files.upload`、`files.list`、`files.download`、`files.links.create`。列表不包含 token、哈希或用户认证版本。名称 trim 后为 1–64 个 Unicode 字符；有效期接受 30、90、365 或 -1（永久）；省略为 365，显式 0 或其他值返回 400。永久元数据增加 `permanent=true` 且 `expires_at=null`；限时记录 `permanent` 省略且到期时间保持原格式。每用户最多 20 个有效令牌，账户版本失效的记录不占限额；超过返回 409，非法输入返回 400。

明文格式 `agt_file_` 加 32 字节密码学随机值的无填充 base64url 编码；服务端仅保存 SHA-256 哈希。生成失败、持久化失败均不返回明文或成功响应。创建响应使用 `Cache-Control: no-store`，日志、审计、URL、异常信息及页面持久化存储不得包含明文。

文件入口只接受 `Authorization: Bearer agt_file_...`，不接受查询参数或 Cookie 中的专用令牌。API 入口先识别专用令牌请求：Header 携带专用前缀时不回退 Cookie；查询参数或 Cookie 携带专用前缀时明确拒绝，不能借助同时存在的普通会话绕过。四个白名单外的 API 一律拒绝专用令牌请求，包括同时携带有效会话的情况。普通会话认证保持兼容。非法或失效令牌返回 401；有效专用令牌访问白名单外接口返回 403；存储不可用返回 503。不扩大通用 `RequireAdmin` 或 RBAC 的凭据范围。

## 五、模块与持久化

新增独立业务模块 `internal/fileaccess`，拥有生成、哈希校验、用户归属、有效期与撤销规则。API 层负责路由、认证选择、Actor 映射；通过注入用户状态查询函数使用 `SessionManager.GetUser`，不得访问其他模块的内部存储。无新增第三方依赖。

存储为 `<data-dir>/file-access-tokens.json`，独立于 `auth.json`，含 schema 版本、全局唯一随机 id、所属 user id、签发时 `SessionVersion`、哈希及元数据。使用锁与临时文件原子替换；敏感文件权限遵循受管认证存储标准。文件不存在初始化为空；格式损坏或未知 schema 时禁用专用令牌能力并记录脱敏错误，现有会话与文件服务继续可用，不覆盖原文件。管理入口此时返回 503。

所有变更先持久化成功再对外可见，失败恢复内存旧状态。重复生成、撤销、列表并发安全；重启后恢复撤销和到期状态。暂不新增 MySQL 表：无论用户存储驱动为何，专用令牌使用独立文件，备份必须包含该文件。不得改变现有用户与会话存储格式。

## 六、状态矩阵与竞态

| 条件 | 领域结果 | HTTP / 副作用 |
| --- | --- | --- |
| 未撤销、永久或当前时间早于到期、用户有效、认证版本一致 | 有效 | 允许四个白名单操作 |
| 限时令牌当前时间等于或晚于到期 | 已过期 | 401，无文件操作 |
| 已撤销 | 已撤销 | 401，无文件操作 |
| 用户删除、禁用或 SessionVersion 不一致 | 所属账户失效 | 401，不自动恢复 |
| 哈希无匹配、格式错误 | 无效凭据 | 401，无文件操作 |
| 状态查询或存储不可用 | 验证不可用 | 503，安全失败 |

列表展示状态由领域枚举显式映射，不能直接透传未知状态。普通网页登录退出不改变专用令牌；修改或重置密码、吊销全部会话及账户状态变更导致版本变化时，旧专用令牌永久失效；重新启用账户不复活旧令牌。

创建操作在异步或磁盘 I/O 返回后重新读取用户与认证版本，失效时不交付明文。撤销成功后的新请求必须失败。已经授权且开始传输的下载不强制断开；在途上传或链接创建在提交前再次校验令牌与用户，失败须清理临时文件、配额预留且不生成可用文件或链接。实现前须审查文件模块的提交扩展点，若必须改变公开契约，先回写并重新确认，不得绕过此门禁。

### 提交扩展点审查与补充契约

2026-10-10 直接审查 `internal/fileshare/service.go`：`Upload` 在流读取及 `Sync` 完成后持文件锁执行对象 Rename 与元数据持久化；`CreateLink` 持文件锁生成并持久化链接。现有方法无鉴权回调，API 在调用前检查不能覆盖上传期间撤销的情况。

拟新增 `UploadWithCommitGuard` 与 `CreateLinkWithCommitGuard`，保留现有 `Upload` 和 `CreateLink` 签名及普通会话行为。守卫形态为 `func(commit func() error) error`，围绕真正提交阶段执行，而非只做一次孤立检查。专用令牌守卫持令牌读锁，重新校验状态和用户版本后执行提交；撤销持令牌写锁，保证撤销与提交有明确先后顺序。上传守卫拒绝时清理临时对象和配额；链接守卫拒绝时无可用链接记录。API 适配鉴权失败为 401 或 503，不映射成普通文件 500。

锁顺序固定为文件服务锁 → 令牌锁 → 用户状态查询锁；创建和撤销令牌不能反向调用文件服务。用户状态校验的线性化点为提交守卫内最后一次读取；已经通过该读取且开始提交的操作视为在途提交，不要求回滚其后才发生的密码或账户变更。令牌撤销与提交的排他规则更严格，撤销先完成时提交必拒绝。以上边界必须有可控制阻塞点的竞态测试。

## 七、管理界面与布局契约

在现有 `pageFiles` 内新增“快捷指令令牌”管理入口，作为 `files-toolbar` 的独立操作组，不嵌入上传控件或文件行。新增元素的具体 id 和选择器由实施设计与测试共同声明，不能假称当前已存在。

弹窗分为标题、说明、创建表单、令牌列表和底部操作；创建成功后独立显示一次性明文与复制按钮，关闭后清除 DOM 和内存明文，重新打开不能恢复。显示创建、到期、撤销或账户失效状态；创建中禁止重复提交，失败显示可重试错误，撤销结果逐项更新，不能由请求受理推断成功。撤销前确认名称与影响。

容器宽度不超过视口，窄屏表单及操作按钮纵向排列，长名称和 token 可换行；列表在其自身容器内滚动。弹窗焦点进入首个输入框、保持内部循环，关闭后回到入口；错误与复制结果可由辅助技术读取。真实浏览器验证 375、390、768、1440 CSS 像素宽度，无横向溢出、遮挡或不可点击入口。

## 八、快捷指令接入与本机保存

新建专用令牌后由用户直接输入快捷指令。专用令牌解决权限和生命周期问题，自动读取仍需持久保存：拟在 iCloud Drive 的 Shortcuts 目录下用独立配置文件保存服务器地址和明文令牌，跨设备同步。这不是钥匙串加密存储，能读取文件的人可以使用令牌；该存储动作须在快捷指令实施阶段单独说明并取得确认。

首次运行或配置缺失提示填写；后续自动读取。401 时提示凭据无效并让用户明确选择替换配置，网络错误或 503 不删除有效配置、不循环重试上传。上传、下载和公共分享仍由用户主动触发。配置文件不进入仓库、日志、导出的 `.shortcut` 模板或分享链接。

当前 Mac 快捷指令不纳入本轮文档改动；最终必须逐项验证手动上传、系统共享文件输入、列表、下载保存、分享链接与替换失效凭据。
