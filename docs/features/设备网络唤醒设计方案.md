# HomeAgent 局域网网络唤醒 (Wake-on-LAN) 方案与设计文档

## 1. 背景与目标

### 1.1 现状与痛点
在家庭/办公局域网环境中，终端设备（尤其是 Windows 主机、各类工作站）在长时间闲置后通常会进入系统休眠（Sleep / S3 / Modern Standby）以节约能耗。然而，设备休眠后：
- CPU 停止运行，用户态后台服务（`homeagent-agent`、`sshd` 等）被挂起；
- TCP/IP 协议栈暂停，与 Server 之间的 SSE 长连接和心跳中断，导致设备在 HomeAgent 控制台显示为离线；
- 外部 SSH 访问与远程管理通道中断（报 `Network is unreachable` 或 `Operation timed out`）。

### 1.2 目标
为解决“日常节能休眠”与“远程按需访问”的矛盾，在 HomeAgent 体系中引入 **Wake-on-LAN (WOL)** 远程网络唤醒能力：
1. **自动采集与智能维护 MAC**：设备首次接入或心跳时自动采集并优先选取有线物理网卡 MAC 地址，同时支持在控制台与 CLI 中手动配置或修正。
2. **原生广播与多网卡穿透**：HomeAgent Server 内部原生实现 WOL 魔术包（Magic Packet）构造与 UDP 广播分发，支持多物理接口定向广播、Burst 突发冗余发包与跨网段广播推导，零外部工具依赖。
3. **控制台闭环交互体验**：在 Web 控制台设备卡片中提供直观的 ⚡「唤醒 (Wake)」操作，具备在线/离线自适应展示、防重点击、唤醒中过渡态以及心跳恢复上线闭环反馈。
4. **统一 API 与 CLI 支持**：提供标准 RESTful API 接口（支持防刷限流）与命令行运维指令（支持按 ID/名称匹配或直传 MAC 唤醒）。
5. **安全与数据保护**：提供服务端 5 秒防刷保护、MAC 地址合法性严格校验、持久化覆盖保护及操作审计流记录。

## 2. 技术原理与协议规范

### 2.1 魔术封包 (Magic Packet) 结构
Wake-on-LAN 遵循行业标准 Magic Packet 规范：
- **前导同步头**：连续 6 字节的 `0xFF`（`FF FF FF FF FF FF`）；
- **目标 MAC 重复区**：目标设备 6 字节 IEEE 802 48-bit MAC 地址连续重复 16 次；
- **数据包总长度**：$6 + (6 \times 16) = 102$ 字节；
- **传输层协议**：UDP 广播包，目标端口默认使用端口 9（亦兼容端口 7）。

```text
┌──────────────────────────┬──────────────────────────────────────────┐
│  Sync Stream (6 Bytes)   │  Target MAC Address * 16 (96 Bytes)      │
│  FF FF FF FF FF FF       │  [MAC][MAC][MAC] ... [MAC] (共 16 次)    │
└──────────────────────────┴──────────────────────────────────────────┘
```

### 2.2 广播发送与穿透策略

1. **多网卡定向广播绑定 (Multi-Interface Directed Broadcast)**：
   - 遍历 Server 本地所有非 Loopback、处于 Up 状态的物理网卡接口；
   - 计算每个物理接口所在子网的定向广播地址（例如 `192.168.50.255:9`）；
   - 通过绑定本地接口 IP 发送广播包，避免因系统路由表默认网关限制导致魔术包无法到达其他局域网物理接口。
2. **全局受限广播 (Limited Broadcast)**：
   - 向 `255.255.255.255:9` 发送全局广播，确保未划分特定子网的傻瓜交换机/平坦局域网全覆盖。
3. **突发冗余发包 (Burst Redundancy)**：
   - 休眠中的网卡 PHY 芯片处于低功耗监听模式，且 UDP 广播存在丢包风险；
   - 底层每次触发唤醒时，以 **50ms** 间隔连续发送 **3 次** 魔术包以确保物理网卡可靠接收。
4. **跨网段智能推导 (Cross-Subnet Inference)**：
   - 若 API/CLI 请求未指定 `broadcast` 参数，Server 会结合目标设备的 `Device.Addresses`（已注册的私有 IPv4 地址），尝试推导目标网段的 `/24` 广播地址（如 `192.168.x.255`）并加入广播列表。

## 3. 数据模型与数据流设计

### 3.1 `Device` 模型扩展 ([`internal/device/device.go`](../internal/device/device.go))

在 `device.Device` 结构中新增 `MAC` 字段，保持向后兼容：

```go
type Device struct {
    ID             string    `json:"id"`
    Hostname       string    `json:"hostname"`
    Alias          string    `json:"alias,omitempty"`
    MAC            string    `json:"mac,omitempty"` // 格式化标准 MAC (如 02:00:00:11:22:33)
    OS             string    `json:"os"`
    Arch           string    `json:"arch"`
    SSHUser        string    `json:"ssh_user"`
    SSHPort        int       `json:"ssh_port"`
    PublicKey      string    `json:"public_key"`
    Addresses      []string  `json:"addresses"`
    CreatedAt      time.Time `json:"created_at"`
    UpdatedAt      time.Time `json:"updated_at"`
    LastSeenAt     time.Time `json:"last_seen_at"`
    SyncStatus     string    `json:"sync_status,omitempty"`
    AppliedVersion int64     `json:"applied_version,omitempty"`
    AppliedHash    string    `json:"applied_hash,omitempty"`
    SyncError      string    `json:"sync_error,omitempty"`
    SyncUpdatedAt  time.Time `json:"sync_updated_at,omitempty"`
}
```

### 3.2 MAC 地址采集与有线优先选举算法
Agent 端在 `join` 注册或更新事实时，自动探测物理网卡 MAC 并执行智能选举：
1. **接口过滤与排除**：
   - 过滤 Loopback 和处于 Down 状态的接口；
   - 排除虚拟网卡、容器网卡与 VPN 隧道（`utun*`, `bridge*`, `docker*`, `veth*`, `tailscale*`, `wg*`, `tap*`, `virbr*`, `vmnet*`, `vboxnet*` 等）；
   - 排除大多数不支持睡眠 WOL 的无线/蓝牙接口（`wlan*`, `wl*`, `wi-fi`, `bluetooth` 等）。
2. **物理有线网卡优先选择**：
   - **最高优先级**：接口名称符合以太网物理命名规则（Linux 下以 `eth*`, `en*`, `eno*`, `enp*` 开头；Windows 下适配器类型为 `Ethernet` / `以太网`；macOS 下 `en0` 等物理以太网口）；
   - **次高优先级**：网卡所绑定的 IPv4 地址命中当前已报告的通信地址（`Addresses`）列表；
   - **备选**：其它有效 6 字节 MAC 的活动物理网卡。
3. **标准化与格式校验**：
   - 使用 `net.ParseMAC` 宽容解析多种输入格式（如 `02:00:00:11:22:33`、`02-00-00-11-22-33`、`0200.0011.2233`）；
   - 校验拦截非法 MAC：拒绝非 6 字节硬件地址、全零 MAC（`00:00:00:00:00:00`）、广播 MAC（`ff:ff:ff:ff:ff:ff`）及组播 MAC（第一个字节最低位为 1，如 `01:00:5e:...`）；
   - 统一标准化输出为全小写冒号分隔格式（如 `02:00:00:11:22:33`）。

### 3.3 数据持久化与覆盖保护 ([`internal/registry/registry.go`](../internal/registry/registry.go))
- 在 `Registry.Save(d)` 时，若 Agent 上报的 `d.MAC == ""`（如特殊受限环境未采集到），**不得覆盖**原有已持久化或用户手工填写的 MAC：
  ```go
  if d.MAC == "" {
      d.MAC = old.MAC
  }
  ```
- 新增 `Registry.UpdateMAC(id string, mac string) (device.Device, error)` 方法，用于管理端独立更新 MAC。

### 4.2 `internal/wol` 领域包接口设计

```go
package wol

import (
    "net"
    "time"
)

// MagicPacket 表示 102 字节的标准 WOL 魔术包
type MagicPacket [102]byte

// BuildMagicPacket 校验 MAC 并生成 102 字节数据
func BuildMagicPacket(macStr string) (MagicPacket, error)

// Options 广播发送选项
type Options struct {
    BroadcastAddrs []string      // 目标广播地址列表（默认包含 255.255.255.255:9 及各物理网卡子网广播地址）
    BurstCount     int           // 突发冗余发包次数（默认 3 次）
    BurstInterval  time.Duration // 发包间隔（默认 50ms）
}

// Wake 向指定 MAC 地址广播发送 WOL 魔术包
func Wake(macStr string, opts *Options) error
```

## 5. API 接口规范

### 5.1 发送 WOL 唤醒请求

- **接口**：`POST /api/v1/devices/{id}/wake`
- **鉴权**：`Authorization: Bearer <token>`
- **请求体（可选）**：
  ```json
  {
    "broadcast": "192.168.50.255" // 可选，显式指定广播地址（必须为合法的 IPv4 广播/单播地址）
  }
  ```

- **服务端处理逻辑**：
  1. 校验 Token 鉴权；
  2. **服务端防刷限流 (Rate Limiting)**：检查当前 `device_id` 最近一次唤醒时间，若距离上次调用小于 5 秒，返回 `429 Too Many Requests`；
  3. 根据 `{id}` 在 Registry 中查询设备；
  4. 检查设备 MAC：
     - 若设备无有效 MAC 且请求体未传入，返回 `400 Bad Request: "device has no MAC address configured"`；
  5. 校验请求体中的 `broadcast`（若传入，必须为有效 IP，禁止公网非法 IP）；
  6. 调用 `wol.Wake(mac, opts)` 执行多网卡广播分发与 Burst 连发；
  7. 向 Event Broker 发布审计事件 `device_wake_sent`；
  8. 返回成功结果。

- **成功响应 (200 OK)**：
  ```json
  {
    "status": "ok",
    "message": "WOL magic packet sent to 02:00:00:11:22:33",
    "mac": "02:00:00:11:22:33",
    "sent_at": "2026-08-18T15:30:00Z"
  }
  ```

### 5.2 设备属性修改（支持 MAC 地址修改）

- **接口**：`PATCH /api/v1/devices/{id}`
- **请求体**：
  ```json
  {
    "alias": "主力工作站",
    "mac": "02:00:00:11:22:33"
  }
  ```
- **处理逻辑**：支持同时或单独更新别名与 MAC 地址（自动校验并标准化 MAC 格式）。

## 6. Web 控制台 UI/UX 设计

### 6.1 设备卡片交互与在线状态自适应
1. **状态自适应展示**：
   - **离线设备 (Offline)**：若已配置 MAC，高亮醒目展示 **⚡「唤醒 (Wake)」** 按钮；若未配置 MAC，按钮禁用并悬浮提示“未配置 MAC 地址，请在编辑中录入”。
   - **在线设备 (Online)**：唤醒按钮呈静默/弱化态或提示“设备在线”，避免用户误操作。
2. **防重复点击与加载过渡**：
   - 点击后按钮即刻进入 `Loading/Waking` 状态（文字变为“正在唤醒...”并展示转圈动效），本地防重禁用 5 秒。
3. **状态闭环反馈机制 (Feedback Closed-Loop)**：
   - 发送后弹出绿色 Toast：“已成功向 [Windows] (02:00:00:11:22:33) 发送 WOL 唤醒封包，等待主机上线...”。
   - 前端启动对该设备状态的监听（通过现有 SSE 事件流或 3 秒短轮询）：
     - **上线成功**：一旦检测到设备心跳恢复（状态转为 Online），卡片恢复常态并弹出 Toast：“🎉 [Windows] 已成功唤醒上线！”；
     - **超时提示**：若 60 秒后设备仍未上线，卡片恢复常态并提示：“唤醒封包已发送但设备暂未上线，请确认设备已通电且 BIOS/网卡已开启 WOL 唤醒支持”。
4. **实时审计日志**：
   - 控制台右侧「实时事件流」新增日志行：`[WOL] 向 Windows 发送唤醒指令 (02:00:00:11:22:33)`。

### 6.2 设备详情与修改弹窗
- 点击设备卡片右上角编辑图标，弹出的编辑弹窗中新增 **MAC 地址** 输入框，支持用户手工录入、校正或清空 MAC。

## 7. CLI 运维命令支持

`homeagent-server` 命令行新增 `wake` 子命令：

```sh
# 1. 通过设备 ID 唤醒
HOMEAGENT_JOIN_TOKEN=... homeagent-server wake <DEVICE_ID>

# 2. 通过设备别名或主机名匹配唤醒
HOMEAGENT_JOIN_TOKEN=... homeagent-server wake "主力工作站"

# 3. 指定广播地址唤醒
HOMEAGENT_JOIN_TOKEN=... homeagent-server wake --broadcast 192.168.50.255 <DEVICE_ID>

# 4. 直接传入 MAC 地址独立唤醒（无需注册设备）
HOMEAGENT_JOIN_TOKEN=... homeagent-server wake --mac 02:00:00:11:22:33

# 输出示例
# [OK] Sent WOL magic packet (3 bursts) to 示例工作站 (02:00:00:11:22:33)
```
