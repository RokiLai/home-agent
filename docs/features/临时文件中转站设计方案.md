## 1. 文档状态

| 阶段 | 状态 | 说明 |
| :--- | :--- | :--- |

## 2. 背景与现状证据

HomeAgent 当前提供服务端 Web 控制台、会话认证、角色权限、统一数据目录和 REST API。设备 Agent 通过 SSE 接收控制指令，但本能力的目标是让用户直接在网页中上传、管理和下载临时文件，因此不需要 Agent、SSE、Command 或设备状态参与。

仓库中的直接证据如下：

- `internal/api/api.go` 使用 Go `http.ServeMux` 注册 REST 路由，并通过认证或权限中间件保护管理接口；
- `internal/auth/session.go` 提供持久化会话及会话有效性校验；
- `cmd/homeagent-server/main.go` 已通过 `--data-dir` 及 `HOMEAGENT_DATA_DIR` 管理服务端数据根目录；
- `internal/ui/static/index.html` 和 `internal/ui/static/js/settings.js` 已提供系统设置页面与分区路由；
- 当前仓库没有通用文件上传、临时下载链接或文件目录配额模块，新增能力应位于独立业务模块中。

## 3. 目标与非目标

### 3.1 目标

1. 所有持有有效 HomeAgent 登录会话的用户都可以通过 Web 控制台上传、查看、下载、删除临时文件，并生成或撤销限时下载链接。
2. 文件统一保存在服务端一个受管目录中，逻辑总配额固定为 20 GiB。
3. 文件默认保留 7 天；Owner 可在系统设置中修改保留天数。
4. 上传和下载全程流式处理，不将完整文件加载到内存。
5. 支持无需登录的限时下载链接；链接不可预测、可撤销，并且最长不超过文件剩余保留时间。
6. 服务重启后能够从持久化元数据和磁盘文件恢复一致状态，并安全处理未完成上传和待清理文件。
7. 并发上传、磁盘不足、文件损坏、路径攻击和重复请求必须安全失败，不得突破配额或暴露任意服务端文件。

### 3.2 非目标

- 不依赖或修改 Agent，不向指定设备下发文件。
- 不实现局域网设备间直传、P2P、WebRTC 或 SSE 文件传输。
- 不实现目录上传、目录同步、文件在线预览或在线编辑。
- 不实现匿名文件列表、永久公开链接或可猜测的下载地址。
- 首期不实现分块上传、断点续传、用户独立配额、文件内容端到端加密或对象存储后端。
- 首期不按角色区分文件读写权限；除保留期设置外，任意有效登录会话具有相同的文件管理能力。

## 4. 架构与模块边界

### 4.1 总体结构

```text
登录用户浏览器
    │
    ├── 登录会话 ──► 文件管理 API
    │                  │
    │                  ├── FileShare Service
    │                  ├── 元数据 Repository
    │                  └── <data-dir>/files/ 文件目录
    │
    └── 限时 Token ──► 公共下载 API ──► FileShare Service
```

建议新增独立业务模块 `internal/fileshare`，负责文件元数据、配额预留、状态迁移、限时链接及清理策略。该模块不得依赖 `internal/api`、`internal/ui`、`internal/daemon`、`internal/broker` 或 `internal/command`。

建议职责划分：

| 层级 | 职责 |
| :--- | :--- |
| `internal/fileshare` | 领域模型、状态机、配额、上传提交、删除、链接授权和清理服务 |
| `internal/fileshare/file` | 基于受管目录的文件内容与元数据持久化实现 |
| `internal/api` | HTTP 解析、会话校验、错误映射、响应头和流式响应 |
| `cmd/homeagent-server` | 使用 `<data-dir>/files` 装配模块并管理清理任务生命周期 |
| `internal/ui/static` | 文件列表、上传入口、容量展示、链接创建和删除交互 |

### 4.2 存储布局

```text
<data-dir>/files/
├── metadata.json
├── objects/
│   └── <file-id>.blob
└── partials/
    └── <upload-id>.part
```

- 用户文件名只保存在元数据中，不能参与实际磁盘路径拼接。
- `file-id` 和 `upload-id` 必须由密码学安全随机源生成。
- `objects` 与 `partials` 必须位于同一文件系统，保证上传提交可以原子重命名。
- `metadata.json` 只保存元数据、设置和限时链接 Token 的哈希，不保存明文 Token 或文件内容。
- 目录及元数据权限沿用服务端受管敏感数据的最小权限策略；实现时必须增加跨平台权限测试。

## 5. 领域模型与持久化契约

### 5.1 文件记录

```go
type FileStatus string

const (
    FileUploading FileStatus = "uploading"
    FileReady     FileStatus = "ready"
    FileDeleting  FileStatus = "deleting"
    FileDeleteFailed FileStatus = "delete_failed"
)

type FileRecord struct {
    ID           string     `json:"id"`
    Name         string     `json:"name"`
    Size         int64      `json:"size"`
    SHA256       string     `json:"sha256"`
    ContentType  string     `json:"content_type"`
    UploadedBy   string     `json:"uploaded_by"`
    Status       FileStatus `json:"status"`
    CreatedAt    time.Time  `json:"created_at"`
    ExpiresAt    time.Time  `json:"expires_at"`
    Revision     uint64     `json:"revision"`
    DeleteError  string     `json:"delete_error,omitempty"`
}
```

字段约束：

- `Name` 是经过校验的展示名称，不得为空，不得包含控制字符、路径分隔符或 `.`、`..` 特殊路径。
- `Size` 以实际成功写入的字节数为准，不信任客户端声明。
- `SHA256` 在流式写入时计算，文件进入 `ready` 前必须固化。
- `ContentType` 仅用于展示；下载统一使用附件模式，不据此启用内联渲染。
- `UploadedBy` 保存稳定用户 ID，不保存会话 Token。
- 时间由服务端以 UTC 生成，不信任客户端时间。
- `Revision` 在每次持久化状态迁移时递增，用于防止并发覆盖。

### 5.2 服务设置

```go
type Settings struct {
    RetentionDays int    `json:"retention_days"`
    Revision      uint64 `json:"revision"`
}
```

- `retention_days` 默认值为 `7`，允许范围为 `1` 至 `365`。
- 20 GiB 总配额是首期固定产品契约，不在设置页面开放修改。
- 修改保留天数需要 `auth.PermInstanceSettingsManage`。当前权限矩阵只向 Owner 授予该权限；读取设置需要有效登录会话。
- 修改只影响此后完成的上传。已有文件的 `expires_at` 保持不变，防止配置变短后文件被批量意外删除。
- 设置更新必须携带 `revision`；版本冲突返回 `409 Conflict`，不得静默覆盖其他管理员的修改。

### 5.3 限时链接

```go
type DownloadLink struct {
    ID          string     `json:"id"`
    FileID      string     `json:"file_id"`
    TokenHash   string     `json:"token_hash"`
    CreatedBy   string     `json:"created_by"`
    CreatedAt   time.Time  `json:"created_at"`
    ExpiresAt   time.Time  `json:"expires_at"`
    RevokedAt   *time.Time `json:"revoked_at,omitempty"`
}
```

- 明文 Token 至少包含 256 位密码学随机熵，只在创建成功的响应中返回一次。
- Repository 只保存带服务端域分隔的安全哈希；日志、审计记录和错误信息不得包含明文 Token 或完整下载 URL。
- 默认链接有效期为 24 小时，可选 10 分钟、1 小时、24 小时或 7 天。
- 实际 `expires_at` 取“请求有效期”和“文件 `expires_at`”中的较早值。
- 首期链接在有效期内不限下载次数；不提供永久链接。
- 删除文件、文件到期或主动撤销链接后，链接立即失效。

## 6. 配额与磁盘空间契约

逻辑总配额固定为：

```text
20 GiB = 20 * 1024 * 1024 * 1024 bytes
```

计费范围包括：

- 所有 `ready` 文件的实际大小；
- 所有进行中上传已写入的临时文件大小；
- 已为并发上传预留但尚未写入的容量。

不按文件数量、压缩后大小或客户端声明值推算实际用量。元数据自身不计入逻辑配额，但真实磁盘空间检查必须包含整个数据目录的开销。

上传开始前必须执行容量预留。请求有可信 `Content-Length` 时预留声明大小；未知长度请求按流式增长原子申请容量。所有预留与已用容量由同一并发临界区管理，确保并发上传不能共同越过 20 GiB。

每次写入前还必须检查宿主机真实可用空间，并保留 512 MiB 安全余量。逻辑配额充足但真实磁盘不足时返回 `507 Insufficient Storage`，清理本次临时文件并释放预留。若当前平台无法可靠取得可用空间，则以实际写入错误作为最终保护，并将空间探测不可用记录为结构化告警；不得因此绕过 20 GiB 逻辑配额。

服务启动时扫描 `objects`、`partials` 和元数据：

1. 以实际文件大小重建已用容量；
2. 删除没有活动上传记录的残留 `.part` 文件；
3. 将元数据存在但内容缺失的记录隔离为不对外可下载的异常状态；
4. 将内容存在但无元数据的对象移入隔离区或记录清理任务，不得直接暴露；
5. 若启动时实际用量已经超过 20 GiB，保留已有文件读取和删除能力，但拒绝所有新上传，直到容量恢复。

## 7. 状态与失败路径

### 7.1 上传状态

```text
创建上传并预留容量
        │
        ▼
    uploading
        │ 写入、SHA-256、fsync、原子重命名、元数据提交
        ▼
      ready

任一步失败：删除临时文件、释放预留、不产生可见 ready 记录
```

上传成功的定义是文件内容完成 `fsync`、原子移动至 `objects`，且 `ready` 元数据持久化成功。HTTP 请求被受理、临时文件创建或响应开始均不能代表成功。

### 7.2 删除状态

```text
ready -> deleting -> 磁盘内容删除 -> 元数据删除
                  └-> delete_failed -> 后台重试
```

- 删除请求首先使文件不再可下载并撤销其全部链接。
- 只有磁盘内容实际删除后才能从已用配额中扣除对应大小。
- 删除失败时保留配额占用和失败状态，后台重试，不能因为元数据已隐藏就提前释放容量。
- 对相同文件重复删除必须幂等，不得影响其他文件。

### 7.3 到期清理

- 后台任务按固定间隔扫描 `expires_at <= now` 的 `ready` 文件，并复用删除状态机。
- 服务启动时立即执行一次到期扫描。
- 清理与下载并发时，已成功取得文件句柄的下载可以完成；清理完成后新下载必须失败。
- 清理与链接创建并发时，必须重新校验文件状态和到期时间；不得为已经进入删除流程的文件生成链接。

### 7.4 失败矩阵

| 场景 | HTTP / 状态 | 必须保证的结果 |
| :--- | :--- | :--- |
| 未登录访问管理 API | `401 Unauthorized` | 不泄露文件是否存在，不创建临时文件 |
| 上传将超过 20 GiB | `507 Insufficient Storage` | 不产生可见文件，释放预留和临时文件 |
| 真实磁盘空间不足 | `507 Insufficient Storage` | 不写满系统盘，不保留脏状态 |
| 上传请求中断 | 上传失败 | 清理临时文件并释放全部容量预留 |
| 元数据提交失败 | 上传失败 | 文件不得出现在列表；对象进入可恢复清理状态 |
| 文件内容缺失或摘要异常 | `409 Conflict` 或 `500` | 禁止下载并记录结构化错误 |
| 文件不存在 | `404 Not Found` | 不泄露其他文件信息 |
| 链接 Token 错误 | `404 Not Found` | 与不存在文件保持一致响应 |
| 链接已过期或已撤销 | `410 Gone` | 不返回文件内容 |
| 文件先于链接到期 | `410 Gone` | 文件保留期拥有最终优先级 |
| 删除磁盘文件失败 | `delete_failed` | 文件不可下载但继续占用配额并重试 |
| 并发删除与下载 | 按句柄取得时点决定 | 不发生路径替换、越权读取或进程崩溃 |

## 8. HTTP API 契约

### 8.1 管理接口

以下接口均要求现有有效登录会话，角色不影响文件操作权限：

```text
POST   /api/v1/files
GET    /api/v1/files
GET    /api/v1/files/{id}/download
DELETE /api/v1/files/{id}
POST   /api/v1/files/{id}/links
GET    /api/v1/files/{id}/links
DELETE /api/v1/files/{id}/links/{link_id}
GET    /api/v1/files/settings
PUT    /api/v1/files/settings
```

其中 `PUT /api/v1/files/settings` 额外要求现有 `auth.PermInstanceSettingsManage`。

上传使用 `multipart/form-data`，首期每次请求只接受一个名为 `file` 的文件字段。服务端必须在读取 Body 前设置覆盖 20 GiB 配额及有限协议开销的硬上限；额外文件字段、重复文件字段或超限正文均拒绝。

文件列表响应示例：

```json
{
  "files": [
    {
      "id": "file_xxx",
      "name": "资料.zip",
      "size": 104857600,
      "sha256": "...",
      "uploaded_by": "user_xxx",
      "created_at": "2026-09-15T10:00:00Z",
      "expires_at": "2026-09-22T10:00:00Z"
    }
  ],
  "quota_bytes": 21474836480,
  "used_bytes": 104857600,
  "reserved_bytes": 0
}
```

创建链接请求与响应：

```json
{
  "expires_in_seconds": 86400
}
```

```json
{
  "id": "link_xxx",
  "download_url": "https://example.test/api/v1/public/files/file_xxx/download?token=<明文随机Token>",
  "expires_at": "2026-09-16T10:00:00Z"
}
```

服务端应基于受信任的公开 URL 配置生成链接，不能直接信任客户端提供的 `Host` 或转发头。

### 8.2 公共下载接口

```text
GET /api/v1/public/files/{id}/download?token=<token>
```

该接口不要求登录会话，Token 是访问指定文件的限时能力凭证。它只能授权下载 URL 中对应的单个文件，不授予列表、删除、设置或其他文件访问能力。

下载响应至少设置：

```http
Content-Disposition: attachment; filename*=UTF-8''<encoded-name>
Content-Type: application/octet-stream
Content-Length: <size>
Cache-Control: private, no-store
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
```

首期支持标准单范围 HTTP Range 请求，并基于已打开的固定文件句柄返回 `206 Partial Content`、准确的 `Content-Range` 与 `Content-Length`。非法范围返回 `416 Range Not Satisfiable`；首期不支持 multipart 多范围响应。

## 9. 安全与隐私约束

1. 管理 API 复用现有会话认证，不接受设备 Token、Join Token 或查询参数中的会话凭证。
2. 公共下载 Token 必须使用常量时间比较或等价的哈希索引校验，不得在日志中出现。
3. 实际文件路径只能由服务端生成的 ID 构造；任何用户输入都不得直接参与 `Open`、`Rename` 或 `Remove` 的路径。
4. 上传时拒绝空文件名、控制字符、路径分隔符、NUL 和超出明确长度上限的名称；显示时仍按不可信文本转义。
5. 下载固定使用 `application/octet-stream` 和附件模式，避免上传的 HTML、SVG 等内容在服务端源站上下文执行。
6. 响应错误不能回显磁盘绝对路径、Token、栈信息或内部存储标识。
7. 公共下载接口首期设置服务端全局 16 个并发下载上限，并复用可信客户端 IP 提取规则实施每 IP 每分钟 60 次的新请求速率限制；超过限制返回 `429 Too Many Requests`，防止有效链接被用于耗尽带宽或文件句柄。
8. 链接 URL 可能被浏览器历史、聊天工具和代理记录；Web 界面必须支持立即撤销，但首期不声称能够从第三方记录中删除已泄露 URL。
9. 服务端若通过公网开放，限时链接同样可从公网访问；本方案不基于来源 IP 限制访问。
10. 审计记录至少包含上传、删除、创建链接、撤销链接、修改保留期的操作者、目标 ID、时间和结果，但不记录文件内容或明文 Token。

## 10. Web 控制台交互与布局契约

### 10.1 文件中转页面

新增独立一级页面“文件中转”，首屏直接提供可用的文件管理界面，不增加营销式介绍页。页面采用未嵌套卡片的工作台布局：

```text
页面标题                    [选择并上传文件]
已用 4.2 GiB / 20 GiB  [容量进度条]
------------------------------------------------
文件名 | 大小 | 上传时间 | 到期时间 | 操作
资料.zip  100 MiB  ...      ...      下载 链接 删除
```

- 上传使用单一“选择并上传文件”按钮：点击打开系统文件选择器，选中后立即校验容量并自动上传，不再要求第二次点击确认。
- 单一上传按钮必须复用控制台主按钮视觉，并依次展示“上传中”和“正在保存”状态；上传失败时保留已选文件并将按钮切换为“重新上传”。原生文件输入仅作为可访问的文件选择承载，不直接展示浏览器默认样式。
- 上传成功后文件才进入列表；失败时保留明确错误，不能出现假成功行。
- 上传接口成功后必须立即用响应中的文件与大小更新列表和容量，再拉取服务端列表校准；刷新失败时保留已确认上传结果并展示错误，不得静默停留在旧列表。
- 操作使用现有图标库可用的下载、链接、复制和删除图标，并提供工具提示。
- 生成链接后显示实际到期时间和复制操作；撤销操作需要确认。
- 删除需要确认，并明确删除会立即使所有链接失效。
- 容量展示以服务端返回数据为准，不由前端累计推算。
- 列表在移动端允许字段收敛，但文件名、大小、到期时间和主要操作必须可见且可交互。
- 限时链接弹窗必须在桌面和移动端视口水平、垂直居中，不受全局样式重置影响。
- 上传中、删除中、配额不足、空列表、加载失败和会话失效均需有独立可见状态。

具体 DOM 标识和 CSS 选择器必须在实施时基于当时的 `index.html`、路由器和模块化脚本结构确定，并先回写实施设计；本文不预设未经代码验证的选择器。

### 10.2 设置页面

## 11. 兼容性、版本与迁移

- 本能力仅修改 Server 与内嵌 Web UI，实施时必须升级服务端版本；Agent 未修改，不升级 Agent 版本。
- 新模块默认启用，数据目录固定为 `<data-dir>/files`；20 GiB 配额不依赖新增启动参数。
- 首次启动自动创建受管目录和默认设置。创建失败时文件模块保持不可用，所有文件管理 API 返回 `503 Service Unavailable`，导航入口显示不可用状态；不得阻止无关的设备管理能力启动。
- 回滚到不支持文件中转的旧 Server 时，旧版本不会读取该目录；文件不得被迁移或删除。再次升级后应能重新识别有效元数据和对象。
- 不修改现有 API 语义，不改变现有登录会话、Agent 协议或 Command 状态。

## 12. 验收条件与证据

### 12.1 功能与协议测试

1. 使用真实监听端口和 HTTP 客户端验证“登录上传 -> 列表可见 -> 登录下载 -> 内容逐字节一致 -> 删除”的完整链路。
2. 使用未登录客户端验证全部管理接口返回 `401`，且无文件、元数据或临时文件副作用。
3. 创建限时链接后，使用无登录客户端通过真实 URL 下载并校验 SHA-256；验证错误 Token、撤销、过期和文件先到期均不能下载。
4. 上传大于可用逻辑容量的文件返回 `507`，目录用量和预留恢复到请求前状态。
5. 并发上传总声明或实际写入超过剩余容量时，聚合结果必须由各上传独立状态得出，且最终磁盘内容与配额不超过 20 GiB。
6. 验证请求中断、元数据写入失败、磁盘写入失败、删除失败和服务重启后的恢复及无脏状态契约。
7. 验证恶意文件名、路径穿越、符号链接替换、重复 multipart 字段、超大请求头和 Token 重放不会越权读取或写入。
8. 验证修改保留天数只影响新文件，现有文件到期时间保持不变，非法范围和 Revision 冲突安全失败。

### 12.2 浏览器端到端测试

使用真实 API 契约数据和浏览器布局引擎验证：

1. 登录后可以进入文件中转页面，通过单一按钮选择文件并自动触发真实上传回调，看到上传进度、服务端保存状态与最终列表状态。
2. 下载、创建链接、复制、撤销和删除入口可交互，事件处理回调完整执行且 Console 无未捕获异常。
3. 会话失效、配额不足、上传中断和服务端错误在页面展示真实失败，不产生成功提示或虚假列表状态。
4. 桌面与移动端截图证明文件名、容量、到期时间和操作不重叠、不溢出，键盘焦点可见且主要操作可命中。
5. 下载链接到期时间不能选择或显示为晚于文件到期时间。

### 12.3 性能验收

实施前补充可重复 Benchmark，并以同机环回、关闭调试日志的环境记录基线。最低阻断指标为：

- 上传和下载 1 GiB 文件时，服务端因单请求增加的稳定堆内存不超过 32 MiB；
- 上传过程中不存在与文件总大小成正比的内存增长；
- 至少 3 个并发上传时配额统计保持一致且 `-race` 无数据竞争。

吞吐量受磁盘和网络环境影响，首期记录实测值但不预设脱离运行环境的固定带宽指标。

## 13. 设计审查结论

审查依据为当前 `internal/api` 路由和中间件、`internal/auth` 会话与权限矩阵、`cmd/homeagent-server` 数据目录装配、现有设置页 DOM 与路由，以及仓库完成门禁。结论如下：

- [x] 功能边界：所有登录角色均可管理全部文件；设置修改沿用 `PermInstanceSettingsManage`，因此当前仅 Owner 可修改。
- [x] 公开契约：API 路由、单文件 `multipart` 字段、错误码、Range 下载和链接有效期选项已经明确。
- [x] 状态与失败路径：上传提交、删除失败、到期清理、启动恢复和模块初始化降级路径已经闭合。
- [x] 安全边界：限时链接是唯一免登录入口，公网部署时同样可访问；Token 仅存哈希且可撤销。
- [x] 存储边界：单目录固定 20 GiB，临时文件和预留计入配额，真实磁盘保留 512 MiB 安全余量。
- [x] 兼容性：仅升级 Server 版本，不修改 Agent、Command 或现有 API。
- [x] 界面契约：页面采用当前一级导航和原生 ES 模块结构，设置沿用现有设置页分区；具体选择器在实施时以代码证据定义并由测试锁定。
- [x] 验收策略：真实端口、浏览器布局、并发、故障恢复、Range 和流式内存门禁均有直接验证手段。

审查发现并修正了四项问题：原文的 Owner/Admin 设置权限与现有 RBAC 不一致；Range 行为未决；初始化失败降级路径未决；磁盘安全余量及公共下载限流缺少量化契约。用户已确认修正后的审查结论并授权实施。
