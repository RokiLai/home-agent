# 版本号单一来源设计

## 1. 状态

| 阶段 | 状态 | 说明 |
| --- | --- | --- |
| 设计 | 评审通过 | 用户已确认单一版本来源及质量门禁兼容方案 |
| 实施 | 实施完成 | 已收敛版本来源、升级至 v0.6.12 并扩展质量门禁解析 |
| 验收 | 本地验收完成，发布验收待执行 | 本地统一门禁通过；真实 Release 与跨版本升级须在发布后执行 |

## 2. 背景与问题

`internal/version/version.go` 当前在 `Version` 初始值和 `Get()` 空值回退中分别写入 `v0.6.11`。两处字面量必须人工同步，遗漏任一处都会造成默认版本与空值回退不一致。现有测试又直接重复版本字符串，不能证明实现只有一个默认版本来源。

`Version` 同时是发布构建通过 `-ldflags -X homeagent/internal/version.Version=...` 覆盖的稳定注入点，不能改为常量或更名。

## 3. 目标与非目标

### 3.1 目标

- 在实现中只保留一个默认版本字面量；
- 保留 `Version` 变量名称、类型及链接器注入能力；
- 保留 `Get()` 的现有去除首尾空白和空值回退行为；
- 按客户端修改规则将共享版本从 `v0.6.11` 升级为 `v0.6.12`；
- 用测试直接约束默认值、注入值、空字符串及纯空白回退。

### 3.2 非目标

- 不增加自动递增版本脚本；
- 不从 Git Tag、GitHub Release、环境变量或提交数量动态推导版本；
- 不拆分 Server 与 Agent 版本；
- 不修改 CLI 输出、公开 API 或发布工作流；
- 不创建 Tag、Release 或执行部署。

## 4. 实现契约

在 `internal/version` 包内新增未导出的常量：

```go
const defaultVersion = "v0.6.12"
```

保留现有可注入变量并引用该常量：

```go
var Version = defaultVersion
```

`Get()` 对 `Version` 执行 `strings.TrimSpace`：非空时返回规范化结果；为空时返回 `defaultVersion`。实现中不得再出现第二个 `v0.6.12` 字面量，也不得把 `Version` 改为常量。

`defaultVersion` 不导出，避免扩大包契约；`Version` 与 `Get()` 的现有调用方式保持不变。

## 5. 状态与失败路径

| 输入状态 | `Get()` 结果 | 副作用 |
| --- | --- | --- |
| 默认未覆盖 | `v0.6.12` | 无 |
| 链接器或测试注入 `v1.2.3` | `v1.2.3` | 无 |
| 注入值带首尾空白 | 去除空白后的值 | 无 |
| 注入空字符串 | `v0.6.12` | 无 |
| 注入纯空白字符串 | `v0.6.12` | 无 |

测试修改全局 `Version` 时必须在结束后恢复原值，不得向其他测试泄漏状态。

## 6. 兼容性与依赖

- `-ldflags -X homeagent/internal/version.Version=vX.Y.Z` 继续有效；
- `version.Get()` 的函数签名和行为保持兼容；
- 不新增外部依赖，不跨模块引用 `internal` 或 `infrastructure`；
- 本任务修改 Agent 与 Server 共享版本包，因此版本升级为 `v0.6.12`；发布工作流将在后续 `dev → main` 合并时使用该版本创建 Release。
- 质量门禁版本解析同时接受历史双字面量格式和候选单一来源格式；两种格式之外的混合、重复或错配结构均安全失败。
- 客户端版本联动继续忽略纯版本字面量替换，但必须把 `version.go` 除版本字面量以外的结构变化计为客户端行为变化，避免本次逻辑收敛被误判为无行为版本空涨。

## 7. 测试策略与验收条件

| 成功标准 | 直接验证方式 |
| --- | --- |
| 实现只有一个默认版本字面量 | 测试读取默认常量和变量关系，并静态检查 `version.go` 中 `v0.6.12` 仅出现一次 |
| 默认版本正确 | 断言 `Version == defaultVersion == "v0.6.12"` |
| 注入契约保持兼容 | 设置自定义版本及带空白版本，断言 `Get()` 返回规范化注入值 |
| 空值安全回退 | 分别设置空字符串和纯空白，断言均回退且无其他状态变化 |
| 测试不污染全局状态 | 每个修改路径结束后恢复 `Version` |
| 新旧版本元数据均可比较 | 质量门禁测试分别解析历史双字面量格式和候选单一来源格式 |
| 非法元数据安全失败 | 负例覆盖重复常量、混合格式、错误变量引用和错误回退 |
| 版本空涨仍被拒绝 | 测试证明只替换版本字面量不算行为变化，结构逻辑变化才计入行为变化 |
| 仓库无回归 | 执行新模块测试和全量 `go test -count=1 -race ./...` |
| Diff Coverage 达标 | 执行 `./scripts/check-diff-coverage.sh HEAD 60`，结果不低于 60% |

本任务不涉及外部协议。真实 Release 创建与“上一正式版本 → v0.6.12”升级属于下一次发布验收，不在本次代码收敛中执行；发布发生后仍须按仓库规则完成真实用户入口升级冒烟。

## 8. 设计审查结论

- 功能边界明确：只收敛默认版本来源并升级共享版本号。
- 公开契约明确：保留 `Version` 注入点与 `Get()` 签名，不新增导出符号。
- 状态和失败路径明确：默认、注入、空值与空白输入均有确定结果。
- 兼容性明确：现有链接器注入、Server 和 Agent 调用不变。
- 质量门禁兼容性明确：基准历史格式和候选单一来源格式均可解析，非法混合格式拒绝。
- 外部依赖明确：无新增依赖或外部协议。
- 验收条件明确：版本唯一性、正例、空值负例、全量回归和 Diff Coverage 均有直接证据。

设计审查未发现阻止实施的未决问题，且已获得用户明确实施授权。

## 9. 实施与本地验收记录

- 版本契约测试先因 `defaultVersion` 不存在而失败，随后实现单一来源后通过。
- 质量门禁扩展测试先因 `versionImplementationChanged` 不存在而失败；实现后覆盖历史双字面量、新单一来源、重复常量、混合格式、错误引用和错误回退。
- 一次行为边界测试因固件把 `return` 写在函数声明同一行而不属于受支持格式；修正为仓库真实行结构后，纯版本字面量变化与结构变化测试均通过，未放宽解析契约。
- 使用 `-ldflags -X homeagent/internal/version.Version=v9.8.7` 构建临时 Server，执行 `version` 输出 `homeagent-server v9.8.7 (darwin/arm64)`，证明链接器注入保持有效。
- 统一质量门禁确认架构依赖通过，客户端版本从 `v0.6.11` 升级到 `v0.6.12` 且 `behavior_changed=true`。
- 新模块测试覆盖 `internal/qualitygate` 与 `internal/version`，全量 `-race` 回归通过。
- Diff Coverage 为 `85.2% (23/27 statements)`，高于 60% 门禁。
- 未创建真实 Release，也未执行上一正式版本到 `v0.6.12` 的真实用户入口升级；相关发布验收保持待执行。
