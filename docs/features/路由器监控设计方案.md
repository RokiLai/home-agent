# 路由器监控设计方案

- 设计状态：界面补充方案已获用户审查确认；恢复事件链路保持待细化/待实施。
- 实施状态：界面补充已实施完成；恢复事件链路尚未实施。
- 验收状态：界面阶段自动化测试及浏览器验证已通过；生产部署尚未执行。

## 范围与现有能力

在控制台左侧新增与「设备」并列的「路由器」，首版展示一台显式配置的路由器，仅管理员可读。Router Guard 保持负责探测、恢复及限频。HomeAgent 负责采集、保存及展示，不接受远程执行、暂停或重启请求。

控制台已有侧栏和哈希路由，入口位于 `internal/ui/static/index.html`，页面解析位于 `internal/ui/static/js/router.js`。服务端路由统一在 `internal/api/api.go` 注册。新增权限校验同时覆盖 API 与导航，隐藏导航不能代替服务端鉴权。

实机已验证 Router Guard 的 `status` 提供开机时长、最后检查时间、暂停截止以及组件状态，且学习进程和双栈分流有独立检查项。现有脚本通过 syslog 报告状态变化和恢复请求，设备缺少 `logread` 且 `/tmp/messages` 未能证明当前事件持续可读。设计不依赖这一日志文件。

## 采集与接口

以公网部署文档定义的主动上报拓扑为首版方案。指定一台已注册且常开的局域网 HomeAgent Agent，每 60 秒通过 SSH 调用 Router Guard 的固定只读入口，再通过 HTTPS 上报。服务端明确绑定允许上报的 Agent ID 和路由器 ID，复用设备鉴权，拒绝未绑定设备或替其他路由器上报。Mac mini 是候选采集节点，生产启用前验证该节点已注册且能用专用身份访问路由器。私网服务端直采作为后续兼容选项。

只读入口提供结构化快照和事件，复用 Router Guard 已有状态与恢复决策点。使用专用凭据、固定主机密钥及服务端固定命令。页面请求不得指定 SSH 地址、端口、命令或路径。SSH 超时或解析失败由 Agent 上报；Agent 本身失联由服务端依据接收时间判断，两种故障分别显示。

已有管理员只读接口 `GET /api/v1/router-monitor`，当前返回配置/采集状态、接收时间、最后成功采集时间及检查快照。恢复时间线与采集缺口是待扩展目标，当前接口尚未提供。未配置、尚无数据、采集失败、快照过期及路由器报告异常应分别呈现。失败时保留最后成功快照及其时间，禁止以历史快照代表当前健康。依据路由器开机时长和最后检查时间判断探测是否停滞，暂停及启动等待单独展示。未知组件与状态应可兼容展示，缺失组件不默认健康。

## 恢复时间线

从部署开始记录状态变化、恢复请求、恢复命令结果、限频和下一轮复查。只有复查直接观察到健康才展示「已恢复」。以设备标识、路由器启动标识和事件序号去重。采集进度与已入库事件一同提交，服务端重启后恢复读取。路由器滚动缓冲区发生丢失时明确标记缺口。页面默认展示最新事件；服务端按接收时间保留 30 天，每台路由器最多 10,000 条（先达到的限制生效）；路由器最多保留最近 256 条事件。单次最多补采 64 条，服务端成功保存后才推进确认游标。多个刷新请求共享一个采集结果，过期的采集响应不得覆盖更新快照。

## 页面布局与交互契约

页面沿用现有 `#pageRouterMonitor`，在其内使用既有 `.content-panel` 容器承载以下区域。保留 `#routerMonitorRefresh`、`#routerMonitorStatus`、`#routerMonitorUpdated` 和 `#routerMonitorChecks` 作为既有交互入口；新增元素标识由实施时定义，本文不假定其已经存在。

1. 健康总览：展示采集状态、路由器检查结论、最近接收时间、最后成功采集时间。采集运行中不等于所有组件健康；任何必需组件缺失或未知均不能显示“全部正常”。
2. 监控流程：以有方向的节点和连接展示“Router Guard 探测 → Agent 采集 → HTTPS 上报 → 服务端保存 → 页面读取”。每个节点显示文字状态、证据时间或“无数据／不可观测”。连接仅表达数据方向；没有逐步事件时不播放执行动画、不标记某节点正在执行、不以页面请求成功证明上游实时健康。
3. 组件状态：以卡片展示局域网、无线网络、系统资源、公网连接、IPv6、DNS、DHCP、代理核心、代理连通性、IP 学习及学习分流。名称以现有前端 `labels` 映射为基准；未知组件保留原名称。每项显示状态与详情，缺少项目显示“未上报”，`skipped` 显示“跳过”，不得合并为正常。
4. 恢复过程：展示“发现异常 → 请求恢复 → 执行结果 → 下一轮复查”的事件链和时间线。事件协议上线前明确显示“恢复事件尚未接入”，保留过程说明但不虚构历史、成功或活动节点。协议上线后，执行命令成功仍显示“待复查”，只有对应复查健康事件才能显示“已恢复”。

所有区域在同一内容容器内垂直排列，区域左边缘对齐；宽屏组件卡片可分栏，窄屏保持上述顺序并使用单列卡片及纵向流程。流程节点不得依赖固定页面宽度。错误原因、未知组件名称和时间线详情允许折行，页面不得横向溢出，控件不得被连接线或文字遮挡。状态同时提供文字，不能仅用颜色区分。

刷新按钮仅重新读取服务端数据，不触发探测或恢复。请求期间显示读取中并禁止重复提交；失败显示读取失败，保留且明确标记上次数据，不能留下代表当前健康的提示。切换页面、退出登录或权限变化后返回的旧响应不得写入页面；并发返回仅接受最新有效请求。权限不足清除旧监控内容且不发送读取请求。所有区域均须支持键盘操作，刷新后焦点不丢失。

## 现有数据与状态映射

真实代码依据：`internal/routermonitor/snapshot.go`、`live.go`、`collect.go` 及 `internal/api/router_monitor.go`。本次界面阶段复用现有公开接口，不新增外部依赖。响应字段为 `state`、`received`、`last_success`、可选 `snapshot`；快照字段为 `mode`、`current_uptime`、`checked_uptime`、`checks`；检查项字段为 `component`、`status`、`detail`。零时间按无数据处理。

| 输入条件 | 页面状态 | 快照及流程处理 |
| --- | --- | --- |
| `state=unconfigured` | 未配置采集 | 不标健康，显示配置说明及不可观测流程 |
| `state=waiting` 且无快照 | 等待首次采集 | 组件未上报，恢复事件未接入 |
| `state=waiting` 且快照 `mode=waiting` | 等待首次完整探测 | 不将已接收上报解释为探测完成 |
| `state=monitoring` | 监控运行中 | 组件结论单独计算，不推断恢复过程 |
| `state=paused` | 监控已暂停 | 显示暂停；当前协议不提供截止时间，不推算恢复时间 |
| `state=collection_failed` | 采集失败 | 保留最后成功快照并标注历史；当前协议不能区分 SSH、命令和解析失败 |
| `state=stale` | 数据过期 | 全部快照标注历史；结合快照时间说明上报过期或探测停滞，不假定具体故障原因 |
| 未知状态或组件状态 | 未知 | 不直接透传协议状态作为业务健康结论 |
| 读取请求失败 | 页面读取失败 | 与采集失败分开显示，已有数据仅作上次结果 |
| 未登录或非 owner/admin | 请先登录或无权查看 | 清除内容，不请求接口；服务端独立鉴权 |

组件状态映射固定为 `healthy→正常`、`failed→异常`、`skipped→跳过`、其余值 `→未知`。总览存在异常则显示异常；无异常但有缺失、未知或跳过则显示检查不完整；仅全部预期组件已上报且正常并且快照有效时显示全部正常。页面只凭 `received` 证明服务端曾接收上报，凭 `last_success` 证明曾保存可解析快照，凭 uptime 差值证明最近完成探测的相对间隔。现有后端以超过 180 秒判为过期；浏览器不得自设不同阈值或将时间推断为执行记录。

## 恢复链路的实施前置条件

恢复事件阶段必须先只读核对 Router Guard 实际事件出口、状态枚举、启动标识与序号来源，并将证据及确定的协议回写本文后重新确认。当前尚未核实这些协议，不得直接按拟定字段实现。需明确以下契约后才能进入该阶段：

- 事件类别、失败原因、组件、探测轮次及恢复动作的关联标识；定义异常、请求、执行成功／失败、限频、待复查、复查健康／异常及未知事件的跨层映射和完整状态矩阵。
- 只读采集命令、权限、输出上限、确认游标往返及兼容策略；未升级 Agent、Router Guard 或服务端时仍可使用既有快照接口。
- 路由器重启、序号回绕或缺口、批次重叠、在途旧响应、持久化失败及服务端重启后的恢复规则。异步完成后重新校验身份、启动代次和游标，事件与确认进度原子保存。
- 将 256 条缓冲、每次 64 条补采、30 天及 10,000 条保留限制落实为对应边界测试与性能验收，并给出执行环境及可接受指标；未确认指标前不宣称该链路具备性能验收条件。

本次界面阶段可独立展示真实快照和明确的事件未接入状态，但不得将此称为“完整恢复流程已交付”。若验收目标要求真实恢复全流程，则上述事件协议和有效验收为阻断条件。

## 实时快照接入配置

服务端设置 `HOMEAGENT_ROUTER_MONITOR_AGENT` 为已注册采集 Agent ID，`HOMEAGENT_ROUTER_MONITOR_ID` 为路由器业务 ID。两项同时设置后启用接收，按绑定隔离本地快照。采集 Agent 设置相同的路由器 ID，并将 `HOMEAGENT_ROUTER_MONITOR_SSH_HOST` 指向预配置的专用只读 SSH 别名。该别名需设置专用凭据和已校验的主机密钥。上报复用 HTTPS 和设备专用凭据。两端环境变量需设置在各自的服务运行环境中。

实时阶段仅保存最近一次采集结果和最后成功快照。「刷新状态」读取服务端已有数据，采集节奏由 Agent 管理。恢复事件缓冲、序号补采与 30 天历史属于下一阶段。

## 路由器 Agent 本机采集

已安装 HomeAgent Agent 的路由器使用本机采集。给路由器 Agent 设置 `HOMEAGENT_ROUTER_MONITOR_MODE=local`。采集目标固定为 Agent 自己的设备 ID；如同时设置路由器 ID，必须与该 ID 一致。本机模式不接受 SSH 别名或自定义命令。Agent 以运行身份执行固定的 `/bin/ash /data/router-guard/router-guard.sh status`，沿用上报的超时、输出校验和 HTTPS 鉴权。

服务端的 `HOMEAGENT_ROUTER_MONITOR_AGENT` 与 `HOMEAGENT_ROUTER_MONITOR_ID` 均设为路由器的已注册设备 ID。路由器需有专用设备凭据。既有 SSH 采集配置继续兼容；未配置监控的 Agent 保持默认关闭。上线验收以路由器 Agent 的真实上报和管理员页面显示为准。
