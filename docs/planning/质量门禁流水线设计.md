# HomeAgent 回归测试与质量门禁流水线设计

## 1. 文档状态

| 阶段 | 状态 | 说明 |
| --- | --- | --- |
| 设计 | 审查通过 | 设计审查已通过并获得实施授权 |
| 实施 | 实施完成 | 验收审查发现的参数、证据、退出码、变更包解析及客户端基准恢复契约已修正并有回归测试 |
| 验收 | 验收通过 | 本地真实流水线、独立全量 -race、Diff Coverage 75.2%、特殊路径及全量回归单次调用契约全部通过 |

## 2. 背景与目标

仓库已经规定变更范围检查、架构依赖检查、新模块测试、基于真实端口和协议的全量 `-race` 回归、Diff Coverage 以及按设计适用的专项验收，但当前缺少统一的可执行入口。现有 `scripts/check-diff-coverage.sh` 会运行全量 `go test -count=1 -race -coverprofile=... ./...`，前端也已有独立语法检查脚本；如果在本地脚本和 CI 配置中分别重复编排，执行顺序、参数和失败规则容易漂移。

本任务建立一套本地 CI 流水线，目标是：

1. 以单一入口执行仓库通用完成门禁；
2. 每项检查产生独立、可追溯的结果，不以请求受理或任务启动推断成功；
3. 避免全量 `-race` 和覆盖率采集重复运行；
4. 将普通变更门禁与依赖真实外部环境的专项、发布验收明确分层，首版只实现本地通用门禁；
5. 失败时保留首个失败步骤、退出码和执行证据。

## 3. 范围

### 3.1 本任务包含

- `scripts/quality-gate.sh` 统一入口及稳定的命令行契约；
- 当前任务变更清单和 `allowed_paths` 的有效性、越界检查；
- UTF-8 无 BOM、`git diff --check`、变更统计和修改文件清单；
- 仓库模块依赖边界检查；
- 变更包测试入口、前端静态检查和全量 `-race` 回归编排；
- 复用一次全量测试生成的 coverage profile 完成 Diff Coverage 门禁；
- 本地可读日志和具有版本契约的机器可读结果文件；
- 流水线自身的正例、反例及失败无误通过测试。

### 3.2 本任务不包含

- 修改产品运行时行为或现有公开接口；
- `acceptance`、`release` profile，自动发布、部署或向外部服务写入状态；
- 为既有业务功能补写缺失的专项验收；
- 将依赖凭据、真实设备或上一正式版本的验收伪装成普通本地测试；
- 执行任意调用方传入的 Shell 命令，或根据文件名猜测某项外部协议、安装或升级验收已经完成；
- 通过删除、跳过、降级或重试掩盖失败测试。

## 4. 现状证据与约束

1. 仓库当前没有 `.github/workflows`、GitLab CI、Makefile 或 Taskfile 提供统一门禁入口。
2. `changes/*.yaml` 当前公开结构为顶层 `task`、`description` 和 `allowed_paths` 列表；本设计仅增加向后兼容的可选 `external_dependencies` 列表，字段缺失等价于没有新增外部依赖。
3. `scripts/check-diff-coverage.sh HEAD 60` 当前自行执行一次全量 `-race` 测试并生成 coverage profile。
4. `scripts/check-frontend-syntax.mjs` 已存在，前端相关测试还可能由 Go 测试启动 Node 或真实浏览器。
5. Go 模块当前仅包含 `golang.org/x/sys` 与 `golang.org/x/crypto` 外部依赖。流水线实现不得为解析当前简单变更清单而直接引入新的 YAML 依赖；如实现阶段证明固定结构解析无法安全满足契约，必须先说明新增依赖的必要性并重新确认。
6. 外部协议、浏览器布局、安装、升级及发布验收必须服从对应设计文档，通用流水线不能用静态检查或 mock 结果替代。

## 5. 总体架构

```text
开发者或本地自动化
          |
          v
scripts/quality-gate.sh
          |
          +-- preflight   参数、仓库、基准提交、变更清单
          +-- scope       allowed_paths、UTF-8、修改文件清单
          +-- static      diff、架构依赖、客户端版本联动
          +-- frontend    前端静态检查及明确的 not_applicable
          +-- module      根据实际变更自动推导 Go 包并运行测试
          +-- regression  一次全量 go test -count=1 -race -coverprofile
          +-- coverage    复用 coverage profile 计算 Diff Coverage
          +-- report      汇总每个目标的独立状态与证据
```

本地手工或自动化调用只使用统一入口，不在外部脚本中复制范围判断、测试命令或阈值逻辑。

## 6. 命令行契约

拟提供以下入口：

```bash
./scripts/quality-gate.sh \
  --change changes/quality-gate-pipeline.yaml \
  --base origin/main \
  --diff-coverage 60
```

参数契约：

| 参数 | 必填 | 契约 |
| --- | --- | --- |
| `--change <path>` | 本地条件必填 | 必须是仓库内 `changes/*.yaml` 文件，且其 `task` 与文件名一致；省略时只允许从候选差异中自动发现唯一一个已纳入 Git 的变更清单 |
| `--base <commit>` | 是 | 必须解析为本仓库 commit；实际比较基准统一取 `<base>` 与候选提交的 merge-base，不允许用 `HEAD` 作为默认值 |
| `--diff-coverage <0..100>` | 否 | 默认 `60`，非法值以参数错误退出，不得隐式回落 |
| `--result-dir <path>` | 否 | 默认创建工作树外临时目录；显式目录也必须位于工作树外 |

流水线不提供 `--skip-tests`、`--ignore-failure`、任意命令执行参数或降低默认阈值的快捷参数。首版只有这一套本地通用门禁，不暴露尚未实现的 profile。未来增加专项或发布 profile 时，必须通过新的设计审查定义受控验收 ID、固定 argv、工作目录、超时、权限和脱敏规则，严禁使用 `eval` 或 Shell 命令字符串。

本地未提交变更必须显式传入 `--change`。对已纳入 Git 的候选内容，省略 `--change` 时由统一入口基于差异自动发现唯一清单；发现零个或多个均以配置错误退出。由于 `/changes/` 被 `.gitignore` 忽略，新任务清单首次提交必须显式使用 `git add -f changes/<task>.yaml`。

## 7. 门禁矩阵

| 门禁 | 首版行为 | 成功证据 |
| --- | --- | --- |
| 参数和变更清单有效 | 必须 | 解析后的任务名、比较基准和允许路径 |
| 实际变更未越过 `allowed_paths` | 必须 | 独立列出新增、修改、删除、重命名前后路径、未跟踪和越界文件 |
| UTF-8 无 BOM | 必须 | 所有仍存在的修改文本文件逐一通过；删除文件不做编码检查 |
| `git diff --check` | 必须 | 零告警 |
| `git diff --stat` 与修改文件清单 | 必须 | 原始统计及完整路径列表 |
| 架构依赖检查 | 必须 | 无跨模块嵌套 `internal`/`infrastructure` 非法依赖，外部依赖变化已显式声明 |
| 客户端版本联动 | 必须 | 客户端行为变化时版本严格提高，客户端无行为变化时版本保持不变 |
| 前端静态检查 | 条件执行 | 相关路径实际变更时执行既有脚本并通过 |
| 变更包测试 | 条件执行 | 根据实际变更的 Go 文件自动推导包集合并逐包通过 |
| 全量真实端口和协议 `-race` 回归 | 必须 | `go test -count=1 -race -coverprofile=... ./...` 退出码为 0 |
| Diff Coverage | 必须 | 复用全量 coverage profile，结果不低于阈值 |
| 设计指定专项验收 | 不执行 | 不得由通用流水线生成成功结论；对应任务仍须在交付前按设计另行验收 |
| 上一正式版本升级与公开服务冒烟 | 不执行 | 涉及发布时仍是独立阻断门禁，不得由本流水线替代 |

“条件执行”必须产生 `passed`、`failed` 或带理由的 `not_applicable`，不能以缺失结果代表不适用。

## 8. 状态、失败与聚合语义

每个步骤只允许以下状态：

| 状态 | 含义 |
| --- | --- |
| `passed` | 命令实际完成且全部断言通过 |
| `failed` | 命令执行失败、断言失败或证据不完整 |
| `not_applicable` | 按明确规则确认不适用，并记录规则与输入证据 |
| `blocked` | 缺少凭据、设备、基准版本或其他必需环境，未执行完成 |
| `not_run` | 因更早的阻断性失败未启动 |

聚合规则：

1. 任一必需步骤为 `failed`、`blocked` 或 `not_run`，流水线整体失败；本流水线未覆盖的任务专项验收不得被计入本流水线整体成功范围；
2. 只有全部必需步骤为 `passed`，其余步骤为有证据的 `not_applicable` 时，整体成功；
3. 子进程退出码必须原样记录，流水线对外统一使用 `0` 表示整体成功、`1` 表示门禁失败、`2` 表示调用或配置错误；
4. 默认按依赖顺序快速失败，但报告必须列出已完成步骤及后续 `not_run`，不得制造全量已执行的假象；
5. 不自动重试失败测试；
6. 临时文件在退出时清理，显式结果目录中的证据不得包含 Secret、Token、Cookie、SSH 私钥或完整认证响应。

## 9. 变更范围契约

范围检查同时覆盖：

- `git diff --name-status -z --find-renames <merge-base>` 返回的新增、修改、删除、复制、类型变化及未合并变更；
- 重命名和复制记录的源路径与目标路径，两者必须分别落在 `allowed_paths` 内；
- `git ls-files --others --exclude-standard -z` 返回的未跟踪且未忽略文件；
- `--change` 显式指定的任务变更清单，无论该文件是否被 `.gitignore` 忽略。当前 `/changes/` 已被忽略，不能依赖 `git ls-files --others` 发现它。

所有文件名链路使用 NUL 分隔，不得按换行拆分。比较基准为用户提供的 `<base>` 与候选提交 `HEAD` 的 merge-base；工作树和暂存区相对于该 merge-base 的变化均须纳入。删除文件参与范围检查但不做编码读取，重命名和复制不能只检查目标路径。

`git diff --stat <merge-base>` 作为已跟踪变化的原始统计；每个未跟踪文件和被忽略但显式指定的任务清单另外使用 `git diff --no-index --stat /dev/null <file>` 生成新增统计。报告必须同时保留两类原始输出并生成完整汇总，不能用只覆盖已跟踪文件的单次 `git diff --stat` 宣称覆盖全部变更。

格式检查必须执行 `git diff --check <merge-base>`，以同时覆盖 merge-base 之后已提交、已暂存和未暂存的变化；不能在干净 CI checkout 中使用无基准参数的 `git diff --check`。未跟踪文件和被忽略但显式指定的任务清单另以 `git diff --no-index --check /dev/null <file>` 检查。两类命令任一失败均视为格式门禁失败。

`allowed_paths` 支持精确文件和以 `/**` 结尾的目录递归规则，不接受其他通配符。路径必须是仓库相对路径，不允许绝对路径、`..`、空路径或重复规范化后逃逸仓库。软链接按链接自身路径参与范围判断，检查器不得跟随软链接读取仓库外目标。

若变更清单缺少现有必填字段、字段重复、缩进或列表结构超出当前受支持子集，必须安全失败并指出行号，不能宽松解析。首版保持现有字段兼容，只增加第 10 节定义的可选 `external_dependencies` 字段。

受支持清单语法固定如下：文件为 UTF-8 无 BOM，LF 与 CRLF 均接受并在解析前规范为 LF；允许空行，不支持注释、锚点、标签、多行标量、引号转义或其他 YAML 能力。顶层键仅允许顺序任意但不得重复的 `task`、`description`、`allowed_paths` 和 `external_dependencies`，未知字段失败。`task` 与 `description` 使用 `key:` 后的非空单行无引号标量，首个冒号是键值分隔，其余冒号和 `#` 作为普通字符；`task` 必须匹配 `[a-z0-9]+(?:-[a-z0-9]+)*`。`allowed_paths` 必须至少包含一项，每项严格使用两个空格加 `- `，值非空且不得使用引号。`external_dependencies` 可省略；存在时每项严格由两个空格缩进的 `- module:` 和紧随其后的四个空格缩进 `rationale:` 组成，两者均为非空无引号标量，模块不得重复，空列表、顺序颠倒或额外嵌套字段均失败。解析器不得把该受控子集宣传为通用 YAML 支持。

## 10. 架构依赖检查契约

检查器以候选工作树的 Go import graph 和基准提交中的依赖清单为主要证据。业务模块根定义为 `homeagent/internal/<module>`；模块内若出现名为 `internal` 或 `infrastructure` 的后代目录，则该目录及其后代是该模块的私有实现。检查器至少拒绝：

1. `homeagent/internal/<source>` 直接导入 `homeagent/internal/<target>/(internal|infrastructure)(/...)`，且 `source != target`；
2. 新增绕过既有公开扩展点的相对路径、链接或生成代码依赖；
3. `go.mod` 或 `go.sum` 新增外部模块，但任务变更清单没有对应的 `external_dependencies` 声明。

当前真实 import graph 中，`api` 导入 `auth`、`device`、`registry` 等顶层模块，`sshsync` 导入 `acl`、`device`、`registry`，这些属于模块公开包之间的合法边，不能一概判错。现有嵌套子包 `alerting/webhook`、`command/file` 和 `ddns/providers/cloudflare` 也不因层级本身被判为私有；只有目录名明确为 `internal` 或 `infrastructure` 时触发禁止规则。相对路径和仓库外软链接以文件系统检查为证据；尚无直接证据的架构气味只能报告为非阻断候选问题。

变更清单保持现有三个字段兼容，并允许新增可选字段：

```yaml
external_dependencies:
  - module: example.com/module
    rationale: 现有标准库或依赖无法满足的具体原因
```

字段缺失等价于空列表。声明只证明变更经过显式说明，不能替代设计审查；模块名必须与 `go.mod` 新增项精确匹配。流水线任务本身不需要新增外部依赖，固定结构解析器必须严格解析上述受控 YAML 子集并安全失败。

### 10.1 客户端版本联动契约

客户端候选包集合以 `go list -deps -json ./cmd/homeagent-agent` 在候选工作树上的结果为准。merge-base 之后，该集合中任一包的 `GoFiles`、`CgoFiles`、`CFiles`、`CXXFiles`、`MFiles`、`HFiles`、`FFiles`、`SFiles`、`SwigFiles`、`SwigCXXFiles`、`SysoFiles` 或 `EmbedFiles` 所列文件发生新增、修改、删除或重命名，以及 `scripts/install.sh`、`scripts/install.ps1` 发生变化，均属于客户端行为变化；`TestGoFiles` 和 `XTestGoFiles` 变化不属于客户端行为变化。`internal/version/version.go` 只承载版本元数据，本身不作为行为变化触发项。若基准提交中的旧包已被整体删除，检查器必须从基准提交的包元数据恢复其文件集合，不能因候选 `go list` 已不可见而漏判。

检查器从 merge-base 与候选工作树分别读取 `internal/version.Version` 的默认值，严格接受 `vMAJOR.MINOR.PATCH`：

- 有客户端行为变化时，候选版本按 SemVer 数值比较必须严格大于基准版本；
- 无客户端行为变化时，候选版本必须等于基准版本，单独修改版本文件失败；
- 版本降低、格式非法、重复定义、无法从基准提交读取或仅修改 fallback 而未同步默认值均失败；
- 服务端、文档或测试专属变化不能触发客户端升级。

正反例测试必须覆盖行为变化未升级、行为变化正确升级、无行为变化却升级、仅测试变化、版本降低及非法版本格式。

## 11. 测试与覆盖率复用

全量回归只运行一次：

```bash
go test -count=1 -race -coverprofile="$coverage_profile" ./...
```

`scripts/check-diff-coverage.sh` 将扩展为可接收已存在的 coverage profile，同时保留当前 `./scripts/check-diff-coverage.sh HEAD 60` 兼容入口。未传 profile 时维持既有行为；统一流水线传入 profile 时不得再次运行测试。

变更包测试先于全量回归执行，用于快速定位。检查器从实际新增或修改的 `.go` 文件取得目录，通过 `go list` 解析为包并去重；删除文件仅在该目录仍是 Go 包时纳入。`allowed_paths` 只用于授权检查，不参与包推导。无法解析的变更包必须失败，不能退化为跳过。变更包测试不能替代全量回归，也不能通过只运行变更包来生成最终 Diff Coverage。所有新增或修改的流水线执行逻辑必须有对应测试，至少覆盖：

- 合法精确路径和目录递归路径；
- 越界的已跟踪文件和未跟踪文件；
- `allowed_paths` 外删除、重命名源路径和目标路径；
- 绝对路径、路径穿越、非法通配符、重复字段及 malformed YAML 安全失败；
- BOM、无效 UTF-8、`git diff --check` 失败；
- 带空格、制表符和非 ASCII 字符的路径贯穿范围、统计和 Diff Coverage 链路时不会被拆分或遗漏；Go 1.26.4 `cover` 已经真实请求验证无法为带换行的 Go 文件生成 profile（会将一个输入拆为两个参数并报 `number of output files ... not equal`），因此此类路径必须在 Diff Coverage 阶段明确安全失败，不得静默遗漏或返回 100%；
- 子检查失败后整体失败，后续状态为 `not_run`；
- `blocked` 不得聚合为成功；
- coverage profile 复用时全量测试只执行一次；
- 空 Go diff、未覆盖新增语句和阈值边界；
- 日志脱敏及结果目录清理。

测试必须使用临时 Git 仓库构造输入，不能依赖或改写开发者当前工作树。

## 12. 本地 CI 集成

首版只提供仓库内本地 CI 入口，不创建或启用 GitHub Actions、GitLab CI 等托管平台 workflow。本地执行契约为：

1. 在候选工作树中使用已安装的 Go 1.26+ 和 Node.js 环境；
2. 显式传入基准提交或分支，由统一入口计算 merge-base；
3. 未提交变更显式传入 `--change`，已提交候选可由入口自动发现唯一已纳入 Git 的任务清单；
4. 结果目录位于工作树外，执行者按需保留或删除脱敏证据；
5. 本地自动化只调用 `scripts/quality-gate.sh`，不复制测试命令、阈值或路径匹配逻辑。

本地 CI 不负责需要生产凭据、真实设备或上一正式版本的专项与发布验收。此类验收仍必须由明确授权的独立流程执行。

## 13. 结果与可追溯证据

结果目录必须位于 Git 工作树外，至少包含：

- `result.json`：任务、基准与候选提交、工作树状态、内容摘要、总体状态、开始结束时间及唯一一份步骤结果；
- `changed-files.txt`：完整修改文件清单；
- `diff-stat.txt`：已跟踪变化的原始 `git diff --stat`、未跟踪及显式任务清单的逐文件 `--no-index --stat`，以及完整汇总；
- `coverage-summary.txt`：Diff Coverage 分子、分母、百分比和阈值；
- `logs/`：各步骤独立日志。

`result.json` 是结果状态的唯一事实源，最小契约如下：

```json
{
  "schema_version": 1,
  "task": "quality-gate-pipeline",
  "base_commit": "40-character-lowercase-hex",
  "candidate_commit": "40-character-lowercase-hex",
  "merge_base": "40-character-lowercase-hex",
  "working_tree_dirty": true,
  "change_digest": "64-character-lowercase-sha256",
  "status": "passed|failed",
  "started_at": "RFC3339 UTC",
  "finished_at": "RFC3339 UTC",
  "steps": [
    {
      "id": "unique-stable-id",
      "status": "passed|failed|not_applicable|blocked|not_run",
      "exit_code": 0,
      "duration_ms": 0,
      "reason": "required non-empty explanation",
      "log": "logs/relative-path.log"
    }
  ]
}
```

所有字段必填；`candidate_commit` 记录 `HEAD`，`working_tree_dirty` 表示候选是否还包含暂存、未暂存、未跟踪或显式任务清单变化。未启动步骤的 `exit_code` 为 `null`，已启动步骤必须记录实际退出码。步骤 ID 在单次结果中唯一且顺序固定。时间统一使用 UTC RFC3339，`duration_ms` 为非负整数，日志路径必须是结果目录内的相对路径且不得包含 `..`。读取方必须拒绝未知 `schema_version`，但允许已知版本出现未知字段以支持向前兼容。

`change_digest` 的输入是以下字节序列的 SHA-256：先写入 ASCII 版本头 `homeagent-change-digest-v1\0`；再写入 `git diff --binary --full-index --no-ext-diff --no-textconv <merge-base>` 的原始 stdout；然后对未跟踪文件和被忽略但显式指定的任务清单按原始路径字节升序排列，逐项写入十进制路径字节长度、NUL、路径原始字节、NUL、十进制内容字节长度、NUL、文件原始内容。符号链接的内容是链接目标文本且不得跟随。路径不是合法 UTF-8、读取期间内容变化或 Git 命令失败时安全失败。删除、重命名、复制、文件模式及已跟踪内容由 binary diff 唯一表达，不再生成第二套记录。相同 Git 版本和相同仓库内容必须产生相同摘要。

日志内容必须经过敏感信息检查；任何无法安全脱敏的原始外部响应不得进入制品。

## 16. 成功标准与验证手段

| 成功标准 | 直接验证手段 |
| --- | --- |
| 本地 CI 使用单一入口 | 契约测试确认不存在 GitHub workflow，README 只暴露一次 `scripts/quality-gate.sh` |
| 唯一确定任务清单 | 临时 Git 仓库测试分别断言零个、一个和多个变更清单时只有一个清单能够通过 |
| 越界修改无法通过 | 临时 Git 仓库正反例测试，分别覆盖已跟踪和未跟踪越界文件 |
| 删除和重命名不能逃逸范围 | 临时 Git 仓库负例分别断言越界删除、越界重命名源路径及目标路径均失败 |
| 客户端版本与行为联动 | 对行为变化未升级、正确升级、无行为变化却升级、测试专属变化、降级和非法版本逐一断言 |
| 受控清单语法安全失败 | 对注释、引号、未知字段、重复字段、空 rationale、重复模块和非法缩进逐一执行反例测试 |
| 全量回归不重复执行 | 测试替身记录 `go test -count=1 -race` 调用次数并显式断言等于 1 |
| 失败不会误聚合为成功 | 对 `failed`、`blocked`、`not_run` 逐一执行负例测试并断言整体非零退出 |
| Diff Coverage 不低于 60% | 真实执行统一入口并核对 coverage 分子、分母、百分比及退出码 |
| 既有 Diff Coverage 调用兼容 | 继续执行 `./scripts/check-diff-coverage.sh HEAD 60` 并与复用 profile 路径比较结果 |
| 修改范围与格式吻合 | `git diff --check` 零告警，核对 `git diff --stat` 和完整修改文件清单 |
| 无敏感信息进入证据 | 使用合成 Token、Cookie 和私钥标记运行脱敏负例测试，并扫描结果目录确认原文不存在 |
| 仓库回归无退化 | 基于真实本地端口和既有协议路径执行全量 `go test -count=1 -race ./...` |

## 17. 架构决策记录

| 决策 | 采用方案 | 未采用方案与原因 | 代价与重审条件 |
| --- | --- | --- | --- |
| 编排边界 | 仓库内 Go 编排器负责解析、状态和结果；Shell 仅提供稳定本地入口 | 纯 Shell 难以安全处理 NUL 路径、JSON 和状态聚合 | 增加一个内部开发工具；若 Go 工具不能覆盖目标平台再重审入口边界 |
| 变更清单解析 | 使用无外部依赖的严格受控 YAML 子集 | 引入完整 YAML 库会增加本任务不必要的生产依赖；宽松自制 YAML 解析器会产生歧义 | 不支持通用 YAML；一旦清单需要多行、锚点或更复杂嵌套，应重新审查并评估成熟 YAML 库 |
| 首版流水线范围 | 只实现本地通用门禁，专项和发布验收保持独立阻断 | 首版同时接入托管 CI、真实服务、设备和发布权限会扩大权限与环境依赖 | 未来需要托管 CI 或新 profile 时重新设计审查 |
| 结果存储 | 单一 `result.json` 保存状态，其他文件只保存不可替代的原始证据 | `summary.json` 与 `steps.json` 复制状态会形成双重事实源 | 单文件可能较大，但首版步骤规模有限；超过制品限制时以 schema 升级重新拆分 |
| 本地比较基准 | 显式传入基准提交或分支，与当前 `HEAD` 计算 merge-base | 使用 `HEAD` 默认值会得到空差异并可能误通过 | 调用者必须明确知道基准；基准不存在时安全失败 |
