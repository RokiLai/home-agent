## 1. 文档状态

| 阶段 | 状态 | 说明 |
| --- | --- | --- |

| 实施 | 已完成 | 本地已完成契约固化、全仓 IPv6/MAC/指纹脱敏、开源治理文件新增及单一发布根提交生成 |

## 2. 背景与目标

HomeAgent 计划由私有仓库转为公开仓库。公开操作会永久扩大代码、配置、文档和 Git 历史的可见范围；仅删除工作树中的敏感文件不能清除历史对象，也不能消除安装脚本默认连接个人服务所产生的安全与运维风险。

本方案目标是：

1. 清除个人身份、家庭网络、设备指纹、凭据和本机环境信息；
2. 将官方托管服务与自托管行为的边界定义为明确的公开契约；
3. 确保示例、测试替身和设计证据不来源于真实私人环境；
4. 清理可从 Git 历史恢复的信息，并阻止敏感内容再次进入仓库；
5. 建立有直接证据、可重复执行且失败时阻止公开的验收门禁。

### 3.3 当前未发现的问题

- 当前已跟踪文件中未发现真实 `.env`、数据库、运行时数据、`known_hosts` 或独立私钥文件；
- 高置信度文本扫描命中的 GitHub Token 和 OpenSSH 私钥内容均位于脱敏示例或清理逻辑测试中，不能据此认定为真实凭据；
- `.DS_Store`、`coverage.out`、`bin/`、`AGENTS.md` 和 `changes/` 当前被忽略；
- 已跟踪文本文件未发现 UTF-8 BOM。

上述结论只描述当前审计证据，不替代整改后的全历史专用凭据扫描。

## 4. 范围与边界

### 4.1 后续整改包含

- 官方默认服务入口（`https://homeagent.rokilai.online`）与自托管覆盖（`server.public_url` / `HOMEAGENT_SERVER`）的契约测试固化；
- 公网 IPv6、MAC、主机名、设备别名、系统指纹和故障证据泛化；
- `.gitignore` 和公开治理文件（`LICENSE` Apache-2.0、`SECURITY.md`、`CONTRIBUTING.md`）；
- Git 作者身份修正（`RokiLai <RokiLai@users.noreply.github.com>`）和单一全新根提交发布；
- 当前版本及全部历史对象的 Secret 扫描；
- 安装、升级、回归和公开前验收。

### 4.2 本方案不包含

- 直接执行任何整改；
- 删除或轮换真实凭据；如后续发现有效凭据，必须先在外部服务撤销或轮换，再处理仓库；
- 未经确认改变现有公开接口、默认服务语义或发布渠道；
- 未经确认重写 Git 历史、强制推送或切换 GitHub 仓库可见性；
- 用删除、跳过、mock 或降低测试标准处理失败门禁。

## 5. 关键决策门（已审查闭环）

经产品所有者审查确认，三项核心决策已确立如下：

### 5.1 默认服务模式（已确立：官方托管与自托管并存）

确立 **模式 2：官方托管与自托管并存**。HomeAgent 官方提供公共平台支持，同时完整保障开源用户自建私有平台：

1. **官方默认服务契约**：
   - 官方服务入口正式确立为 `https://homeagent.rokilai.online`；
   - 客户端 Agent（`cmd/homeagent-agent/main.go`）与一键安装脚本（`scripts/install.sh` / `scripts/install.ps1`）在未指定服务地址时，默认连接该官方入口；
   - 服务端认证接口在未显式配置 `server.public_url` 时，默认下发 `https://homeagent.rokilai.online`。
2. **自托管覆盖契约**：
   - 自建服务端通过配置文件 `server.public_url` 或环境变量 `HOMEAGENT_PUBLIC_URL` 指定自定义通信域名/IP；
   - 自建服务端的 Web 控制台动态识别自定义地址，并在设备接入页自动生成包含 `HOMEAGENT_SERVER=<自建地址>` 的完整接入命令；在官方服务下则展示省略该环境变量的最短接入命令；
   - 客户端 Agent 支持通过 `-server` 命令行参数或 `HOMEAGENT_SERVER` 环境变量优先覆盖默认值。
3. **测试保障**：必须具备完整的正反例契约测试，断言自托管配置贯穿请求解析、状态下发、控制台渲染和安装命令生成全链路。

### 5.2 公开历史策略（已确立：单一全新根提交）

确立 **从审计通过的工作树生成单一全新根提交发布（Single Clean Root Commit）**：

1. 当前仓库历史较短（4 个提交），采用单一干净根提交发布可 100% 消除历史提交信息、blob 与元数据中的本机身份和未脱敏痕迹；
2. 提交作者与提交者（Author / Committer）统一设置为 GitHub noreply 身份：`RokiLai <RokiLai@users.noreply.github.com>`；
3. 本地与远端备份私有历史，在全部验收通过并获得最终授权前，不执行强制推送（`git push --force`）。

### 5.3 许可证与治理模式（已确立：Apache-2.0）

确立采用 **Apache License 2.0**：

1. **许可证文件**：在仓库根目录添加标准 `LICENSE`（Apache-2.0）；
2. **安全漏洞渠道**：新增 `SECURITY.md`，明确优先通过 GitHub 私密漏洞报告（GitHub Private Vulnerability Reporting）提交安全漏洞；
3. **贡献规范**：新增 `CONTRIBUTING.md`，明确开发门禁、测试要求、凭据禁令与提交身份规范。

## 6. 分阶段整改计划

### 6.1 阶段一：冻结公开与建立清单

1. 在全部阻断项关闭前保持仓库私有；
2. 为每个实施任务建立独立 `changes/<task>.yaml`，只开放必要路径；
3. 导出所有分支、标签、远端引用、GitHub Release 资产和自动化 Secret 的只读清单；
4. 建立敏感数据词典，只记录类型与定位方式，不在报告中复制凭据值。

### 6.2 阶段二：固化官方服务契约与自托管兼容性

1. 固化官方公共服务默认入口（`https://homeagent.rokilai.online`）的公开契约；

6. 每项替换必须保持原测试要验证的协议或分类语义，不能机械替换导致测试失真。

完成证据：地址分类测试、隐私词典扫描、人工复核记录，以及测试数据来源与真实协议差异说明。

## 7. Secret 与隐私扫描契约

扫描必须同时覆盖：

- 当前工作树、暂存区和未跟踪文件；
- 全部分支、标签和其他拟公开引用；
- Git 历史中的提交、树和 blob；
- GitHub Release 资产、Actions 日志和构建制品；
- 文档、截图、示例响应、测试 fixture 和压缩包内容。

至少使用一种维护中的专用 Secret 扫描器，并记录工具名称、版本、规则版本、完整命令、扫描范围、退出码和报告摘要。正则扫描只能作为补充。每个命中项必须分类为：

- `confirmed_secret`：先撤销或轮换，再清理仓库和历史；
- `personal_data`：泛化、删除或形成经确认的公开例外；
- `test_fixture`：证明为不可用替身，并记录来源和与真实协议的差异；
- `false_positive`：记录判定依据，不得仅凭文件位于测试目录判定。

报告不得回显完整 Secret。任何 `confirmed_secret`、未决高置信度命中或扫描范围不完整都必须阻止公开。

## 8. 测试策略

后续涉及可执行行为的整改必须测试先行，并至少覆盖：

1. 未配置服务地址时按确认契约安全失败或连接正式公共服务；
2. 自托管地址能够覆盖默认值，并贯穿响应、解析、状态、渲染和交互；
3. 安装脚本不会在缺少必要配置时连接个人域名；
4. 占位域名不可作为运行时真实目标；
5. Secret 清理器对 Token、Cookie 和私钥测试内容继续有效，且不会把原文写入报告；
6. `.gitignore` 阻止真实本地凭据和数据文件，同时不误伤明确允许的示例文件；
7. 上一正式版本到候选版本的安装、重装和升级路径保持兼容。

测试数据必须从产品契约和真实外部协议观察推导，不得根据当前实现反向构造。

## 9. 回滚与事故响应

### 9.1 公开前发现敏感信息

保持仓库私有；立即撤销或轮换凭据；确认外部服务访问日志；清理当前版本和历史；重新执行全部扫描与验收。

### 9.2 公开后发现敏感信息

1. 先撤销或轮换凭据，不能等待 Git 历史清理；
2. 临时将仓库转回 Private 只能降低继续扩散，不能撤回已被克隆的数据；
3. 清理所有引用、Release、Actions 日志和缓存后重建历史；
4. 通知受影响方并记录暴露窗口、访问证据和补救措施；
5. 完成根因复盘，将契约、实现、测试或长期流程缺口写入对应载体。

## 11. 后续任务拆分建议

建议拆分为以下独立任务，避免将产品契约、隐私清理和破坏性历史操作混在一次变更中：

1. `public-service-contract`：固化官方公共服务契约并保障自托管覆盖兼容性（含测试与文档）；
2. `public-repository-data-sanitization`：清理公网 IPv6、MAC、设备别名与系统指纹并补测试；
3. `public-repository-governance`：完善忽略规则、添加 Apache-2.0 `LICENSE`、`SECURITY.md` 与 `CONTRIBUTING.md`；
4. `public-history-rebuild`：经单独确认后以 `RokiLai <RokiLai@users.noreply.github.com>` 重建单一根提交与远端引用；
5. `public-release-acceptance`：执行真实安装、升级、Secret 扫描和匿名公开面验收。

每个任务都必须单独定义 `allowed_paths`，不得沿用本方案文档任务的范围实施代码或历史修改。
