# HomeAgent 产品迭代路线图

## 目标定位

将 HomeAgent 从局域网 SSH 公钥分发工具逐步演进为面向个人与家庭环境的轻量可信设备控制平面。

路线图优先补齐现有能力之间的可靠性、安全性和可观测性闭环，再扩展新的远程运维操作。

## 优先级总览

- [x] **P0：统一任务与回执模型**
- [ ] **P1：离线指令与断线重连收敛**
- [x] **P1：设备健康与告警**
- [ ] **P1：SSH 同步安全加固与灾难恢复**
- [ ] **P2：持久化、备份与恢复升级**
- [ ] **P2：权限与安全边界强化**
- [ ] **P3：受控远程运维能力扩展**

同一优先级内按文档出现顺序推进。P1 中先完成离线任务收敛，再建设健康告警，并可并行推进 SSH 安全加固；P2 中先完成持久化与恢复基线，再扩展角色、二次认证和高风险操作授权。P3 必须等待其“前置条件”全部满足。

凡清单中使用“评估”“明确”或“设计”的事项，交付物必须是已评审的 ADR 或设计文档，其中应包含最终决策、未选方案、兼容策略、验收指标和后续实施任务，不能仅以讨论结束视为完成。

## P0：统一任务与回执模型

**当前状态：已完成。** 实现与验收证据见《[P0 统一任务与回执模型开发方案](../architecture/P0命令任务模型设计.md)》；离线排队、断线补投和 `Last-Event-ID` 仍属于下一节 P1 范围。

### 目标

为 SSH 密钥同步、自升级、关机和 GitHub 凭据同步建立统一、可追踪的任务生命周期，避免不同模块共享或覆盖彼此状态。

### 清单

- [x] 定义统一的 Command/Job 领域模型。
- [x] 为每次操作生成全局唯一的 `command_id`。
- [x] 记录任务类型、目标设备、请求来源、创建时间和有效期。
- [x] 统一任务状态：`queued`、`dispatched`、`accepted`、`succeeded`、`failed`、`timeout`、`canceled`。
- [x] 要求 Agent ACK 显式关联 `command_id` 和模块类型。
- [x] 定义合法的状态迁移规则，拒绝乱序或非法回执。
- [x] 为任务执行增加幂等键，避免重复操作。
- [x] 为任务增加超时、有限重试和最终失败策略。
- [x] 定义超时后晚到 ACK、取消与执行并发、Agent 接收后失联等终态规则。
- [x] 将 SSH 密钥同步、自升级、关机和 GitHub 凭据同步迁移到统一模型。
- [x] 在 Web 控制台展示单设备任务状态和最近操作结果。
- [x] 提供操作历史查询，记录谁在何时对哪台设备执行了什么操作及其结果。
- [x] 为状态隔离、重复 ACK、乱序 ACK、超时和重试增加测试。

### 完成标准

- [x] 不同模块的 ACK 不再写入彼此的状态字段。
- [x] 每个控制操作均可从创建追踪至最终结果。
- [x] 重复或乱序 ACK 不会导致任务状态回退或重复执行。
- [x] 控制台能够明确区分“已下发”和“已成功执行”。

## P1：离线指令与断线重连收敛

### 目标

保证设备临时离线、SSE 断线或服务端重启后，仍能安全恢复未完成任务，并避免过期或重复指令被执行。

### 清单

- [ ] 为待执行任务提供持久化存储。
- [ ] 设备离线时保留可延迟执行的任务。
- [ ] Agent 重连后拉取或接收尚未完成的有效任务。
- [ ] 为 SSE 事件定义稳定事件 ID，并评估 `Last-Event-ID` 恢复机制。
- [ ] 为每类指令定义 TTL 和过期行为。
- [ ] 定义服务端与设备时钟偏差容忍范围，避免仅依赖设备本地时间判断 TTL。
- [ ] 明确关机、升级等高风险任务是否允许离线排队。
- [ ] Agent 持久化最近已执行的幂等键或任务 ID。
- [ ] 服务端重启后恢复任务状态和待投递队列。
- [ ] 明确本阶段只持久化任务与投递状态；通用 schema 迁移、全量备份恢复和存储治理归入 P2。
- [ ] 对缓冲区满、连接中断、重复投递和服务端重启增加测试。
- [ ] 验证过期关机指令不会在设备晚到重连后执行。

### 完成标准

- [ ] 可重试任务不会因设备短暂离线而静默丢失。
- [ ] 已成功执行的任务不会因重连而重复执行。
- [ ] 过期或已取消任务在任何情况下都不会执行。
- [ ] 服务端重启不会丢失任务最终状态。

## P1：设备健康与告警

**当前状态：已完成。** 四态健康评估、运行 Facts、历史、Dashboard、通用 Webhook、告警去重/静默/恢复以及有界重试已落地，验收证据见《[P1 设备健康与告警开发方案](../fixes/P1设备健康与告警系统设计.md)》。

### 目标

将已有设备 Facts、心跳和同步结果转化为可行动的健康状态，而不仅是静态信息展示。

### 清单

- [x] 定义设备健康状态：`healthy`、`degraded`、`offline`、`unknown`。
- [x] 定义在线、离线和失联时间阈值。
- [x] 检测 Agent 版本落后。
- [x] 检测 SSH 密钥同步漂移或持续失败。
- [x] 检测 DDNS 同步失败和地址状态异常。
- [x] 检测升级任务失败或长时间未收敛。
- [x] 增加设备运行时间、负载、内存和磁盘等最小必要 Facts。
- [x] 在 Dashboard 汇总异常设备及可执行建议。
- [x] 支持按设备查看健康状态变化历史。
- [x] 设计可插拔告警接口。
- [x] 优先实现一种轻量告警通道，如通用 Webhook。
- [x] 为 Webhook 定义鉴权、退避重试、投递失败可见性和超时策略。
- [x] 增加告警去重、静默窗口和恢复通知。

### 完成标准

- [x] 管理员无需检查日志即可发现主要设备异常。
- [x] 每个异常状态都包含原因、首次发生时间和建议动作。
- [x] 同一持续故障不会产生无上限重复通知。
- [x] 状态恢复后能够清除告警并记录恢复时间。

## P1：SSH 同步安全加固与灾难恢复

### 目标

强化 HomeAgent 的核心安全承诺，使实时推送、SSH 兜底和离线应用共享一致的安全写入语义。

详细事项同时参考 [SSH 访问集成待办事项](../features/SSH访问集成待办事项.md)。

### 清单

- [ ] 定义统一的 KeySet、同步计划和应用结果模型。
- [ ] 对 SSH 公钥格式和允许的算法进行严格校验。
- [ ] 显式拒绝 OpenSSH、PEM、PuTTY 等私钥内容或标记。
- [ ] 按算法和 Key Body 去重，不依赖注释文本。
- [ ] 校验托管区标记的数量、顺序、完整性和嵌套关系。
- [ ] 托管区异常时安全失败，并保持原文件不变。
- [ ] 提供 dry-run，展示新增、移除和保持不变的密钥。
- [ ] 写入前创建可恢复备份并定义保留策略。
- [ ] 使用同文件系统临时文件和原子替换。
- [ ] 正确处理 Unix 权限和 Windows ACL。
- [ ] 对并发同步使用设备级锁。
- [ ] 保留托管区外的用户条目、注释和 SSH options。
- [ ] 统一 SSE、SSH 兜底和本地离线应用的写入实现。
- [ ] 设计密钥轮换、吊销、导入导出和灾难恢复流程。
- [ ] 定义离线设备的吊销传播窗口、重新上线策略和紧急处置流程。
- [ ] 增加私钥混入、符号链接替换、路径穿越、并发修改等反例测试。

### 完成标准

- [ ] 任何校验或写入失败都不会破坏现有 SSH 登录能力。
- [ ] 重复应用同一 KeySet 完全幂等。
- [ ] 已吊销密钥不会因旧托管区或离线数据残留而继续生效。
- [ ] Server 丢失后可使用不含私钥的备份材料完成恢复。

## P2：持久化、备份与恢复升级

### 目标

确保设备、认证、任务和网络状态在异常退出、升级、重装与迁移场景中保持一致且可恢复。

### 清单

- [ ] 盘点当前 JSON 文件和内存 Store 的持久化边界。
- [ ] 为所有持久化数据定义 schema version。
- [ ] 建立向前迁移和失败回滚机制。
- [ ] 统一原子写入、目录同步、权限和错误恢复策略。
- [ ] 将需要跨重启保存的设备网络状态迁移出纯内存 Store。
- [ ] 实现 `homeagent-server backup`。
- [ ] 实现 `homeagent-server restore --dry-run`。
- [ ] 定义自动备份周期、保留数量和清理策略。
- [ ] 增加备份完整性校验和敏感字段保护。
- [ ] 明确备份范围、加密方式、密钥托管、真实性验证、RPO、RTO 和恢复演练周期。
- [ ] 编写服务端重装、主机迁移和 Registry 损坏恢复手册。
- [ ] 评估数据规模达到何种阈值时才需要迁移到 SQLite。

### 完成标准

- [ ] 服务端正常重启不会丢失需持久化的运行状态。
- [ ] 损坏或版本不兼容的数据不会被静默覆盖。
- [ ] 备份恢复支持 dry-run，并可验证恢复结果。
- [ ] 从上一正式版本升级后现有数据和设备连接保持有效。

## P2：权限与安全边界强化

### 目标

在支持公网访问和高风险远程操作时，提供明确的身份、授权、审计与凭据生命周期管理。

### 清单

- [ ] 明确管理员、只读用户和设备身份的权限矩阵。
- [ ] 支持查看者与管理员等最小必要角色。
- [ ] 评估并实现 Passkey/WebAuthn 或 TOTP 二次认证。
- [ ] 提供管理员会话查看和一键吊销。
- [ ] 支持设备 Token 轮换、吊销和重新认领。
- [ ] 为升级、关机和凭据分发等高风险操作增加二次确认策略。
- [ ] 建立不可与普通业务状态混用的安全审计记录。
- [ ] 明确 CSRF、CORS、可信反向代理和来源地址处理边界。
- [ ] 对登录、Token 创建和高风险接口实施独立限流。
- [ ] 验证设备只能访问自己的事件、状态和任务。
- [ ] 增加越权、重放、会话固定和凭据泄露反例测试。

### 完成标准

- [ ] 每个敏感接口都有明确的调用主体和授权规则。
- [ ] 管理员可以吊销任一会话或设备凭据。
- [ ] 高风险操作具有可查询、不可混淆的审计记录。
- [ ] 公网部署的信任边界和必要配置有明确文档。

## P3：受控远程运维能力扩展

### 前置条件

- [ ] P0 统一任务与回执模型已完成。
- [ ] P1 离线重连、幂等和任务过期机制已完成。
- [ ] P2 高风险操作授权与安全审计已完成。

### 清单

- [ ] 支持远程重启。
- [ ] 支持受限的服务启动、停止和重启。
- [ ] 支持预定义 Runbook，不直接开放任意 Shell。
- [ ] 为 Runbook 定义严格参数 schema、权限和超时。
- [ ] 支持受控日志采集，并对敏感内容脱敏。
- [ ] 支持受控文件分发，并校验哈希、大小和目标路径。
- [ ] 评估 Web SSH Terminal 的隔离、授权和审计成本。
- [ ] 支持设备分组和分批执行策略。
- [ ] 支持定时任务、维护窗口和取消操作。
- [ ] 为每种远程能力提供平台支持矩阵和安全失败行为。
- [ ] 定义执行账户、提权方式、Runbook 版本固定及文件落盘回滚策略。

### 完成标准

- [ ] 默认不存在任意命令执行入口。
- [ ] 所有远程操作均可授权、追踪、超时、取消和审计。
- [ ] 不支持的平台在执行前明确失败，不产生部分修改。
- [ ] 批量任务支持分批、停止和失败隔离。

## 建议版本里程碑

- [ ] 完成 ACK 关联和状态机。
- [ ] 完成操作历史与控制台结果展示。

### v0.6：可靠控制平面

- [ ] 完成幂等、TTL、超时和有限重试。
- [ ] 完成基础设备健康状态、异常汇总和控制台展示。

### v0.7：可长期自托管

- [ ] 完成 SSH 同步安全加固。
- [ ] 完成全局 schema 治理、备份、恢复和数据迁移机制。
- [ ] 完成基础告警通道、去重和恢复通知。

- [ ] 根据真实需求评估 Web SSH、插件或自动化集成。

## 通用交付检查

每个路线图事项进入开发前：

- [ ] 创建对应的 `changes/<task>.yaml` 并明确 `allowed_paths`。
- [ ] 检查现有公开契约、数据迁移和跨版本兼容要求。
- [ ] 对外部协议进行真实请求验证，并记录完整响应链。
- [ ] 从产品契约和真实外部行为推导测试。
- [ ] 客户端发生改动时升级客户端版本号。

每个事项交付前：

- [ ] 完成变更范围检查。
- [ ] 完成架构依赖检查。
- [ ] 运行新模块测试。
- [ ] 运行全量回归测试。
- [ ] 完成 Diff Coverage 检查。
- [ ] 验证失败路径不会通过删除、跳过或弱化测试被掩盖。
- [ ] 涉及安装或升级时，完成上一正式版本到候选版本的真实用户路径验收。
- [ ] 交付记录列出全部修改文件和未验证风险。

## 暂不优先事项

- [ ] 在任务可靠性和安全边界完成前，不开放任意 Shell 命令执行。
- [ ] 在文件存储达到明确瓶颈前，不引入 PostgreSQL 等高运维成本依赖。
- [ ] 在核心闭环稳定前，不以增加大量指标或第三方集成为主要目标。
- [ ] 不建立与 HomeAgent Registry 并行的第二套设备或授权事实来源。
